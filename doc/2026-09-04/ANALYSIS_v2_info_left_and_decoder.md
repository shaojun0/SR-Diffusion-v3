## 0. TL;DR（先看这六条）

1. **是, 还有信息没被利用——但"没被利用"要按层拆**：DINO/编码器输出携带整图
   信息（register 每键=24 层双向注意力的全图摘要）; 卡点在**解码器怎么取用**,
   不在编码器存不存在信息。
2. **"架构学不出来"要拆成三种不同机制, 不能混为一谈**：
   ① 读出端**设计缺陷**（F3/F4: 固定模板 + 共享键凸组合, 无逐 patch 内容句柄,
   E2 从未实现）; ② 编码端**训练没逼出来**（register 只被输出≈0 的后步读 →
   塌缩冗余, 多样性预算全押 step-1 读区）; ③ exp2 读侧全开**训练动力学塌缩**
   （对称退化吸引子, grad≈0.001 自锁均值色, 连学的机会都没有）。
3. **仓库里最硬的对照一直没拆**：v4（register K=64 + DINO 微调 + **v3 式无时序
   读出**）= **8.26** vs slice27_v2（register K=63 + DINO 微调 + **v2 时序解码**）=
   **19.878**——编码器结构相同、DINO lr 相同（1.5e-4）、预算相同（8760 步/40ep/
   fp32/bs16×2, 已核对 train_v2.py / train_v4.py [代码]）, 差 ~11.6 只可能来自
   **解码器设计**。
4. S25/S64（19.15/19.58）= "v2 解码栈去掉时间轴只剩一步"的水平——**连单步都到
   不了 v4**, 说明压制成分藏在 A_t 内容项 + 576 行查询自注意力里, 不只是时间轴/
   累加/均值损失本身 [推断, 待消融]。
5. "14.28 → 20" 不是信息消失：14.28 走的是**查询自注意力混叠通道**（被因果 tgt
   堵死）; 剩余"每步只读自己块"路径被 F3/F4 + 键冗余（cos 0.96–0.999）卡在
   ~19–20 上限; slice05 又把 step-1 前缀削到 4 键 → 20.55（因果族最差, 无泄露,
   你自己的探针已证是诚实的）。
6. **下一步（服务器开机后）**: 先跑 **E1 线性探针**（30 分钟、零训练, 设计见 §5）
   量化"z_s 里还剩多少信息"; 再跑**解码器单变量对照**（v2 编码器 + v4 式读出,
   ~2h）裁决"解码栈压制读出"假说。

## 1. 问题拆解: 信息分层盘点

| 层 | 是否携带信息 | 证据 | 卡点 |
|---|---|---|---|
| DINO patch 特征 | 是（冻结时线性探针 ≈9.8） | v4 REPORT §3 | 无 |
| register z_s | 是 | 旧代码（无因果）同一批 z_s 读出 14.28; v4 同款 register 读出 8.26; S25/S64 各块信息等价（都能独立支撑 ~19 重建） | **解码器怎么取用** |
| 解码输出（因果族） | 用出的只是 step-1 前缀键那一份 | slice27_v2 19.88 / slice05 20.55, 泄露探针证无泄露 | F3/F4 读出上限 + 键冗余 |

**判读**: 信息在编码器输出层存在且充足; "14.28→20" 是**取用通道**变化的结果,
不是信息源消失。

## 2. "架构学不出来"的三种机制拆分

### ① 读出端设计缺陷（真·架构问题, E2 从未实现）
- [代码+数据] 查询身份 = 固定模板 query_base; 输出 = 对共享键的凸组合 + 共享 FFN。
  逐 patch 精细只能靠注意力在键间做选择; 键彼此 cos 0.96–0.999（slice27_v2 探针
  16..63≈0.97; exp1 9..35≥0.99）→ 注意力无内容可区分。
- 342M 参数但读出通道里**没有"指着 patch k 自己内容"的句柄** → 直接交叉注意力
  读键的精度上限 ≈19–20（S25/S64 独立重训 = 该上限的无偏估计）。
- 修复方向（文档早有, 未实现）: E2 原式（K=N 时 `Q = A_t + query_base + Linear(z_s[k])`）;
  K<N 时改写为 E2'/F1（编码侧注入, 见 §2②）。

### ② 编码端无分工压力（训练没逼出来, 不是学不会）
- [数据] exp1: 位置 4..35 intra cos 0.85–0.999（9..35 全 ≥0.99）; 采样种子
  pos4/9/16/25 两两 cos 0.9986–0.9999; 而 step-1 读区 1..3 intra 只有 **0.62** =
  全 register 文件多样性最高处; z_s[1] 与后步种子 cos≈0.42。
- 解释 [推断]: 只有被有效读取的 register 收到强梯度 → 被迫携带多样内容; 只被
  "输出≈0 的后步"读的 register 梯度弱且同向 → 塌缩成冗余团。**模型把多样性预算
  全押在唯一被读的 3 个 register 上——它"会学", 只是没被要求分工**。
- 旧代码压缩收益（K=576→63: 17.46→14.28）就来自"强制分工"; 因果代码把读区分工
  废了, 压缩只剩 step-1 前缀变短的成本（你的 REPORT_v2_block_slice05 §4.2 同判）。

### ③ 训练动力学塌缩（exp2 新证据: 连学的机会都没有）
- [数据] 读侧全开（memory_mask 全 0, 仅因果 tgt）: train loss 0.899（lr 峰值附近）
  → 跳回 1.14+; grad_norm 0.5–2 → **0.001–0.006** 冻结; 全量 L1 = 64.62 ≈ 均值色;
  checkpoint 复验证非 bug。
- 机制 [推断]: 每键被 5 步 × 576 行共享 → 单键梯度 ≈1/36 → 无键值得专业化 →
  键趋同 → 注意力均匀 → 梯度湮灭 → **对称退化吸引子**自锁, cosine 衰减无逃逸。
- 意义: "放开访问"不是中性操作; 分块读侧的最小价值 = 提供**分工压力**与对称性
  破缺, 删掉它训练直接崩。

## 3. 最硬对照: v4 = 8.26 vs slice27_v2 = 19.878（编码器几乎相同）

训练代码核对 [代码]:

| 项 | v4（8.26） | slice27_v2（19.878） |
|---|---|---|
| 编码器 | register specials K=64 进 DINO 序列, 不冻结 | register specials K=63 进 DINO 序列, 不冻结（结构相同） |
| DINO lr | 1.5e-4（分组: 新模块 3e-4） | 1.5e-4（单 lr 全模型） |
| 预算 | 8760 步 / 40ep / fp32 / bs16×2 / seed 同 | 同左 |
| 解码器 | **v3 式无时序**: N 行查询（q=query_base 仅, 无 A_t、无查询自注意力、无掩码、无累加）→ 交叉注意力读全部 K 键 → 头 | 时间轴 TransformerDecoder: q = A_t + query_base, 576 行查询自注意力（因果块下三角）, 分块 memory_mask, 累加 + 梯度解耦 + 平权均值损失 |
| 全量像素 L1 | **8.26** | **19.878** |

差距 ~11.6（n=3004, SE≈0.13 → ≈90 SE）; 编码侧同款、预算同款, 归因只剩解码器
设计（含其训练压力如何塑造 register 分工; v4 的 z_s within-std 0.27 vs v3 0.97
佐证微调塑造了分工结构 [数据]）。

**S25/S64 的定位**: 单步（|T|=1, 无累加）仍是 v2 解码栈（A_t + 576 行查询自注意力
保留）→ 19.15/19.58。连"单步 + 更多键 + 独占梯度"都到不了 v4 → 压制成分不是
时间轴/均值损失本身, 而是 **A_t 内容项（所有行查询被同一个全局摘要偏置）+ 查询
行自注意力（行间混叠/稀释逐行区分）**, 或 v2 训练细节（单 lr、深度 2、头结构）
[推断, 具体成分待消融]。

## 4. "14.28 → 20" 的机制解释（为什么不是信息消失）

1. 旧 slice27（无因果）= 14.28: step-1 经查询自注意力**混叠池化**步 2..5 的行状态
   （各步读了 16..63 + 各自种子）→ 唯一能突破 ~19 读出上限的通道, 但形态是
   "step-1 一肩扛 + Y₂₊≈0", 无渐进语义。
2. 因果 tgt_mask = 堵死该通道（09-03 实验: 14.28→19.878）; 剩余路径 = 每步
   固定模板直读自己块 → 上限 ~19–20（S25/S64 锚点）。
3. slice05 = 窗口前移 [0:5], step-1 前缀 16 键→4 键, 且 4..15（slice27_v2 里 step-1
   的多样前缀）落入塌缩尾区 → 20.554（因果族最差; 你的泄露分析证无泄露、诚实）。
4. 结论: 单调链 4 键 20.55 < 16 键 19.88 < 36 键 19.15 ≈ 80 键 19.58 = **因果/
   分块族在"固定模板读出上限"内的键数税曲线**; 要低于 19 只有两条路: 放开混叠
   （=作弊形态的 14.28, 且已被堵）或给读出器逐 patch 内容句柄（E2/F1）或换
   v4 式读出（实证 8.26）。

## 5. E1 线性探针实验设计（服务器开机后执行, ~30 min, 零训练）

**目的**: 量化"z_s 里还剩多少信息、解码浪费多少", 回答本文问题的最硬数字。
参照 08-27 三档（真实 DINO patch→9.8 / z_s→40.4 / F_hat→64.9）; 本次在
slice27_v2（K=63）与 slice05（K=35）final_model 上重测。

**方法**（基于 `doc/2026-08-27/trace_info_pixel.py` 改造, 适配当前 model_v2 接口）:

1. 模型构造（注意旧脚本的 `reencoder_depth` 参数已不存在）:
   ```python
   model = SRPhase1V2(dinov2=dino, num_patches=576, dim=dino.config.hidden_size,
                      decoder_steps=[9,16,25,36,49], decoder_depth=2, num_specials=63)
   # slice05 版: decoder_steps=[1,4,9,16,25], num_specials=35
   model.load_state_dict(torch.load(final_model, map_location="cpu"), strict=True)
   ```
2. 采样 512 图（与 09-04 探针同子集, 数字可并排）; 每批:
   - **DINO patch 特征 P**: 与训练同路径 = 手动跑 DINO 24 层, 取序列 patch 段
     （[cls; specials; patches] 的 `seq[:, 1+K:]`, 而非 `dinov2(x)` 的干净序列——
     后者缺 register token, 与训练分布不同）;
   - **z_s**: `model.encode(x)` 输出;
   - **解码器输出特征 h**: `Y_cum[:, -1]`（最后步累加特征, 与 F_hat 同源但未过
     PixelHead）;
   - 像素目标 pix: 与探针脚本同口径（0-255 反归一化后做线性解码 L1）。
3. 线性解码 L1（np.linalg.lstsq, 同 trace_info_pixel.py 的 dec_l1）: P→像素,
   z_s→像素, h→像素; 同时记录各层 within-std。
4. **判读规则**:
   | 结果 | 结论 |
   |---|---|
   | z_s→像素 ≈ 9–14 | 信息在 z_s, 浪费在解码结构 → 坐实"解码栈压制", 走 §6-A |
   | z_s→像素 ≈ 19–20 与全量相当 | 解码器没浪费多少; 瓶颈在编码路由/读出上限 → 复核 §2① |
   | z_s→像素 ≈ 40+ | 编码路由就丢了大半 → 先修 F1/E2'（编码侧注入） |
5. 产物: `output/probe_e1_<model>.json` + 本目录追加小节。

## 6. 后续选项（按信息量排序, 服务器开机后拍板）

- **A. 解码器单变量对照**（~2h）: slice27_v2 编码器配置（K=63, 同预算同 lr）,
  解码器换成 v4 式无时序读出（q=query_base 仅, 无自注意力/无 A_t/无累加, 新模块
  lr 3e-4 可对齐 v4）→ 若进 8–14: "解码栈压制"定案, Phase-1 编码器直接走这条;
  若仍 ~19: 压制在别处（编码训练细节）, 再查。
- **B. E2'/F1 编码侧注入**（1–2 天）: special 输入拼 `Linear(patch_feat)`, 让
  register 真正分工 —— 渐进语义叙事的正路, 但不在 GOAL §2 验收内。
- **C. Phase-2 预演**（唯一验收）: 冻结最好编码器 → MLP → Qwen 小批量文字。
