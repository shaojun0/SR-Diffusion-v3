## 0. TL;DR（先看这六条）

1. **三个配置全部是"读出容量/可及性"杠杆, 共同上限 ≈ 19–20**（S25/S64 独立重训
   19.15/19.58 是无偏锚点: 单步给 36–80 个 register 也只有 ~19）——都**够不到**
   旧 slice27 的 14.28, 更造不出真阶梯。
2. **配置 ① 的推理期干预版已有实测**（探针 `mem_all_open` = memory 全开 + 因果 tgt）:
   同权重下 20.64 → 21.84（略差, 分布外伪影, 不能当训练结论）。
3. **配置 ② 的历史同族数据是反的**: 09-01 分块 K=576 无解耦 **17.46** vs +解耦
   **18.77**——去解耦（plain cumsum）当年反而更好; 文档判读"梯度再平衡不是杠杆":
   旧模型 step-1（经混叠）是唯一有用杠杆, 解耦把它梯度从 |T| 份削到 1 份。
4. **当前因果模型下配置 ② 预期收益小**: step-1 瓶颈是**可及范围（0..15）**不是
   梯度预算, 5 倍梯度突破不了可及上限; 后步梯度变大但读的是 cos≈0.97 塌缩簇,
   无增量可修 → 预期 L1 改善 ≤~1, 曲线更平。[推断]
5. **配置 ③（全键 + plain cumsum）是三配置中预期最优**（≈19 上下, 全平或弱阶梯）,
   但仍远不到 14.28: 14.28 需要**跨步行状态混叠**（被因果 tgt 堵死）, 而"直接交叉
   注意力读 register"的精度上限就是 ~19（S25/S64）。[推断]
6. **无论哪个配置, 对"通过 v2 实现 v1"的边际贡献 ≈ 0**: 阶梯不是验收项
   （GOAL §2: 平台=联想已成立; 验收=K 压缩×重建质量 + Phase 2 NLP）。
   若一定要实证, 最省事 = **单发读出 K=63**（|T|=1 消掉累加/均值损失）,
   它是配置 ① 的极限形态且预期 ≥ ①。

## 1. 三配置定义（代码行级）

| # | 改动 | 位置 | 数值变化 | 实际改变 |
|---|---|---|---|---|
| ① | memory 掩码放开（全键可及）, 查询自注意力保留块因果 | `build_block_mask` → 全 0（读法 A）; 或每步套首步前缀规则、前缀逐块增长（读法 B） | 前向输出变 | 每步**可及键范围**变大（读法 B 即 08-27 KV 因果前缀的 K=63 版: 步1 见 0..15 … 步5 见 0..63） |
| ② | 去掉梯度按步解耦 | `decode()`: `Y_cum = ...detach()+Y` → `Y.cumsum(dim=1)` | **数值不变**（解耦版本来就是 cumsum 的数值拷贝） | 只改**梯度归因**: Y_t 从"只收自己那步 1/|T| 份"变回"收第 n≥t 步全部损失项"（Y₁ 收满 |T| 份, 三角失衡回归） |
| ③ | ① + ② | 上两者 | 同①前向 + 同②梯度 | 每步全键可及 + 前步梯度霸权 |

> 读法 A/B 结论基本一致（键超 ~16–36 后冗余, 前缀多开不加信息）, 下文以读法 A
> （memory 全开）为主分析, 读法 B 只在 §2.1 末尾补充。

## 2. 逐配置分析

### 2.1 配置 ①: 打开 memory（全键/前缀）, 仅剩查询因果

- **探针实测（同权重 eval 干预 = 读法 A）** [数据]: trained 20.64 → mem_all_open
  **21.84**（512 子集）。注意这是分布外干预: 权重按"步1 只读 0..15"训练, 放开键
  不是它训练过的通路, **不能**据此说"全键更差"或"信息不在 z_s"; 只能说明该权重
  不会用额外键。
- **训练期预期** [推断, 锚点 S25/S64]: step-1 可及 16 键 → 64 键。但 S25/S64 已
  标定: 单步前缀全开（36/80 键）训练也只能 **19.15/19.58**——因为位置 16..63 是
  cos≈0.97 的冗余簇（探针实测）, 键多内容不增。预期重训 ≈ **19.2–19.5 全平**,
  比现状好 ~0.5, 远够不到 14.28。
- **为什么够不到 14.28**: 14.28 来自 step-1 经查询自注意力**混叠池化**步 2..5 的
  "经 FFN 装饰后的行状态"（跨步行状态混叠）; 配置 ① 保留因果 tgt = 堵死该通道,
  而"直接交叉注意力读 register 键"的读出精度上限就是 ~19。
- **读法 B（前缀逐块增长）**: 曲线头部会略粗（步1 只有 0..15 → ~19.9）, 步 2+
  因键冗余停在 ~19.5 → 出现"弱下降"假阶梯, 但那是**键少造成的差**, 不是信息增量。
  若目标是看到"阶梯形状", 它是唯一能看到形状的选项——代价是 L1 更差。

### 2.2 配置 ②: 去掉梯度解耦（plain cumsum）

- **历史同族数据（最重要的一条）** [数据]: 09-01 分块掩码 K=576 [4:9] 无解耦
  **17.46**; 加解耦 → **18.77**（+1.31 变差）; 深度补到 4 层也只回到 18.25。
  即: **去解耦（plain cumsum）在历史上是更好的那个**。判读（ANALYSIS §6.6）:
  旧模型 step-1 是唯一可用杠杆（混叠全信息通道在它手里）, 解耦把它每样本的梯度
  从 |T| 份削成 1 份 → 饿着主力; 后步没有可再分配的信息, 公平梯度无处可用。
- **当前因果模型下** [推断]: step-1 的信息瓶颈是**可及范围（0..15, 掩码决定）**
  而非梯度预算 → plain cumsum 给 Y₁ 5 倍梯度也突破不了 ~19.9; 后步梯度权重从
  1/5 升到 4/5..2/5, 但它们只能读 16..63 塌缩簇, 增量≈0。预期: L1 小幅改善
  （≤~1）, 曲线依旧全平, "第一步扛全部"更彻底（更远离阶梯）。
- **⚠️ 实验注意事项** [推断]: L1 梯度恒定 ±1/归一化常数, Y₁ 收 |T| 份 = 等效
  学习率放大 |T| 倍; 与解耦版对比须同步调 lr, 否则结果不可比。
- **推理期不可探**: 数值与解耦版完全相同, eval 数字 = trained 20.64, 只能重训验证。

### 2.3 配置 ③: 全键 + plain cumsum

- [推断] Y₁ 全键可及 + 满梯度 → 最接近"单发全键读出"的训练压力; 后步 4/5..2/5
  梯度 + 全键, 理论上最可能让后步做"多视角精修"。但精修内容仍来自同一冗余簇
  （16..63 cos 0.97）+ 固定模板读出（F3/F4）。预期: 三配置中 L1 最优 ≈ 19 上下,
  曲线基本全平; 若显弱阶梯, 性质同 §2.1 读法 B 的假阶梯。

## 3. 共性上限论证（为什么三者都到不了 14.28 / 造不出真阶梯）

1. **读出上限锚点** [数据]: S25（36 键单步重训）=19.15, S64（80 键）=19.58 ——
   "固定 query_base 模板 + 直接交叉注意力读 register"的精度上限 ≈ 19–20, 与键数
   无关（键冗余, S25≈S64 差 2.2%）。
2. **14.28 的机制是混叠池化, 不是读出容量** [数据]: 旧 slice27 = step-1 池化
   步 2..5 的装饰行状态; 三配置全部保留因果 tgt → 该通道封死 → 上限回到 ~19。
3. **真阶梯需要"每块独立可加信息"** [推断+数据]: 因果训练已把 16..63 压成
   cos 0.97 单簇、采样种子 pos16..49 压成 cos 0.999（探针实测）——掩码/梯度侧
   的任何改动都变不出不存在的分工; 分工只能来自**编码侧注入逐 patch 内容**
   （E2'/F1: special 输入拼 `Linear(patch_feat)`）或 K=N 下的 E2 原式。
4. **价值判断** [文档]: GOAL §2 明示平台（少键≈全键）是"联想已成立"的证据,
   阶梯不在验收标准内; Phase 2（v1）推理一次性消费全部 K token, 无"逐步解锁"。
   → 三配置即使实证跑赢, 也只是像素探针 19.9 → ~19.2 的止痛药级收益。

## 4. 若未来实证: 建议与成本

| 方案 | 内容 | 成本 | 预期/目的 |
|---|---|---|---|
| 单发读出 K=63（Route A） | 去掉时间轴/累加/掩码, 1 步 N 行读出（≈v4 解码结构）, 同预算重训 | ~2 GPU·h | 配置①的极限形态; 检验能否进 8–14 区间, 直接服务 v1 编码器 |
| 配置③重训 | 全键 + plain cumsum | ~2 GPU·h | 三配置中 L1 最优的实证; 顺带关掉"掩码/梯度侧"这条线 |
| 配置②重训 | 块掩码 + plain cumsum | ~2 GPU·h | 补"去解耦在当前因果模型"的实证（历史 17.46 vs 18.77 的外推校验） |
| 配置①重训 | 全键 + 解耦现状 | ~2 GPU·h | 信息量最低（§2.1 预期明确） |

> 结论: 若只想"关掉一条线", 跑配置③或单发; 若想服务 v1, 跑单发（Route A）;
> 配置①单独跑的信息量最低。全部为 2026-09-04 推断, 未训练验证。
