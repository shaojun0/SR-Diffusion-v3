## 0. TL;DR（先看这六条）

1. **"后几步 ≈0"在因果 mask 模型里再次实锤**：5 步各自输出的像素量级
   `step_px_scale = [1.02, 0.09, 0.07, 0.06, 0.06]`——Y₂₊ 只有 Y₁ 的 6–9%，
   且逐 n 累加 L1 全平（20.64 → 20.64, 512 子集口径）→ 后几步**没有任何可加的增量**。
2. **因果 mask 训练让"后区 register"塌缩成单一冗余簇（新证据, 比旧模型更极端）**：
   实测 z_s 位置 16..63（步 2..5 的读区）两两 cos ≈ **0.96–0.97**（块内 0.963–0.973、
   跨块 0.969–0.974）;对照旧无因果模型同口径 ≈ 0.90–0.92（09-02 REPORT）。训练把
   16..63 压成"一份全局摘要的 48 份拷贝"——**步 2..5 读到的本来就是同一份内容**。
3. **采样种子塌缩到 cos≈0.999（最刺眼的一条）**：步 2..5 的查询内容项
   `A_t = z_s[16/25/36/49]` 两两 cos = **0.9982–0.9999**（而 pos9 与它们只有 0.36）——
   解码器在步 2..5 拿到的查询种子彼此**几乎相同**。模型"放弃"了后步: 把全部有效
   信息放进 step-1 能读的 0..15, 后区沦为不携带独立信息的冗余摘要。
4. **推理期放开掩码救不回来**：tgt_mask 全开（memory 掩码不变）→ L1 20.64 → **36.2**;
   全开也 37.5。因果训练出的权重**依赖**因果结构, eval 干预不是旧模型, 无法用来
   拆 +5.6 归因——真正归因只能重训（二路消融: MLP 头 × 无因果 mask, ~2h）。
5. **step-1 全键放开反而略降（21.8 vs 20.6）是分布外干预伪影**：权重按 0..15 掩码
   训练, 放开键 ≠ "信息不在 z_s"。此干预**不能**用来否定"信息在 z_s", 记录备查。
6. **对 §0.5 推论的两条正交前提的实证修正**："每步独立预测"损失改造**造不出**
   16..63 的独立内容——S25/S64 独立重训早已证明给单步 36–80 个 register 也只有
   ~19.2（F3/F4 读出上限）。独立损失只有配合**编码侧信息注入（F1/E2'）**才有意义。

## 1. 探针设计（全部为推理期干预, 不重训）

对同一个 final_model 做 5 个掩码配置 + z_s 结构测量（512 张 test 子集, bs16,
fp32;每配置 ~14s）:

| 配置 | memory_mask（读侧） | tgt_mask（查询自注意力） | 目的 |
|---|---|---|---|
| trained | 分块（训练原样） | 块因果（训练原样） | 复现基线 |
| mem_step1_full | 分块, 但步1放开全部键 | 块因果 | "信息是否在 z_s、只是被掩码挡在步1外" |
| mem_all_open | 全部键全开 | 块因果 | 同上, 全步放开 |
| tgt_open | 分块（原样） | 无（全双向） | 拆 +5.6 归因（报告 §5.1 二路消融的 eval 版） |
| both_open | 全开 | 无 | 旧行为（无因果时代）在现权重上的复现尝试 |

实现: monkeypatch `model_v2.build_block_mask` / `build_causal_query_mask`
（decoder.forward 在调用时按模块全局名解析, patch 即生效）。**eval 干预 ≠ 重训**,
所有跨配置结论只谈"该权重在该访问结构下能用出多少", 不谈"重训会怎样"。

## 3. 判读: 理论与实际为什么不符

### 3.1 理论隐含假设被实测否定: "每块有独立可加信息"不成立

"堵混叠 → 每步只见自己的块 → 逼出分工 → 曲线变阶梯"的全部推演, 都建立在
**每个 z_s 块携带彼此独立、能逐 patch 定位的信息**这一隐含假设上。实测:

- 因果 mask 训练下, 步 2..5 的读区（位置 16..63）**塌缩成 cos≈0.97 的单簇**——
  跨块 0.969–0.974 ≈ 块内 0.963–0.973, 即"块"之间没有信息边界可言;
- 更致命: 步 2..5 的**查询种子** z_s[16/25/36/49] 彼此 cos≈0.999 ——解码器层面
  后四步连"不同的起点"都没有;
- 对照旧模型（无因果, 09-02 同口径 0.90–0.92）: 旧模型的后区还没塌到 0.97,
  而即使那样也只够混叠通道"蹭出"14.28, 不够任何一步独立读到 14 以下。

### 3.2 "14.28 的胜利"从来不是渐进, 是 step-1 的混叠池化

旧 slice27（无因果）的 14.28 = step-1 经查询自注意力, 把步 2..5 的行状态
（各自读了 16..63 的块 + 各自种子的内容）**池化进自己的输出**。时间轴在这里的
实际作用 = "给 step-1 一个能看完全部 register 的迂回通道", 不是"每步补一层信息"
（旧报告已证 Y₂₊≈0）。堵死混叠 = 关掉这条唯一的全信息通道 → step-1 只剩 0..15
前缀 → 落到 ~19.9 ≈ 单步/前缀独立读出的上限（S25/S64: 19.15/19.58, 同量级）。

### 3.3 "曲线全平"在权威目标（GOAL §2）下不是缺陷, 阶梯也从来不是验收项

GOAL_compression_for_nlp.md §2 明确: 验收 = **K 压缩 × 重建质量**（Phase 1 中间
验收）+ **Phase 2 冻结编码器的 NLP 文字质量**（唯一最终验收）;"少 token 还原全图"
的**平台本身是"联想能力已成立"的证据**。Phase 2（v1: z_s → MLP → Qwen）在推理时
一次性使用全部 K 个 token, **不存在"逐步解锁"**。因此 09-01 起追的"渐进阶梯"
既与架构/信息现实不兼容（§3.1–3.2）, 又不在验收标准内——这是"理论和实际不符"
最根本的一层错位。

### 3.4 修正后的机制结论（对 ANALYSIS §0.5 的实证补充）

- 堵混叠失败的原因分两层, 缺一不可:
  ① **信息侧**: 因果训练主动把 16..63 压成冗余簇（0.97）——后步无内容可加;
  ② **读出侧**: 即使有内容, 固定 query_base 模板 + 共享键凸组合（F3/F4）的
  单步读出精度上限 ≈19–20（S25/S64 重训即此上限的独立估计）。
- 推论修正: "每步独立预测"的损失改造**单独**不是杠杆（独立单步也只有 ~19）;
  它与 E2/F1（把逐 patch 内容注入查询/编码侧）是**联合前提**, 不是正交可选项。
- E2 在 K<N 压缩下需改写: 原式 `Q = A_t + query_base + Linear(z_s[k])` 依赖
  K=N（patch k 有自己的 register）。K=63 < 576 时不存在 z_s[k>63] ——若坚持渐进,
  要么 K=N（放弃压缩）, 要么改注入 DINO patch 特征侧（E2': special 输入拼
  `Linear(patch_feat)` 让 register 真正分工, 即 F1 路线）。

## 4. 通向 v1（NLP）的选项（按证据强度排序, 未跑, 待拍板）

| 选项 | 内容 | 依据 | 成本/风险 |
|---|---|---|---|
| **A. 接受"无渐进", 编码器收敛到 v4 式单发读出 K≈64** | model_v2 去时间轴/累加/掩码（decoder_steps 单步或 v3/v4 式 N 行单发读出）, K=63–64 重训; 或直接按 train_v4.py 配方重训 + `--freeze_dino` 孪生对照（补 P1 归因） | v4 (register K=64 + DINO 微调 + 单发) = 8.26, 仓库内最佳且配置已知; v2 编码器形态与 v4 相同, 差的只是解码器; 探针证实时间轴机制对重建无正贡献且主动制造塌缩 | ~2 GPU·h/run; DINO 微调语义漂移风险仍在（Phase 2 前须量化） |
| **B. 坚持渐进语义（若要）** | ① E2'/F1 编码侧注入 patch 特征 → register 分工 → 再谈每步独立损失; ② 或 K=N 下实现 E2 原式 | §3.4; ANALYSIS §9 P0 | 1–2 天架构活, 无成功保证; 对 v1 非必需 |
| **C. 像素侧停手, 直接 Phase 2 预演** | 冻结现有最好编码器（slice27 14.28 或 v4 8.26）→ MLP → Qwen 小批量中文文字, 直接回答"z_s 语义信息够不够 v1" | GOAL §4.4/P2; 像素侧已 6 轮证伪, 继续调像素边际信息低 | 需 Qwen + 标注数据管线; 是唯一验收, 迟早要做 |

**建议顺序**: 若目标是"尽快用 v2 成果实现 v1" → **A 先跑**（拿到干净的 K=64
编码器, 顺带补 v4 归因）→ 接着 **C**（Phase 2 预演给最终答案）。B 仅在用户
坚持"token 增量性"叙事本身时才做, 且需先接受它不在验收标准内。
