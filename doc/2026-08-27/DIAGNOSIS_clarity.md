> 诊断方式：**离线静态分析**（读代码 + 读报告/数据 + 纯计算复现）。服务器已关机，无 GPU、无 DINO 权重、无 parquet 数据，**未跑任何训练/推理**。

## 0. 结论速览（TL;DR）

**最可能的 1-2 个根因：**

1. **输出查询解码器的"逐 patch 信息路由"缺陷（主因，可回收约 13 L1）**：编码器侧的 special token 输入不含任何 patch 自身内容（`token+pos[k]` 全位置共享，`model_v2.py:94-110`），576 个 `z_s[k]` 实际都是"全局摘要"，彼此高度冗余；解码器查询的内容项 `W_q(A_t)` 是全局的（与 patch 无关），逐 patch 身份只来自**固定的** `query_base[k]` 模板（`model_v2.py:303,314`）。结果：每个 patch 的输出只能是对少量共享键的凸组合 + 共享 FFN，**无法表达逐 patch 的高频细节**。这就是 t≥1 平台（2 键≈577 键）与边缘低通的直接原因。
2. **DINOv2 语义特征的信息上限（结构性次因，决定"清晰"天花板 ≈9.8）**：真实 DINO 特征线性解码像素的 L1=9.8（[数据]），即哪怕下游完全无损，也只能到 9.8；要更清晰必须让不冻结的 DINO 真正适配像素重建（当前 7009 张/8760 步/单 lr 不足以大幅改造 304M 预训练参数）。

**最值得先试的 1 个改动：**

> 先花 ~30 分钟跑一次**诊断探针**（对新 `final_model.pt` 复用 `trace_info_pixel.py`/`pixel_recon_check.py`，度量 `z_s`、`F_hat` 的线性解码 L1），精确定位 12.9 的差距落在 ReEncoder 还是 Decoder；**随后改解码器为"逐 patch 内容查询"**（一行改动：`Q = W_q(A_t) + query_base + Linear(z_s[k])`），预期全量 L1 从 22.7 降到 ≤16，t≥1 平台消失。详见 §7。

## 1. 背景与任务定义

- 模型：`SRPhase1V2`（`model_v2.py`）。输入 `pixel_values (B,3,448,252)`（DINO 归一化）→ **DINOv2-large（不冻结）** → `ReEncoder`（4 层 Transformer，dim=1024）→ `OutputQueryDecoder`（输出查询注意力，平方采样 25 步，KV 因果）→ `PixelHead`（单层 Linear 1024→588）→ 像素 patch `(B,576,588)`。
- 目标：重建 448×252 工地图像素（每个 14×14×3 patch = 588 维），全 fp32、平权 L1、bs16/卡×2、lr=1.5e-4 cosine、40 epochs/8760 步。

## 3. 逐项排查

### 3.1 过拟合？—— **否，正常收敛偏轻度欠拟合**（证据充分）

| 检查项 | 证据 | 结论 |
|---|---|---|
| train/eval 分离 | `train_v2.py:164-171`：`train_files=glob("train-*.parquet")`（7009）与 `test_files=glob("test-*.parquet")`（3004）是不同文件、不同 split，无交叉 [代码] | 分离 ✓ |
| eval 曲线 | 0.5294→0.4735→0.4471→0.4236→**0.4230**（step 2000/4000/6000/8000/8760，`REPORT_test_v2_pixel_target.md §3`）单调下降**无回升** [数据] | 无过拟合信号 ✓ |
| 正则 | `train_v2.py:79` weight_decay=0.01；ReEncoder dropout=0.0（`model_v2.py:173`）；无数据增强（`data_v2.py` 的旋转是 aspect-ratio 的**确定性**函数，非随机）[代码] | 正则弱，但未见其害 |
| 过拟合的充要迹象 | 若过拟合：train loss 持续降而 eval 平台/回升——当前 eval 到 8760 步仍在微降（0.4236→0.4230） | 不成立 |

**判读**：这是"强监督、确定性任务（重建输入本身）、eval 与 train 同分布"的正常收敛形态。末尾 760 步 eval 仅降 0.0006，说明**已基本收敛、轻度欠拟合**（再多训一点收益有限，除非改架构/损失）。**过拟合不是清晰度不足的原因。**

> 附带论证 [推断]：目标信息量巨大（每样本 448×252×3≈33.9 万像素值，7009 张 ≈ 2.37G 值），367M 参数不可能逐样本死记（参数量 < 目标信息量），模型必须学习"图像的通用结构"才能压低 train loss——这从信息论上就不利于过拟合，与实测 eval 单调下降一致。

### 3.2 参数量不够？—— **总量足够，但结构失衡：像素解码头仅 0.6M 且为线性、无空间归纳偏置**

**分布**（[计算]，§2）：ReEncoder 51.57M（81%）> Decoder 10.63M（17%）> PixelHead 0.60M（**1%**）> SpecialBank 0.59M。DINO 304M 不冻结。

**PixelHead 单层 Linear(1024→588) 是否为瓶颈？** 分两层看：

1. **维度上不构成硬瓶颈** [推断]：588 维像素 patch，1024 维特征在维度上足够（1024>588）；若特征 `z_k` 是像素 `p_k` 的仿射满秩编码（`z_k = A·p_k+b`，A 列满秩），则 `W·z_k` 可精确重建。602,700 个参数（588×1024+588）本身足以表达任意 588×1024 线性映射。
2. **真正的约束是"特征必须可线性解码"** [推断]：整条链路（ReEncoder 每层的 LayerNorm ×2 + 最终 norm、Decoder 的 `norm(ffn(Y))`，见 `model_v2.py:173-176, 324`）对每个 token **减去均值、除以标准差**——特征与像素之间是强非线性关系；单层线性头要求模型把像素信息"线性化"进特征，这是对编码器容量的隐性征税。实测重建 std≈原图 86-100%（`REPORT_test_v2_pixel_target.md §4.3` 表格 57.3/66.8=0.86、70.5/78.3=0.90、81.2/85.2=0.95；本文蒙太奇统计 92-100%），说明**低频/能量保住了，但高频（邻域差）只剩 ~1/3**（§4.4.6）——这正是"信息在特征里但无法被线性头完全读出"或"特征里就没有高频"的低通特征。
3. **关键对照（信息上限探针）** [数据]：真实 DINO 特征 → **线性**最小二乘解码 L1=**9.8**（`REPORT_test_v2_train_and_leak.md §5.7`）。探针本身就是一个"线性头"——说明**线性解码能力在原始 DINO 特征上可达 9.8**，模型 23.4 与 9.8 的差距不是"线性头不够"能单独解释的，而是**喂给头的特征已经不行了**（ReEncoder/Decoder 链路丢失）。PixelHead 的线性性是一个**放大因子/次因**，不是根因；但它是全模型最便宜的升级点（0.6M→几 M）。

**ReEncoder/Decoder 容量是否足够？** [推断] 51.57M + 10.63M 处理 576×1024 维特征，参数量是输出像素维（576×588≈33.9 万）的 180 倍以上，**总量绰绰有余**；瓶颈不在体量而在结构（见 §4.4.3）。

**与主流图像重建解码器对比**（[推断，文献常识]）：

| 模型 | 解码器规模/结构 | 与本模型对比 |
|---|---|---|
| MAE（ViT-L） | 解码器 8 层×512 维（论文称"轻量"，仍为数千万级） | 本模型"解码"=10.6M 特征 + 0.6M 像素，仅约 1/10 |
| Stable Diffusion VAE | 解码器 ≈49.5M，**分层转置卷积**（空间归纳偏置强） | 本模型无任何像素级卷积/局部性 |
| VQGAN / 常规 VAE | 解码器与编码器同量级或更大，卷积/转置卷积 | 同上 |
| DiT | 线性 patchify 头（小） | 例外——但 DiT 解码的是 **VAE 已压缩好的 latent**，任务完全不同 |

**结论**：参数量不是"不够"，而是**分配失衡 + 缺空间归纳偏置**：81% 参数在编码侧，解码侧（17%+1%）既小又没有像素级先验。这放大了"特征链路丢失高频"的后果，但根源不在参数数量本身。

### 3.3 数据量不够？—— **对"泛化/DINO 微调"有影响，但不是本次模糊的直接原因**

| 指标 | 数值 | 判读 |
|---|---|---|
| 训练样本 | 7009 张（40 epochs → 280,360 次样本视图） | 对 367M 参数而言**很少**（参数/样本 ≈ 52,400:1）[计算] |
| 强监督强度 | 每样本 33.9 万像素值目标（确定性重建） | 信息量巨大，部分抵消样本少 [推断] |
| 多样性 | 工地场景（天空/地面/围挡大面积均匀），patch 特征跨位置 std≈5e-5（历史实测）[数据] | 多样性低 → 学到的"边缘/纹理先验"少 |
| 增强 | 无随机增强（旋转为确定性函数）[代码] | 相当于每 epoch 看到完全相同的 7009 张 |

**判断**：
- **不是过拟合的原因**（§3.1 已排除）。
- **不是"模糊"的直接原因**：模糊是单图性质，7009 张再多一倍，只要信息链路丢高频，重建照样糊 [推断]。
- **真实影响在两点** [推断]：① DINOv2-large（304M）微调效果受限于 7009 张同类图——想让 DINO 为像素重建保留纹理信息，7k 张同分布数据远远不够，DINO 基本停留在语义特征；② 无增强 → 泛化边际小（eval 3004 张与 train 同分布，测不出分布外退化，但也没吃到多样性红利）。
- **结论**：数据量是**次因/远期项**：加随机增强（翻转/随机裁剪/颜色抖动，注意 `data_v2.py` 当前是确定性预处理）与扩数据有助于 DINO 微调与泛化，但**先修架构才有意义**。

### 3.4 其他更可能的根因（重点）

#### 3.4.1 DINOv2 特征的信息瓶颈 —— 结构性次因（决定 9.8 这个"清晰"天花板）

**证据链**：
1. **探针实证信息在 DINO 特征里** [数据]：真实 DINO patch 特征 → 线性解码像素 L1=**9.8**（改善 51.5 vs 平均色 61.3）。→ "改解码器能不能追上 9.8"的答案是：**能**，因为 9.8 用的是 DINO 原始输出、线性解码，模型链路（ReEncoder+Decoder+PixelHead）只要做到"信息无损通过"，就能从 23.4 降到 ≈9.8，回收 12.9 L1。
2. **但 9.8 本身仍是"偏糊"水平** [推断]：9.8 相对完美重建（好自编码器在类似数据上 L1 通常 5-8）仍有明显平滑——DINO 是**语义/分类特征**（patch=14 粒度、24 层全局注意力混合 + LayerNorm），高频纹理在编码时被语义化/平滑化。**9.8 是"下游无损"的乐观上限，不是"清晰"的终点**。
3. **patch embed 本身不丢信息，丢在 Transformer 语义化** [推断]：patch embed 是 kernel=14 的卷积（588→1024，线性、可单射）；之后 24 层全局注意力把逐 patch 内容混合成语义 blob。
4. **DINO 不冻结 ≠ 已适配** [推断]：`train_v2.py:176-189` 只设了单组 lr=1.5e-4。对 304M 预训练 DINO 而言该 lr 偏高（典型微调 1e-5~5e-5），且 7009 张×8760 步的像素 L1 梯度逐参数很弱——eval 曲线（§3.1）显示整体稳步改善但幅度温和，与"DINO 大体保持预训练行为"一致。要让 DINO 为纹理保留信息，需要分组低 lr + 更多/更多样数据 + 更长训练。

> **探针协议备注** [数据]：9.8 是**旧模型（特征目标训练）**的 DINO 特征、在 32-64 张 test 上**同批拟合+同批评估**的最小二乘结果（`pixel_recon_check.py:61,95-99`）。数值可信（样本 3.7 万 ≫ 588 输出维，过拟合风险低），但属于"上限估计"，且新模型 DINO 微调后的实际值可能不同——需在验证实验中重测（§7 E1）。

#### 3.4.2 损失函数：纯 L1 —— 助推平滑的**放大器**，不是根因

**机制** [推断]：
- L1 的最优解是**条件中位数**：当模型对某像素"不确定"（信息没传过来）时，最优输出是分布中心 → **方差收缩、边缘平滑**。实测重建 std≈86-100%、边缘≈1/3 正是"部分收缩"的形态（§4.4.6）。
- L1 梯度幅度恒为 1（只取符号）：高低频误差同等对待，**没有额外压力去修锐边**；MSE 对大残差（边缘）的梯度略大，但也只改善一点。
- **关键**：信息传不出去时，**任何逐像素损失（L1/L2）都给平滑解**；感知损失（LPIPS）用预训练特征距离、能"逼"模型保住高频，但前提是高频信息在特征里（9.8 探针证明在）。所以**损失是次要的，容量/路由是主要的**。

**建议**（§6 P2）：保留 L1 主损失，叠加 LPIPS / 多尺度（金字塔）L1 / 梯度项，或最后接 patch 判别器。**顺序：先修路由与解码头，再加感知损失**，否则感知损失会逼模型"在没信息的维度上编造锐边"（假细节）。

#### 3.4.3 OutputQueryDecoder 机制 —— **核心根因（代码级证据最硬）**

这是本次诊断最重点的部分。四条代码事实 + 三条实测数据 + 一条机制推断，全部指向同一结论：**该解码器在本任务上无法完成"逐 patch 高频信息读出"**。

**代码事实（[代码] `model_v2.py`）**：

| # | 事实 | 位置 | 后果 |
|---|---|---|---|
| F1 | SpecialTokenBank 输入 `token+pos[k]`：token 全位置共享，只有 pos 不同——**special token k 的输入里没有任何 patch k 的内容** | `model_v2.py:94-110` | `z_s[k]` 想携带 patch k 的信息，**只能靠注意力路由**（从 576 个 patch token 里"挑出"自己的），这是 4 层 8 头网络在 1153 长序列上的硬学习问题 |
| F2 | ReEncoder 的 specials 行**看全部 patches**（全局）+ 前缀链：`z_s[j]` 都聚合了整图信息 → 576 个 `z_s[j]` 彼此**高度冗余**，都是"位置标签化的全局摘要" | `model_v2.py:117-133, 146-152` | 解码器的"前缀"键集合没有信息梯度：加键不加信息 |
| F3 | 解码器查询 = `W_q(A_t)`（**内容项全局**，只取序列第 t 个位置）+ `query_base[k]`（**固定模板**，跨图不变）；patch k 的身份**只**来自固定模板 | `model_v2.py:303, 314` | 逐 patch 读出 = 固定模板与共享键的双线性交互，表达能力低 |
| F4 | `K=V=A`（共享键值），输出 = `norm(ffn(SDPA))`：每个 patch 的输出是对**同一组共享键的凸组合 + 共享 FFN** | `model_v2.py:312-324` | 每张图所有 patch 的输出都活在"这 577 个键张成的流形"里——**无法独立表达 576 个 588 维像素 patch 的高频部分** |

**实测数据（[数据]）**：

1. **t=0 机制被数值证实** [计算]：单键时 softmax 恒为 1（与查询无关）→ t=0 步 576 个 patch 输出**完全相同**（本机验证最大差异 = 0.0）→ t=0 重建 = 全图平铺同一个 patch 模式。实测 t=0 L1=60.03≈平均色 61 ✓ 自洽。
2. **t≥1 平台** [数据]：t=1（2 键）L1=22.93，t=576（577 键）L1=22.72——**577 键只比 2 键好 0.21 L1**（占可恢复空间 12.9 的 1.6%）。如果 `z_s[j]` 携带 patch j 内容、且解码器能读出，长前缀应该显著更好。平台 = **键里没有（或读不出）逐 patch 信息**，正是 F1-F4 的实测投影。
3. **历史探针**（旧模型，机制参照）[数据]：真实 DINO P→9.8，ReEncoder `z_s`→40.4，Decoder `F_hat`→**64.9**（比平均色还差），`F_hat` 空间变异性只剩 P 的 6%（`REPORT_test_v2_train_and_leak.md §5.7`）——旧模型是特征目标退化训练的（结论不可直接外推），但它揭示了**这条链路在结构上极易丢失空间信息**；像素目标训练只是把模型逼到"尽力保留"，没有改变 F1-F4 的结构约束。

**机制推断（[推断]）**：
- "渐进前缀"设计（Perceiver AR 范式，`model_v2.py:55-64, 272-288`）的语义是**压缩**：用短前缀还原长序列。但本任务 `k=全量`（无预算、无压缩），渐进机制**只有成本没有收益**——它限制了长前缀的读出能力，却没有任何地方需要这种限制。
- 训练动力学角度：损失 = 25 步平权均值，t=1 与 t=576 权重相同。模型优化均值的最优策略是"让所有 t≥1 输出尽量相似且尽量好"（共享的全局+模板分量），**长前缀步没有强激励去建立逐 patch 键路由**（即使有，F3 的查询结构也读不出来）。
- 低通特征来源：即使 `z_s` 里有一点点逐 patch 残差，也要先经过"凸组合 + 共享 FFN + LayerNorm + 平均"才能到像素——这一串操作对高频是天然的衰减器。

**结论：OutputQueryDecoder 的逐 patch 信息路由缺陷是本次"糊"的第一根因**，证据强度：代码事实（F1-F4，可复现）+ 实测平台（infer_test.json）+ 机制验证（t=0 恒等输出）+ 历史探针（方向一致）。

#### 3.4.4 训练动态：fp32 合适；lr 单组、40 epochs 基本收敛；t=0 不可约项应剔除

| 项 | 现状 [代码] | 评价 [推断] |
|---|---|---|
| fp32 | 全 fp32，无 autocast（`train_v2.py:229`） | ✓ 合适。历史 bf16+density 曾欠收敛（`REPORT_test_v2_train_and_leak.md §3-4`），fp32+平权正确 |

#### 3.4.5 预处理：1600×900→448×252 不构成"相对任务"的高频损失

## 4. 根因排序（机制链）

| 优先级 | 根因 | 性质 | 证据强度 | 可回收空间 |
|---|---|---|---|---|
| **1** | **OutputQueryDecoder 逐 patch 信息路由缺陷**：special 无 patch 内容输入（F1）、键为冗余全局摘要（F2）、查询身份仅固定模板（F3）、输出=共享键凸组合（F4） | 架构结构性 | 代码事实 + t≥1 平台实测 + t=0 机制验证 | **22.7→≈9.8（12.9 L1）的大头** |
| **2** | **DINOv2 语义特征信息上限 ≈9.8**：高频在 DINO 编码时被语义化/平滑化；不冻结但微调不足（单 lr、7k 张、8760 步） | 结构性次因 | 9.8 探针 + DINO 训练目标常识 | 决定"清晰"天花板；突破 9.8 需 DINO 适配 |
| **3** | **PixelHead 单层线性 + 无空间归纳偏置（0.6M）**：特征须"线性可解码"，高频被 LayerNorm/混合链路压缩后线性头读不出 | 放大因子 | 探针（线性头在原始特征上可达 9.8）+ 参数量 | 改 MLP/小 CNN 后可部分恢复锐度 |
| **4** | **纯 L1 损失**：信息不足时给条件中位数（平滑）解，且对高频无梯度偏向 | 放大器 | L1 统计性质 + 重建 std/边缘形态 | 加 LPIPS/多尺度/对抗提升观感 |
| **5** | **数据量（7009、无增强）+ 训练动态（单组 lr、40 epochs、t=0 不可约项）** | 次要/远期 | eval 单调、无过拟合 | 泛化与 DINO 适配，非本次模糊主因 |
| — | 过拟合 | 已排除 | eval 单调无回升 | — |
| — | 预处理下采样 | 非根因（目标是 448×252 本身） | 代码 | — |

**一句话机制链**：DINO 语义特征把高频纹理"压扁"（上限 9.8）→ ReEncoder 的 special token 不绑定 patch 内容、产出冗余全局摘要 → 解码器用固定模板对共享键做凸组合读数，**逐 patch 高频在链路上被结构性丢弃** → 线性 PixelHead 与 L1 再把残余信息平滑化 → 重建 = 原图低通滤波版（全局方差 ~100%、块内方差 ~80-100%、边缘 ~1/3）。

## 5. 改进方案（按优先级，具体到改哪、怎么改、预期收益）

### P0 — 先诊断定位（不改模型，~30 分钟，服务器上跑）
1. 用**新** `final_model.pt` 重跑 `trace_info_pixel.py`（或 `pixel_recon_check.py`），度量 `z_s` 与 `F_hat` 的线性解码 L1 + within-std。
2. 补测**每 patch 平均色 baseline**（`pixel_recon_check.py` 已有该参照项但未随像素目标版公布）——判断 23.4 是否≈"patch 级 DC"水平。
3. 判定规则：若 `z_s→像素 ≈9.8` 而 `F_hat→像素 ≈23` ⇒ 信息丢在 Decoder（支持根因 1）；若 `z_s≈23` ⇒ 丢在 ReEncoder 路由（支持 F1/F2）；若两者都好 ⇒ 丢在 PixelHead/损失。

### P1 — 修解码链路（最高预期收益）
1. **解码器逐 patch 内容查询**（最小改动，`model_v2.py:314`）：`Q = W_q(A_t).unsqueeze(2) + query_base + Linear(z_s)`——把 patch k 自己的特征注入查询，让每步 t≥k 都能直接读 patch k 的信息。预期：t≥1 平台消失、全量 L1 22.7→**≤16**、边缘恢复到原图 60%+。
2. **编码器侧绑定**（改 `SpecialTokenBank`/`ReEncoder`，`model_v2.py:353-357`）：special token k 的输入加入 `Linear(patch_feat[k])`，让 `z_s[k]` 天然携带 patch k 内容，绕开"4 层网络学 576 路注意力路由"的难题。可与 1 叠加。
3. **简化备选**：本任务 `k=全量`、无压缩需求，可 `kv_causal=False` + `steps=[N]`（或直接把 PixelHead 接到 `z_s`，Decoder 退化为浅 MLP），让"渐进前缀"设计不再限制读出。预期同上，代价是失去渐进曲线（该曲线在本任务只证明了"平台"）。

### P2 — 解码头 + 损失（锐度放大器）
1. **PixelHead 升级**：Linear → 2 层 MLP（1024→2048→588，GELU），或小 CNN（把 (32,18,1024) 特征图卷积/上采样解码到 448×252×3），引入空间归纳偏置。预期：边缘 +30-50%、L1 再降 2-4（在 P1 之后叠加收益更大）。
2. **损失叠加**：L1 + λ·LPIPS（λ≈0.1-0.5）+ 多尺度 L1（1×/2×/4× 金字塔）或梯度项；最后可选 patch 判别器。预期：主观锐度大幅提升，LPIPS 指标下降。
3. **剔除 t=0**：从训练损失与 `F_hat` 集成中去掉 t=0（保留 eval 展示）。预期 -0.3~0.7 L1（[计算]），并去掉一个数学上不可约的目标。

### P3 — 训练口径（远期）
1. 分组 lr：DINO 1e-5~3e-5、新模块 1.5e-4~3e-4（`train_v2.py:212` 拆分参数组）。预期：DINO 保留/增强纹理信息，9.8 上限下移。
2. epochs 60-80 + 随机增强（水平翻转/随机裁剪/颜色抖动——`data_v2.py` 当前为确定性预处理，需在 collate 里加）。
3. 若追求"清晰大图"：输入分辨率 448×252→896×504（2304 patches），改变任务信息量——列为远期独立项目。

## 6. 最小验证实验设计（修改点 + 预期指标）

### E1 — 诊断探针：定位 12.9 L1 差距的层级（P0，无训练，~30 min）
- **改**：无（复用 `trace_info_pixel.py` / `pixel_recon_check.py`，权重换成像素目标版 `final_model.pt`）；顺带补测每 patch 平均色 baseline。
- **测**：`z_s`、`F_hat` 的线性解码 L1（0-255），与 9.8（原始 DINO）和 23.4（模型全链路）对比。
- **预期/判定**：`z_s≈9.8` 且 `F_hat≈23` ⇒ 信息丢在 Decoder（直接支持 P1-1/P1-3）；`z_s≈23` ⇒ 丢在 ReEncoder 路由（支持 P1-2）；两者都接近 9.8 ⇒ 丢在 PixelHead/损失（支持 P2）。**该实验决定 P1 内部先改哪一处。**

### E2 — 解码器逐 patch 内容查询（P1-1，全量重训 40 epochs，~2h）
- **改**：`model_v2.py:314` 一行——`Q = (W_q(A_t).unsqueeze(2) + self.query_base + self.q_patch(z_s)).reshape(...)`，`q_patch` 为新增 `Linear(1024,1024)`（约 +1.05M 参数）。
- **测**：全量像素 L1、t≥1 渐进曲线、边缘/std（复用 `infer_v2_test.py` + `verify_visual.py`）。
- **预期**：全量 L1 22.7→**≤16**；t≥1 曲线由平台变"前缀越长越精细"的阶梯；边缘比从 ~1/3 升到 60%+。若 E1 显示信息丢在 ReEncoder，则先做 E2'（special 注入 patch 特征，P1-2）再重测。

### E3 — PixelHead 增强 + 感知损失（P2，全量重训 40 epochs，~2h）
- **改**：`PixelHead` 换 2 层 MLP（1024→2048→588，GELU）；损失加 `λ·LPIPS`（或 3 级金字塔 L1）；同时剔除 t=0 步。
- **测**：全量 L1、LPIPS、边缘/块内 std。
- **预期**：L1 再降 2-4，边缘 +30-50%，主观锐度明显改善。可与 E2 串行叠加（E2 后再加 E3，预期叠加后 L1 ≈ 12-15，逼近 9.8 上限）。

> 冒烟建议：E2/E3 先在单卡小步数（如 `--max_steps 500`）跑通并看 loss 趋势，再全量。
