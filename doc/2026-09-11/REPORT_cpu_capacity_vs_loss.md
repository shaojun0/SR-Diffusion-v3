# CPU 可证伪实验报告：解码器容量假设 vs 损失结构假设

> 日期: 2026-09-11 ｜ 设备: **CPU only**（torch 2.8.0+cpu, 8 核, 无 GPU）
> 脚本: `doc/2026-09-11/cpu_repro_cumloss_capacity.py`（自包含合成数据；**不依赖 DINOv2 / 真实数据 / checkpoint**）
> 数据: `doc/2026-09-11/data/cpu_repro_results.json`
> 触发问题: "`model_v2.py` 没能自适应，是不是解码器还没到临界值（参数量不够）"

---

## 0. 结论（含一次自我修正）

**容量假设（H1）被否。损失结构假设（H2）也被证明"单独不足以解释"——前一轮把主因归给
损失结构是过强的。** 两个读窗口设定下都**没能复现** v2 的塌缩。

| 臂 | step-1 单独 L1 | 最终 L1 | 后步量级/step-1 |
|---|---|---|---|
| **A** 累加平权损失（depth2, 固定 query_base） | 0.4354 | **0.3484** | **0.81** |
| **B** 累加损失 + 容量×3（depth6）+ 逐 patch 内容查询 | 0.4268 | **0.1959** | **0.91** |
| **C** 分区域私有目标 | 0.8496 | 0.7345 | 0.41 |
| 平凡常数基线 | 0.7882 | — | — |

（上表 = `--visible block`；`--visible prefix` 见 §3，结论方向相同）

1. **加容量不是解药，也不是病因**：B 臂参数量 ×2.8、再加逐 patch 内容查询，后步量级
   依然是 0.91（没有出现 v2 的 0.03–0.06）。容量只改"能多好"（0.3484 → 0.1959），
   不改"后步肯不肯出力"。与 v2 实测 `decoder_depth 2→4`（L1 18.25、曲线照样全平）一致。
2. **累加平权损失单独不足以让后步塌缩**：两个设定下 `progressive L1` 都**单调下降**
   （block 0.4354→0.3484，−20%；prefix 0.4508→0.2298，−49%），且每步都在改善最终结果。
3. 所以 v2 的塌缩既不能只归给容量，也不能只归给损失式子。**仍未对齐的那一处差异**是：
   v2 的 step-1 已经**达到读出机制自身的上限**（S25/S64 单步 19.15/19.58 ≈ 5 步模型
   19.85），而本合成设定里 step-1 距离其上限仍有大净空（弱 step-1 是刻意构造的）。
   最省事的解释：**step-1 吃掉了全部可及净空间 ⇒ 后步边际收益 ≈0 ⇒ 累加损失把零选成
   精确最优**。这条要证伪，得把「读出上限」而非「信息量」当变量再做一组。

## 1. 实验设计：怎么把"容量不够"和"损失结构"分开

真实数据无法回答"信息够不够"，合成数据可以。构造的关键是让**信息充要性成为已知事实**：

- 4 个采样步 `[1,4,9,16]`；`z_s` 块 k 的每个 register = `proj(f_k) + 0.05·noise`
  （同一因子的多次独立读数）
- `target[b] = W_own·f_{group(b)} + W_glob·concat(f) + 0.05·noise`
  ⇒ 每个 patch 由**全部**因子决定（本组为主、全局弱耦合）
- **原始相关系数实测**（不依赖任何回归）：每块均值与 target 的 `max|corr| ≈ 0.66–0.70`
  ⇒ 信息在线性可达意义上充足

两种读窗口（`--visible`）：

| 模式 | 规则 | 对应真实情形 | step-1 读窗口 |
|---|---|---|---|
| `block` | 块内排他（同 `build_block_mask`） | v2 现状 | 只 3 个 register（**刻意做弱**）|
| `prefix` | 全程用第一个步的前缀规则 | v2 里 step-1 已经很宽 | 0..hi(k)，逐步外扩 |

三臂只在"损失/容量"上不同，掩码/查询基/共享参数结构完全同构：

| 臂 | 损失 | 解码器 |
|---|---|---|
| A | `mean_n L1(cumsum_n Y_pix, target)`（原版） | depth 2，固定 `query_base` |
| B | **同 A，一字不改** | depth 6 + 逐 patch 内容查询句柄 |
| C | 每步只监督自己那 1/4 patch 区（私有目标） | depth 2，固定 `query_base` |

判据（都刻意选**不可能有数值陷阱**的量）：
- `step_scale_ratio[t] = mean|pixel(Y_t)| / mean|target|`（塌缩 ⇒ ≪0.1）
- `progressive L1[t] = |cumsum_t 预测 − target|`（逐样本）
- `step1_only = |step-1 的预测 − target|`（"后步什么都不做"的基线）

## 2. 结果 A：`--visible block`（step-1 弱，只读 3 个 register）

```
step_scale_ratio  A = [0.5428, 0.6856, 0.8953, 0.8610]
                  B = [0.5872, 0.7830, 0.9806, 0.9796]
                  C = [0.9897, 0.3306, 0.5266, 0.3678]
progressive L1    A = [0.4354, 0.3702, 0.3631, 0.3484]      (单调下降, −20%)
                  B = [0.4268, 0.3095, 0.1957, 0.1959]      (−54%)
                  C = [0.8496, 0.7850, 0.7286, 0.7345]
平凡常数基线 = 0.7882        oracle 参考 = [0.6123, 0.6174, 0.6196, 0.7890]
```

**在 step-1 被做弱的设定下，累加损失允许并实现了渐进细化**：后步量级 0.81/0.91，
最终 L1 优于 step-1 单独。这正是"渐进"应有的形状。

## 3. 结果 B：`--visible prefix`（step-1 读窗口已经很宽）

```
step_scale_ratio  A = [0.5291, 0.7219, 0.8696, 1.0018]
                  B = [0.6213, 0.7130, 0.8960, 0.9982]
                  C = [0.9912, 0.9473, 0.7503, 0.6158]
progressive L1    A = [0.4508, 0.4082, 0.2753, 0.2298]      (单调下降, −49%)
                  B = [0.4577, 0.4222, 0.2668, 0.2122]      (−54%)
                  C = [0.8507, 0.8551, 0.7820, 0.7266]
oracle 参考 = [0.6238, 0.4516, 0.2620, 0.2620]
```

**把 step-1 的读窗口加宽，渐进反而更强**（−49% vs −20%），因为后续步真的看到了更多
信息。**累加损失没有把后步压成零。**

> 注意这里有个设计局限（诚实声明）：`prefix` 模式下 step-1 的信息量仍小于 step-4
> （信息是随步真的递增的），所以它仍不等于 v2 的"step-1 已到读出上限"。

## 4. 这次踩的坑（每一次都会**静默**把结论带偏）

| # | 错误 | 症状 | 修法 |
|---|---|---|---|
| 1 | `torch.einsum('bp,npq->nq', ...)` 形状错配 | target 量级炸到 29.8，线性分量被淹没 | 改矩阵乘 `C[k] @ G[k]` |
| 2 | 隐因子**独立随机**、到 target 通路随机 | oracle R²≈0.04，信息薄到测不出 | 改因子模型（target 显式线性于因子）|
| 3 | target 生成后成了**常量**（z_s 逐样本变、target 不变）| oracle 恒等于常数解、`cond=inf` | target 必须是**样本的函数** |
| 4 | **训练/测试是两套不同随机结构**（`make_data(0)` vs `make_data(1)` 各自重抽投影矩阵）| 模型学 seed-0 的世界、评 seed-1 的世界：progressive L1 **1.08**，连平凡常数 0.79 都不如 | **同一数据集切分** |
| 5 | 特征标准化后块内近共线、SNR≈400，岭回归 λ=1e-2 把主方向系数压缩 ~50× | 每块 R² 全为负（−1.5 ~ −3.6）| 改块均值/最小范数解；oracle 只作**参考量**，不作判定依据 |
| 6 | `(N,P)` 张量被当 `(T,N,P)` 广播 | 训练跑完、**评估阶段**才崩（白跑 20 分钟） | 直接 `(Y_pix[:, 0] - tgt).abs().mean()` |

**方法学教训**：参照量的数值正确性要先拿**不可能出错的口径**验（原始相关系数、平凡常数
基线），再用来支撑结论。本实验最终只依赖 `step_scale_ratio` 与 `progressive L1` vs
`step1_only` 这三个不存在数值陷阱的量。

## 5. 与真实 v2 的对照表（本实验**没能**复现的部分已标出）

| | 本实验 block 模式 | 本实验 prefix 模式 | v2 真实模型 |
|---|---|---|---|
| step-1 读窗口 | 3 个 register | 前缀（逐步外扩）| 0..hi，**577 token** |
| step-1 距自己的上限 | 很远（刻意）| 较远 | **已到上限**（S25/S64 单步 ≈ 5 步）|
| 后步量级 | 0.81 / 0.91 | 0.86 / 0.87 | **0.06 / 0.03** |
| progressive 曲线 | 单调下降 −20% | 单调下降 −49% | **全平** |

⇒ **唯一未对齐的变量是"step-1 是否已到读出上限"**。这是现在最该拿去做实验的那一个。

## 6. 对 `model_v2.py` 的可执行建议

1. **不要再往"加容量"投资源**：本实验 B 臂（参数量 ×2.8 + 逐 patch 查询）与 v2 的
   depth 2→4 都表明容量对"后步塌缩"没有作用。
2. **先做零训练探针，再动架构**（本项目已重复 5 次"全量训练后才发现机制没生效"）：
   - 残差可预测性：`target − step-1 预测` 对**后区 register 独有信息**做回归。
     ⚠️ 必须**同一数据集切分**、**别用强岭回归**（见坑 #4/#5）。
   - `F_hat` 像素 std（现成阈值：常数色 ≈0.073–0.083，健康多步 0.84）。
   - 现成口径见 `doc/2026-09-07/ANALYSIS_k3_why_later_steps_zero.md` §5。
3. **把"读出上限"当变量做一组**：固定信息供给，人为压低/抬高 step-1 的读出能力，
   看后步是否随之从"出力"翻转到"归零"。这是本实验暴露出的唯一未消融变量。
4. 若确认"step-1 已吃满净空间" ⇒ 要么接受单发（v4 8.26 = 仓库最佳），
   要么换损失（P1 分区域私有目标——仓库里唯一让后步量级从 6% 拉到 45% 的手段），
   要么**给 step-1 减负**（把它的读窗口做窄，让后步有净空间可赚）。

## 7. 复现

```bash
# 块内排他（现状读窗口）
python doc/2026-09-11/cpu_repro_cumloss_capacity.py --steps 450

# 全程前缀规则（step-1 读窗口已较宽）
python doc/2026-09-11/cpu_repro_cumloss_capacity.py --steps 450 --visible prefix
```

CPU 实测：约 0.4–1.1 s/步（B=128, N=32, |T|=4, D=96）；450 步/臂约 3–5 分钟，
三臂约 9–25 分钟。**完全不需要 GPU。**
