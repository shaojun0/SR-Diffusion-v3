## 0. 结论速览（TL;DR）

1. **堵混叠通道后 L1 大幅变差**: 全量 3004 test 像素 L1 = **19.878（±6.96）**，旧 slice27 为 14.284 → **+5.59（+39%）**。
2. **渐进曲线依旧全平**: [19.872, 19.866, 19.866, 19.870, 19.878]（极差 0.013）——**堵混叠**这一 P0#3 杠杆**没有**把曲线从"平台"变成"阶梯"。
3. 结果含义: 查询自注意力混叠通道此前提供的不是"多余的偷看"，而是 **step-1 输出唯一可用的全信息通道**——堵死后模型落回"Y₁ 用首步前缀(0..15, 16 键)尽力 + 后步增量≈0"，总重建回到 ~19.9（≈单块独立水平，见 §4 与 S25/S64 单步对照）。
4. 本实验**耦合了两个改动**（因果 mask × 2 层 MLP 头），回归归因需二路消融拆分（§5.1）；但"曲线仍全平"这一现象与头容量无关（新旧头都平），指向 **z_s 块间冗余（F2）+ 损失结构（累加）未变**——后几步没有"可加的增量信息"。
5. 判读: 在 z_s 冗余（cos≈0.9）与"各块信息等价"（S25≈S64）未修的前提下，**任何掩码侧/头侧改动都改变不了"曲线全平"**——曲线形态的修复仍需 E2（逐 patch 内容查询，让每块携带独立信息）+ 损失结构改造（每步独立预测）。

## 1. 背景与目的

- 系列: v2 register 式分块掩码 5 步模型，K=num_specials 自动推导（b653847）；slice [2:7]（K=63）曾达 v2 block 系列最佳 **14.284**（REPORT_v2_block_slice27）。
- ANALYSIS_v2_story_and_next（09a1db5）§5.4 定位"曲线全平第三支柱" = **查询间自注意力无掩码全双向**——后步查询经第 2 层自注意力把信息"偷看"进第 1 步输出（量化: 同查询同掩码, 5 步在场 17.42 vs 隔离 39.08）。
- §9 P0#3: "堵混叠通道（若要渐进语义）：查询自注意力加按步因果 tgt_mask（步 t 的查询只能自注意力到步 ≤t 的行）——实测可验证'曲线是否从平台变阶梯'"。
- 用户按此实现并提交: `ab2071e` PixelHead 单层 Linear → 2 层 MLP（dim 1024→hidden 2048→588, GELU, ~+2.1M 参数, 回应"解码器参数量不够"）+ `b295016` `build_causal_query_mask`（块下三角 tgt_mask, (|T|·N, |T|·N)）；随后指示: 拉最新代码在新服务器上重跑 slice [2:7]。
- 目的: ① L1 能否维持/超越 14.28；② 曲线是否变阶梯（每步真增量）。

## 4. 判读

1. **堵混叠通道 = 关掉 step-1 唯一的信息通道, 而非"堵偷看"**: 旧 slice27 的 14.28 全部来自"第 1 步经查询自注意力吸收全部块信息一肩扛起"（累加角色分工 + 混叠），堵死后 Y₁ 只能用首步前缀 0..15（16 键）重建 576 patch——19.87 ≈ 与 S25（36 键独立 ~19.15）/S64（80 键 ~19.58）单步水平同一量级，即"无混叠时模型只能达到单块/前缀的独立水平"。
2. **曲线仍然全平 = 后几步仍无增量**: cumsum L1 逐 n 恒定（19.87→19.88），说明 Y₂₊≈0 依旧——即使每步只能读自己块，模型也没把块 16..63 的信息写进增量。原因指向**信息侧**而非掩码侧: z_s 块间高度冗余（cos≈0.9, ANALYSIS 系列实测）、各块信息等价（S25≈S64）→ 后几步"没有可加的增量信息"，堵掩码堵不出不存在的分工（与"梯度再平衡不是杠杆"同族结论）。
3. **两个改动耦合, 无法单独归因**: 本实验同时换了 PixelHead（容量 +~2.1M）与加因果 mask。若 MLP 头自身难优化/更吃数据, 也会贡献一部分 +5.6。需要二路消融拆分（§5.1）。
4. **对 ANALYSIS §9 P0#3 的裁决**: "堵混叠 → 曲线变阶梯"**未获支持**（至少在没有信息分工的前提下）。渐进语义的修复路径应回到 E2（逐 patch 内容查询, 让每块/每步携带**独立**信息）+ 损失结构（每步独立预测）, 而不是掩码侧封堵。

## 5. 建议的后续实验

1. **二路消融拆分 mask × head**: (a) 旧单层头 + 因果 mask；(b) 新 MLP 头 + 无因果 mask——把 +5.6 归因到 mask 还是 head（本报告无法区分）。
2. **E1 探针先行**（ANALYSIS §8.3）: 对 slice27_v2 模型跑 trace_info_pixel 逐层定位信息在哪一级丢失，再决定修编码（F1/F2 分工）还是解码（E2）。
3. **E2 实现 + 每步独立损失**: `Q = A_t + query_base + Linear(z_s[k])`（+~1M）让每行查询读 patch k 自己的内容；损失改"每步独立预测 + 信息流硬截止"——这是让曲线出现阶梯的两条正交前提（信息独立 + 判据有效）。
4. 若只关心重建 L1（不执着渐进语义）: 回到无因果 mask 的 slice27（14.28），在其上叠 MLP 头做单变量验证（头是否有正贡献）。
