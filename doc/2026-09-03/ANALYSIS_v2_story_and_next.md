## 0. 结论速览（TL;DR，先看这十条）

1. **"预测背景"是数学必然，不是模型蠢**：L1 在信息缺失时的最优解 = 条件中位数；工地图大面积均匀，中位数就是背景色。真正的问题永远是**信息为什么没到输出**。
2. **信息没到输出有三层原因，层叠而成**：① 目标退化（特征空间近常数，假收敛）；② 解码器结构上读不出逐 patch 内容（F3/F4）；③ 损失结构 + 查询自注意力混叠让"第一步扛全部"成为最优（曲线全平）。
3. **特征空间的 L1 是骗人的**：工地 DINO 特征跨位置 std≈5e-5，输出质心即 L1=0.000038——看着完美收敛，实际是全图单色。
4. **解码器"读不出"是主犯，且是**诊断后 6 个版本都没修的**那个根因**：DIAGNOSIS 的 E2 修复（逐 patch 内容查询）从未实现。
5. **梯度下降只能沿架构允许的方向移动**：结构表达不出逐 patch 输出时，梯度只能把模型推向"结构允许的最优"= 背景。这是解释一切的总纲。
6. **新 v2（分块掩码+累加）的渐进曲线全平 = 损失结构强制的**：`mean_n L1(cumsum_n Y)` 下，"Y₁=全部、Y₂₊≈0"是全局最优（实测像素增量 [1.054, 0.015×4]）。
7. **分块掩码被"查询自注意力混叠"绕过**：掩码只挡交叉注意力，查询行之间自注意力全开放 → 第一步经第 2 层自注意力"偷看"到所有块（量化：同查询同掩码，5 步在场 17.42 vs 隔离 39.08）。
8. **梯度再平衡不是杠杆**：按步解耦（消灭 t=0 多份梯度）实测 17.46→18.77 变差——因为后面 token 里根本没有可再分配的信息。
9. **K 压缩是有效的**：slice27（K=63）拿到 v2 系列最佳 14.284（vs 旧 K=576 基线 17.46），与 v4 的 K=64（8.26）呼应——"~64 是 register 式模型的甜点"。
10. **v4 的 8.26 ≠ 已验证的胜利**：是"register + 微调 DINO"的联合效应，缺 register+冻结孪生对照；且 DINO 微调有 Phase 2 语义漂移风险。

## 0.5 实验更新（2026-09-03）：堵混叠通道被证伪——掩码侧改动不是渐进语义的修复路径

> 依据: `doc/2026-09-03/REPORT_v2_slice27_causal_mask.md`（HEAD `b295016`：查询自注意力加**按步因果 tgt_mask** + PixelHead 单层→**2 层 MLP**；slice [2:7] K=63 同预算重跑，对照旧 slice27=14.284）。

### 结果

| 指标 | 旧 slice27（无因果 mask，单层头） | slice27_v2（因果 tgt_mask + MLP 头） |
|---|---|---|
| 全量像素 L1 (0-255) | **14.284** | **19.878（+5.59，+39%）** |
| 5 步渐进曲线 | [14.264 … 14.284] 全平 | [19.872 … 19.878] **仍全平**（极差 0.013） |

### 判读（对本文档此前结论的修正）

1. **"偷看通道"不是多余的偷看，而是 step-1 当前唯一可利用的全信息通道**：堵死后 Y₁ 只能用首步前缀 0..15（16 键）重建 576 patch，模型落到 ~19.9 ≈ 单块独立水平（对照 S25=19.15 / S64=19.58）——旧 slice27 的 14.28 全部来自"第 1 步经混叠一肩扛起"。
2. **曲线仍全平 = 后几步依旧没有"可加的增量信息"**：即使每步只能读自己块，Y₂₊≈0 不变。原因在**信息侧**（z_s 块间冗余 cos≈0.9、各块信息等价 S25≈S64）与**损失结构**（累加），不在掩码侧——堵掩码堵不出不存在的分工，与"梯度再平衡不是杠杆"（§6.6）同族结论。
3. **本节对 §5.4 的"偷看"框架和 §9 P0#3 的建议做修正**：堵混叠只有在"每块已携带独立信息"之后才有意义；在此之前它是唯一的全信息通道，堵了只会掉 L1。
4. 实验耦合了两个改动（mask × MLP 头），+5.59 的归因需二路消融（旧头+因果 mask / 新头+无因果 mask）拆分——但"曲线仍全平"与头容量无关（新旧头都平）。

### 累积证据闭环（至此，四类修复尝试全部被证伪或无关）

| 尝试 | 结果 | 结论 |
|---|---|---|
| 改目标（特征→像素） | 64.9→23.41 | 必要但不充分（F3/F4 未修） |
| 改编码器（ReEncoder→register） | 23.41→24.14 | 编码侧修复不动解码瓶颈 |
| 换架构（v3/v4/v5） | 17.77/8.26/41.23 | 换解码器结构才有效；v4 归因存疑 |
| 梯度再平衡（按步解耦） | 17.46→18.77 | 无可再分配信息 |
| K 压缩（slice27 K=63） | →14.284 | **有效**（压缩强制分工） |
| 堵混叠（因果 tgt_mask）+ MLP 头 | 14.284→19.878 | 信息未独立时分工无从谈起 |

**推论**：让渐进曲线出现阶梯的两条正交前提 = ① 每块携带**独立**信息（E2 逐 patch 内容查询 + F1 编码侧注入）；② 损失结构改为**每步独立预测**。在两者之前，任何掩码侧/头侧/梯度侧的改动都只会平移 L1 而改变不了曲线形态。

## 1. 阅读指南：先建立三块心智模型

下面三条是理解全部现象的地基，比任何单条实验数字都重要。

### 1.1 L1 的数学：信息缺失时，"背景"就是最优答案

- L1 损失的最优预测是**条件中位数**。当模型对某个像素"不确定"（信息没传过来）时，最小化 L1 的唯一理性做法是输出分布中心。
- 工地图上天空/地面/围挡占绝大多数像素 → **分布中心 ≈ 背景色**。
- 推论 1：看到"模型在输出均值/背景"，先问"信息为什么没到"，别怪模型偷懒。
- 推论 2：**L1 是面积加权**的。背景占 80% 面积时，重建好背景就能拿低 L1，少数像素（物体/边缘）在指标里被淹没——所以"数字还行但看着差"是常态。永远要配边缘/高频/可视化判读。

### 1.2 梯度只推得动"结构允许"的方向（总纲）

> 梯度下降只能沿着架构表达能力允许的方向更新。如果结构上表达不出"逐 patch 输出"，那么梯度里"逐 patch 的分量"无处可去，模型只能落回结构允许的最优——背景。

- 这条解释了：为什么换损失（特征→像素）不够、换编码器（ReEncoder→register）不够、调梯度（解耦/加权）也不够——**只要解码器读不出逐 patch 信息，梯度就没有地方把信息塞进去**。
- 反向验证：v3/v4 换掉解码器结构后，同一损失、同一数据，L1 立刻从 23.4 级降到 17.77/8.26 级。

### 1.3 信息放置欠定 → 冗余是低梯度代价的解

- 只要损失只要求"信息在前缀里**某个位置**"（不指定哪一格），梯度场就不惩罚"所有格子里放同一份摘要"——冗余全局摘要是**稳定不动点**。
- 打破它需要外力：① 显式压缩（K<N，容量不够冗余）；② 架构不对称（查询绑定 patch 内容）；③ 预算/选择机制。
- 项目的 K 压缩（v3/v4/slice27）走的就是 ①，E2 走的是 ②。

## 3. 失败模式一：目标退化（特征目标时代，08-26）

### 3.1 发生了什么

- 监督目标 = DINOv2 patch 特征。工地图的 DINO 特征**跨位置 std ≈ 5e-5**（每图近似常数向量）[数据]。
- "输出每图质心"就能拿特征 L1 ≈ 0.00004；模型收敛到 **0.000038 ≈ 质心下限**——**完美收敛到常数解** [数据]。
- 渐进曲线全平（25 步 L1 全在 0.000039–0.000041）——"1 个键还原全量"不是泄露，是**目标本身没有空间结构**。

### 3.2 探针揭穿（像素级逆向还原实验）

| 阶段 | 特征→像素 线性解码 L1 | 判读 |
|---|---|---|
| 真实 DINO patch | **9.8** | 信息**在**原始特征里 |
| ReEncoder 输出 z_s | 40.4 | 路由损失部分信息 |
| Decoder 输出 F_hat | **64.9**（平均色 61.3） | **比平均色还差**；空间变异性只剩 6% |

### 3.3 教训

1. **特征空间 L1 一律不可信**；重建类任务必须监督原始像素 + 像素级探针。
2. **永远与"质心/平均色 baseline"对比**——模型必须显著优于它才有意义。

## 4. 失败模式二：解码器读不出（F1–F4，08-27 诊断，根因从未修）

改像素目标后（23.41，比平均色好 2.6×），肉眼看还是"背景+模糊轮廓"（边缘只保留 ~1/3~1/5）。`DIAGNOSIS_clarity.md` 给出四条代码事实：

| # | 事实 | 后果 |
|---|---|---|
| F1 | special token 输入 = 共享向量+pos，**不含 patch k 内容** | z_s[k] 想携带 patch k 信息只能靠注意力硬学路由 |
| F2 | specials 行看全部 patches → z_s 全是"全局摘要"，彼此高度冗余（cos≈0.9） | 键集合没有信息梯度：加键不加信息 |
| F3 | 查询 = `W_q(A_t)`（对全部 patch 相同）+ **固定模板** `query_base[k]` | patch 身份只来自跨图不变的固定模板 |
| F4 | 输出 = 共享键的**凸组合** + 共享 FFN | 所有 patch 输出活在共享键张成的低维流形里，无法表达逐 patch 高频 |

**实测投影**：t≥1 平台——t=1（2 键）22.93 vs t=576（577 键）22.72，**加 575 个键只回收可恢复空间 12.9 的 1.6%** [数据]。t=0 单键机制验证：softmax 恒 1 → 576 个 patch 输出完全相同（max diff = 0.0），重建 = 全图平铺同一 patch ≈ 平均色 [计算]。

**文档里写好的最小修复（E2）**：`Q = W_q(A_t) + query_base + Linear(z_s[k])`——把 patch k 自己的特征注入查询（约 +1M 参数）。**grep 证实 6 个版本（v3/v4/v5/v2 standard/block/block-d4）无一实现** [代码]。

## 5. 失败模式三：新 v2 的"曲线全平"（09-01 之后，机制级分析）

### 5.1 新 v2 改了什么（设计意图）

当前 `model_v2.py`（HEAD `b653847` 之上）：

| 机制 | 内容 | 设计意图 |
|---|---|---|
| 分块掩码 | 每步 t 只见自己的平方块 `[⌊√t⌋², min((⌊√t⌋+1)²−1, K)]` | 每块 register 只供自己的步读 → 每步补一层信息 |
| 首步前缀规则 | 第一个步可见 0..hi（含 z_cls） | 切片丢前段时信息不浪费 |
| **累加集成** | `F_hat = Σ_t Y_t`；loss = `mean_n L1(cumsum_n Y, target)` | 每步输出"残差"，累加出完整重建 |
| 梯度按步解耦 | `carry.detach() + Y`，每步恰收 1/|T| 份梯度 | 消灭 t=0 收 |T| 份梯度的失衡 |
| K/N 解耦 + 自动推导 | `K = min(max_t((⌊√t⌋+1)²−1), N)` | 消除"花瓶 register"（编码器生成、解码器从不读、却经全双向耦合干扰） |
| 标准 TransformerDecoder 2 层 | 查询 = `A_t + query_base`；自注意力全开放，交叉注意力带 memory_mask | Perceiver/BLIP-2 风格 |

### 5.2 累加损失 → "信息前置"是数学最优（曲线全平的第一支柱）

`L = mean_n L1(cumsum_n Y, target)` 的一个（近）全局最优解是：

```
Y₁ ≈ 能独立还原 target 的主预测，Y₂₊ ≈ 0
→ 任意 n 的 cumsum_n ≈ Y₁ ≈ target → 每个损失项同时最小
```

梯度下降没有理由偏离它：**后几步做残差只会引入额外误差风险，不做反而最优**。实测完全命中 [数据]：

- 5 步前向内每步**像素**增量 `|W·Y_t|` = [1.054, 0.015, 0.015, 0.015, 0.015]（第 1 步=唯一主预测器）；
- 同一步在**特征**空间 `|Y_t|` 全部 ≈1.065（没退化）——后几步把输出学进了 PixelHead 的近零空间（R¹⁰²⁴→R⁵⁸⁸ 的核方向）。

> **结论：累加损失下渐进曲线全平是损失结构强制的，不是有效机制判据。** 想测"token 增量性"必须用固定输入逐量解锁的探针（v5 的 m 扫描就是这种，结果是 Δ<0.001——机制从未成立）。

### 5.3 首步前缀规则（第二支柱）

block [4:9] 的第一个步 t=25 可见 0..35（z_cls + register 1..35，36 个键）——单步就握有相当宽的前缀；S25 单步模型同样可见 0..35，独立可达 19.15（和 5 步模型只差 1.7）[数据]。

### 5.4 查询自注意力混叠 = "偷看通道"（第三支柱，最隐蔽）

**现象**：分块掩码只挡**交叉注意力**（查询读 z_s 键）；`nn.TransformerDecoder` 的**查询间自注意力无掩码全双向**（`model_v2.py` docstring L285-287 明说"有意为之"；forward 只传 `memory_mask`，无 `tgt_mask`）[代码]。

**偷看路径**（depth=2 时）：

```
第 1 层: 所有查询行先互相自注意力（此时无人读过块）→ 各自交叉注意力读自己的块
         （第 2 步读到块 2 的键，第 1 步只读到 0..15 …）
第 2 层: 再次自注意力 —— 第 2~5 步的查询已"身怀"各自块的信息，
         第 1 步的查询在此把全部块的信息吸收 → 输出已含所有块内容
```

**量化证据** [数据]：同查询、同交叉掩码（0..35），**5 步在场 17.42 vs 隔离 39.08——22.5 像素 L1 差 = 纯查询自注意力上下文效应**。分块隔离被绕过，渐进语义失效。

> ⚠️ 2026-09-03 修正：该通道当前是 step-1 **唯一**的全信息通道——在信息冗余未修（z_s cos≈0.9）时堵死它，L1 从 14.28 恶化到 19.88（见 §0.5）。"堵混叠"只有在每块已携带独立信息之后才有意义。

### 5.5 三支柱如何合谋制造"全平"

1. 累加损失让"第一步扛全部"成为最优（5.2）；
2. 首步前缀让第一步单键就有宽访问（5.3）；
3. 混叠让第一步**连自己块外的信息都能拿到**（5.4）。

三者的合力 = 后几步无事可做 → 输出≈0 残差 → 曲线全平（block 全平 17.41–17.46 / slice27 全平 14.26–14.28 同形态）。

## 6. 梯度动力学专题（把"头痛"的部分写成可查文档）

> 结合 §1 的三个心智模型，以下是本项目实验里**真实出现过的**梯度机制。

### 6.1 t=0 的 N 倍梯度放大（旧 KV 因果版）

- t=0 掩码只允许看 z_cls → N=576 行查询全部输出同一个向量 → z_cls 从第 0 步单独收 ~N 份梯度。
- 后果：梯度疯狂奖励"把信息塞进 z_cls" → 信息集中 → z_s 冗余（F2）→ 解码器读不出 → 输出背景。自洽坏循环。

### 6.2 位置梯度不平衡（头重脚轻）

- token s 的梯度 ∝ 被多少查询行关注：前缀 token 被所有步关注，尾部 token（末两步之间）只被最后一步关注 → 头部梯度载荷比尾部大一个量级。
- 新 block 版没有完全消除它，但 K 缩到 63 后尾部冷区从 576 缩到 63，天然缓解。

### 6.3 多任务平均：平权 25 步 / 5 步

- 共享参数的更新 = 各步子任务梯度的平均；最省力的方向 = 让所有步输出相似且都还行（对工地图即背景/第一步扛全部）。
- 这是"曲线全平"在梯度层面的投影：**没有子任务梯度在激励"后步差异化"**。

### 6.4 L1 恒定梯度

- L1 每元素梯度幅值恒定（±1/归一化常数），不随误差缩小 → 最优附近无自动减速 → 收敛后像素级抖动（配合 LR 衰减使用）。

### 6.5 花瓶 register 的梯度证据（09-02）

- K=N=576 但只读 1..99 时，花瓶区（100..576）梯度 |Σ|=9.81 > 读窗口 6.35；扰动花瓶输入 → 读窗口输出变化 ~68% [数据/计算]。
- 端到端砍掉花瓶（K=99）反而差（18.53 vs 17.46）→ **花瓶=编码侧附加容量/工作记忆**（24 层全双向注意力的中间 token 有正贡献）[数据]。

### 6.6 反向证据：梯度再平衡不是杠杆（最重要的一条）

- 梯度按步解耦（消灭 t=0 多份梯度 + 每步平权——与"线性加权 w_t∝t"同族）实测 **17.46 → 18.77，变差** [数据]。
- 逻辑：若 z_s 里有可分摊的增量信息，解耦后模型应能把信息分散到各步而不损失精度；**变差恰恰证明信息根本不在后面那些 token 里**——没有东西可再分配。
- **推论：在"读不出逐 patch 内容"（F3/F4）修好之前，任何损失加权/梯度平衡调优都只是止痛药**，真正的杠杆是 E2。

### 6.7 用户曾提的两个方案 → 实验裁决

| 方案 | 裁决 |
|---|---|
| ① 缩短特殊 token（K=128 级压缩） | ✅ **被 slice27（K=63 → 14.284）证实方向正确**；K≈64 是甜点（呼应 v4 8.26） |
| ② 按 2t/((1+T)|T|) 线性加权 | ⚠️ 同族实验（梯度解耦）**证明不是杠杆**：没有可再分配的信息；等 E2 修好后再考虑是否加权 |

## 7. 什么有效：K 压缩 + 换解码器（v3/v4/slice27）

| 版本 | 解码器 | K | DINO | L1 | 证据解读 |
|---|---|---|---|---|---|
| v3 | QFormer 交叉读 + **无时序 N 行查询** | 64 | 冻结 | 17.77 | h 探针 17.03 ≈ 全量 → **解码链路通了**；z_s 均值探针 60.83 → 信息在 token 间差异里 |
| v4 | v3 式无时序 | 64 | 微调（分组 lr） | **8.26** | 端到端 held-out 干净数字；归因=联合效应，孪生对照缺失 |
| v2 slice27 | 分块+累加（新 v2） | 63 | 不冻结 | **14.284** | v2 系列最佳；K 与窗口耦合变化，归因待拆 |

**共同点**：① 解码器让每行查询能自由组合有内容差异的键（不再"固定模板×冗余键"）；② K≈64 压缩强制 z_s 分工。

**v4 的 8.26 不是免费午餐** [推断]：
- "突破 9.8"是旧模型样本内线性上限 vs 新管线端到端 held-out 的口径混比；
- register+冻结孪生（`train_v4.py --freeze_dino`）没跑，现有证据支持增益主要来自 **DINO 微调**；
- 7k 张同分布工地图微调 304M DINO → **Phase 2 语义漂移风险**（GOAL §4.2 预警的"像素化扭曲被永久固化"）——对"冻结编码器做 NLP"的最终目标不是已验证的胜利。

## 8. 验证判据与探针（以后怎么自查，别再全量训练完才发现）

1. **质心/平均色 baseline**：模型 L1 必须显著优于它才有意义（61→23.4=2.6×；64.9 连 baseline 都不如→直接判死）。
2. **渐进曲线平台**：加键不加信息 = 键冗余或读不出。**但注意**：累加损失下曲线全平是数学必然，不能当判据——要用 m 扫描式探针（固定输入、逐量解锁 token，看 L1 是否单调降）。
3. **逐层线性解码探针**（E1，`trace_info_pixel.py`）：DINO→z_s→h→像素 逐层测，谁掉队修谁（9.8→40.4→64.9 就是它定位的）。**对每个新模型先跑它，30 分钟，零训练成本。**
4. **单步隔离测试的陷阱**：训练好的多步模型里"单步隔离"差异巨大（单25=39.08 vs 单64=60.84）≠ 块信息量不同——那是累加角色分工（主预测器 vs 残差≈0）的伪影。**要测块信息必须独立重训练**（S25=19.15 vs S64=19.58，差 2.2% → 块等价）。
5. **token 使用率 / 梯度分布**：看 z_s 是否全部被用（v5 建议的探针，没跑过）、token 梯度是否头重脚轻。
6. **权重对称性检查**：同查询同掩码、仅"在场/隔离"对比（17.42 vs 39.08）→ 量化混叠通道。

## 9. 未修根因与下一步行动（P0/P1/P2）

### P0 — 停止开新架构，实现 08-27 就写好的修复（全部有据，~1-2 天）

1. **E2：解码器逐 patch 内容查询**：`Q = A_t + query_base + Linear(z_s[k])`（+~1M 参数）。给每行查询注入 patch k 自己的特征 → 读得出逐 patch 内容。预期：曲线从平台变阶梯、L1 在 14.28 基础上再降（历史预期 22.7→≤16；现在起点更低）。
2. **F1：编码器侧绑定**：special k 输入拼 `Linear(patch_feat[k])`，绕开"24 层学路由"。
3. **堵混叠通道（若要渐进语义）**：~~查询自注意力加按步因果 `tgt_mask`~~——**❌ 已实测证伪（2026-09-03，见 §0.5）**：信息未独立时该通道是 step-1 唯一全信息通道，堵死 L1 14.28→19.88 且曲线仍全平。此项只有在 E2 让每块携带独立信息之后才可重试。
4. **修损失结构**：累加损失下曲线全平是数学必然。改为"每步独立预测 + 信息流硬截止"，或接受无渐进（v4 式）。
5. **探针先行**：slice27 模型跑 E1（trace_info_pixel），定位 14.28 距 8.26 的差距在编码侧还是解码侧——避免第 6 次全量训练后才发现没生效。

### P1 — 补对照、量化归因

- v4 `--freeze_dino` 孪生（register+冻结）→ 拆"编码形态 vs DINO 微调"。
- slice27 的 K×窗口解耦扫描（H1：K≈64 更优 vs H2：低索引窗口更优）。
- DINO 微调前后特征相似度/线性可预测性探针 → Phase 2 语义漂移量化。

### P2 — 验收主线（在路由修好之后才有意义）

- K 扫描（K=32/64/128）× 重建质量 = Phase 1 中间验收的正式证据（K 压缩 × 活信息保真）。
- Phase 2 预演：冻结编码器 → MLP → Qwen 小批量文字，直接回答"特征还适不适合 NLP"。
