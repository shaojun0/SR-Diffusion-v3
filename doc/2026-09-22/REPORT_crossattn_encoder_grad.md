# 报告：BPTT 送到编码器的信号（经交叉注意力）到底有多弱？（2026-09-22）

> 问题（用户），原话：「这个 BPTT 的编码信号放到交叉注意力那里会不会太弱了。」
> 探针：`probe_crossattn_encoder_grad.py`（本目录）｜原始结果：`data/probe_crossattn_encoder_grad.json`
> 代码口径：直接用仓库自己的 `model_v2.SRPhase1V2 / OutputQueryDecoder / PixelHead`，
> 只把 DINOv2 换成结构对齐的假编码器（本机 torch 2.8.0+cpu、无 GPU、无 dinov2-large 权重）。

---

## 0. 结论（先读这三行）

1. **方向相反：BPTT 让编码器的信号变强，不是变弱。** 交叉注意力是编码器进解码器的
   **唯一**通道，但 BPTT 把这条通道**变宽**：每个 register token 参与的损失项数
   1 → 9.49（24 步 K=576），实测 `‖∂L/∂z_s‖` **×5.0**、`‖∂L/∂norm‖` 系数 ×5.0。
2. **加进来的路径是相干的，不是噪声**：BPTT 下逐 step 的 `∂L_i/∂z_s` 两两 cos
   均值 **+0.493**（最小 −0.033，几乎无相消）；detach 下逐 step 的梯度**支撑集互不相交**
   （cos 恒 0，`‖Σg‖/Σ‖g‖ = 0.408`）。
3. **真正"弱"的地方不在交叉注意力，而在两处**：① 损失是 `mean_t` 平权 ⇒ 我们真正
   交付的 `F_hat`（末步）只贡献 `1/|T|`（24 步 = 1/24）；② 编码器每参数梯度仍只有
   解码器的 **≈1/3**，且编码器 token 全部共用一个 24 层主干，逐块目标互相干扰。
   ⇒ **"给编码器补信号"不该靠挪到交叉注意力，而该靠损失加权或给 z_s 一条不经
   交叉注意力的直接监督通路。**

---

## 1. 结构事实（为什么问题问得对）

`OutputQueryDecoder.forward`（`model_v2.py:505-520`）：

```
A     = [z_cls; z_s] + pos_embed          # 编码器输出
A_in  = stack_in(A)                       # 只被用作 memory
Y     = stack(stack_in(Y), A_in[:, lo:hi+1])   # ← 交叉注意力的 K/V
```

- **编码器输出只经交叉注意力进解码器**：`A_in` 的唯一去处是 `nn.TransformerDecoder`
  的 `memory`；解码器的自注意力只在 N 行查询之间做。`z_s` 要影响输出，**必须**过
  交叉注意力的 `softmax` + `V` 投影。
- **`z_cls` 只被 step 1 读到**（`lo = 0 if i == 0 else ...`）。
- **读窗口是互不重叠的平方块**（块 k = `[k², (k+1)²−1]`）⇒ detach 下每个 register
  位置只被"读它的那一步"更新。
- **每一步的损失都被 `1/|T|` 平权**（`loss = per_step.mean()`），而 `F_hat` 取末步。

扇出（每个 register token 平均参与的损失项数；公式与
`doc/2026-09-16/ANALYSIS_v2_bptt_cpu_verify.md` §2.4 一致）：

| 操作点 | \|T\| | K | 末步窗口 | 扇出 detach→BPTT | 每键有效监督 `扇出/|T|` |
|---|---:|---:|---:|---:|---:|
| slice[0:5] | 5 | 35 | 11 | 1 → **2.50** | 0.200 → 0.500 |
| 本探针 | 8 | 64 | 1 | 1 → **4.12** | 0.125 → 0.515 |
| 224×126 d4（在跑） | 12 | 144 | 1 | 1 → **5.48** | 0.083 → 0.456 |
| **全量（当前主线）** | **24** | **576** | **1** | 1 → **9.49** | **0.042 → 0.395** |

⇒ BPTT 对编码器是 **×9.5 的通道加宽**；但 `1/|T|` 平权把它压回 **≈0.40**（相对
"单步全读"口径）。**两个因子近似对消：编码器拿到的有效监督不随 |T| 增长而消失，
只是停在一个 0.4 左右的平台。**

## 2. 测量（N=K=64、8 步、D=64、编码器 2 层假 DINO；同一 warm start 只差 `carry_detach`）

操作点：先在 **16 张图上过拟合 500 步**（`fit L1 = 0.536`，平凡解 0.812）。
这一步是必须的——`query_base` 是全局共享参数、不能逐图记忆，要压低这 16 张
的损失，图像信息**只能**从 `z_s/z_cls` 经交叉注意力进来 ⇒ 保证测到的
`∂L/∂z_s` 不是"解码器忽略 memory"的退化零点。
（首版用大训练集 warm start 300 步停在平凡解 0.81，已弃用，与
`doc/2026-09-16/ANALYSIS_v2_bptt_cpu_verify.md` §4 记录的第一版 toy 失败同因。）

### 2.1 总量（测量点 = 过拟合过的那 16 张里的 8 张）

| 量 | **detach** | **BPTT** | 相对 |
|---|---:|---:|---:|
| `‖∂L/∂z_s‖`（编码器读出） | 0.0123 | **0.0611** | **×5.0** |
| `‖∂L/∂z_cls‖` | 0.0023 | 0.0371 | ×16.1 |
| `‖∂L/∂query_base‖` | 0.0152 | 0.2315 | ×15.2 |
| 编码器参数 RMS | 1.40e-3 | 6.96e-3 | ×5.0 |
| 解码器参数 RMS | 4.05e-3 | 1.81e-2 | ×4.5 |
| **编码器/解码器（RMS 比）** | **0.345** | **0.384** | +11% |
| PixeHead 参数 RMS | 3.38e-3 | 3.38e-3 | 不变 |

> PixelHead 的梯度两臂**逐位相同**（i=0 那一行三列也逐位相同）——这是免费拿到的
> **前向不变性自检**：`detach` 只切反传，前向数值两臂逐位一致，因此上表所有差异
> **纯粹来自反向路径**。（与 `model_v2.py:524` 的注释一致。）

逐 step 相干性（`g_i = ∂L_i/∂z_s`，flatten）：

| | detach | BPTT |
|---|---:|---:|
| `‖Σ g_i‖ / Σ‖g_i‖` | 0.408 | **0.862** |
| 两两 cos 均值 / 最小 / 最大 | 0.000 / 0.000 / 0.000 | **+0.493 / −0.033 / +0.959** |

> detach 的 0.000 不是巧合：读窗口互不重叠 ⇒ 各步梯度**支撑集不相交**，
> 恒正交。BPTT 之后 9.5× 条路径落在**同一批**位置上，cos 均值 +0.49
> ⇒ 它们是**冗余叠加**（相干），不是互相抵消的噪声。

### 2.2 逐 step 信号（左 detach / 右 BPTT）

| i | t | `L_i` | `‖∂L_i/∂z_s‖` detach → BPTT | `‖∂L_i/∂z_cls‖` | `‖∂L_i/∂query_base‖` |
|---:|---:|---:|---:|---:|---:|
| 0 | 1 | 0.594 | 0.0104 → 0.0104 | 0.0188 → 0.0188 | 0.1216 → 0.1216 |
| 1 | 4 | 0.811 | 0.0216 → 0.0273 | 0 → 0.0233 | 0 → 0.1487 |
| 2 | 9 | 1.090 | 0.0283 → 0.0460 | 0 → 0.0315 | 0 → 0.2221 |
| 3 | 16 | 1.471 | 0.0309 → 0.0636 | 0 → 0.0401 | 0 → 0.2659 |
| 4 | 25 | 1.905 | 0.0195 → 0.0824 | 0 → 0.0457 | 0 → 0.3031 |
| 5 | 36 | 2.349 | 0.0190 → 0.0927 | 0 → 0.0492 | 0 → 0.3250 |
| 6 | 49 | 2.761 | 0.0409 → 0.1105 | 0 → 0.0568 | 0 → 0.3564 |
| 7 | 64 | 3.230 | 0.0701 → 0.1347 | 0 → 0.0596 | 0 → 0.3857 |

三条可直接引用的事实：

1. **step 0（i=0）两臂逐位相同** ⇒ BPTT 的全部效应都落在 i≥1，符合结构预期。
2. **detach 下 `∂L_i/∂query_base = 0`、`∂L_i/∂z_cls = 0`（i≥1）**：独立复现了
   `ANALYSIS_v2_bptt_cpu_verify.md` 的行为层断言（`query_base` 只被读窗口最小的
   那一步塑造）。BPTT 把这两项从**结构性 0** 变成非零。
3. **BPTT 下 `‖∂L_i/∂z_s‖` 随步号单调上升**（0.0104 → 0.1347，×13）：越靠后的
   损失对编码器的控制越强——但**权重仍是 `1/|T|`**（见下）。

### 2.3 稀释：越靠后的步越重要，却和前面的步等权

| 损失口径 | detach `‖∂L/∂z_s‖` | BPTT `‖∂L/∂z_s‖` |
|---|---:|---:|
| 仅 step 0（单步单损失） | 0.0104 | 0.0104 |
| **仅末步**（= `F_hat` 那一步） | 0.0701 | 0.1347 |
| `mean_t`（训练实际口径） | 0.0123 | 0.0611 |

⇒ 用 `mean_t` 而不是 "末步 + BPTT"，编码器信号从 0.1347 掉到 0.0611（**−55%**）。
24 步配置下这个因子更大：末步只占 `1/24 ≈ 4%` 的梯度质量。

## 3. 诚实的边界（不能说 / 待验证）

1. **假编码器**：本机无 dinov2-large、无 GPU；编码器是结构对齐的 2 层假 DINO。
   **绝对数值不可外推**到真实 run；可外推的是**结构比值**（扇出 ×4.12、逐 step 相干性、
   enc/dec RMS 比、`∂L_i/∂query_base` 的 0/非 0）——这些由 `model_v2.py` 的
   读窗口/carry/损失口径决定，与编码器规模无关。
2. **测量点在"16 张过拟合"上，不是收敛点**：目的是让解码器真的依赖 memory，
   不代表真实训练后期的梯度几何（后期注意力更尖 ⇒ 交叉注意力的门控更强）。
3. **未测 `∂L/∂z_s` 到 DINO 各层的衰减**：本探针只测到编码器**输出**与编码器
   **参数**的总量；没有做"梯度在 24 层里怎么衰减"的逐层剖分。
4. **未在真实 checkpoint 上验证**：真实数值应在服务器上、用
   `doc/2026-09-16/bptt24_bptt_infer_test.json` 对应的权重跑一次同样的逐 step 反传
   （见 §5 的一行改法）。**本报告不声称真实 run 的 `‖∂L/∂z_s‖` 就是这些数。**
5. **单 seed、单测量点、8 步**；真实主线是 24 步 / K=576。

## 4. 若要"给编码器更强的信号"，按性价比排序

| | 做法 | 评价 |
|---|---|---|
| ❌ | 把 carry/编码信号再挪进交叉注意力（加一层 memory 或改 query） | 交叉注意力**已经是**唯一通道且 BPTT 已把它加宽 ×9.5；再塞一层只是再加一个 softmax 门控，不解决 §0 的两个真问题 |
| ✅ | **损失加权倾向末步**（`per_step` 加权，或对末步额外加权） | 一行改动；直接补上 `F_hat` 只占 1/|T| 的短板。**代价**：嵌套 RD 曲线（早停主线 C2a）靠"每步都可用"，权重要小心，别把前几步压坏 |
| ✅ | **给 `z_s` 一条不经交叉注意力的辅助监督**（如 pooled `z_s` → 小重建头） | 编码器拿到独立于"解码器是否愿意看图"的梯度；直击 detach 臂"曲线平、首末步跨图相关 0.9994 ⇒ memory 被忽略"的病 |
| ✅ | **先量"解码器是否在用 memory"**（`tools/diag_attribution.py` 的 z_s 置零/打乱敏感性） | 零训练成本。如果 detach 模型对 z_s 置零无反应，那么**再大的梯度也没用**——这比量梯度大小更根本 |
| ⚠️ | 把 `A_in` 同时接进解码器自注意力（prefix 式） | 去掉 softmax-V 瓶颈，但改架构、动口径，且与已归档结果不可比 |

> 与本仓已有结论的关系：`doc/2026-09-16/ANALYSIS_v2_bptt_cpu_verify.md` §3 用
> **冻结编码器**那一刀证明"carry 变精修算子"这条机制**成立在解码器侧**；
> 本报告补的是同一机制**编码器侧**的量化：BPTT 把编码器通道加宽 ×5（探针）/×9.5（扇出），
> 加宽后路径相干 —— 所以"BPTT 送给编码器的信号太弱"**不成立**。

## 5. 复现

```bash
cd SR-Diffusion-v3
python3 doc/2026-09-22/probe_crossattn_encoder_grad.py \
    --grid 8 --dim 64 --heads 8 --enc-layers 2 --dec-depth 2 \
    --warm 500 --fit-n 16 --fit-batch 8 --phaseb 300
# -> doc/2026-09-22/data/probe_crossattn_encoder_grad.json
```

在**真实 checkpoint** 上取同一组数（服务器，约 25 次反传）：

```python
z_cls, z_s = model.encode(x); z_s.retain_grad()
Y = model.decode(z_cls, z_s, x)["Y_pix"]
per = F.l1_loss(Y, tgt.unsqueeze(1).expand_as(Y), reduction="none").mean((0,2,3))
for i in range(len(model.decoder.steps)):           # 逐 step
    model.zero_grad(set_to_none=True)
    per[i].backward()
    print(i, float(z_s.grad.norm()), float(model.decoder.query_base.grad.norm()))
```
