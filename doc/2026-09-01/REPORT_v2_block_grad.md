# SR-Diffusion v3 — v2 分块掩码 + 梯度按步解耦（grad decouple）训练 + 推理报告

> 日期: 2026-09-01 ｜ 分支: `main` ｜ 服务器: 新租 2× RTX PRO 6000 (97GB), torch 2.12.1+cu130
> 本文档记录用户新提交（490dc08 梯度优化）在 block mask 基础上的训练与推理：数值累加不变，但 Y_cum 梯度按步解耦——每步 Y_t 只从自己那一步的损失收 1 份梯度（平权），消除"t=0 收 |T| 份梯度动力"的三角失衡。

---

## 1. 训练配置

| 项 | 值 |
|---|---|
| 架构 | DINOv2-large(不冻结, dim=1024) → OutputQueryDecoder(nn.TransformerDecoder 2 层, 分块掩码) → PixelHead（register 式, 无 ReEncoder） |
| 分块掩码 | 每采样步 t 只 attend 自己所在的 z_s 块（块号 ⌊√t⌋）；第一个步可见自己块之前所有元素（含位置 0 = z_cls） |
| 集成 | **累加 + 梯度按步解耦（490dc08）**: Y_cum[n] = Σ_{t≤n} Y_t 数值不变（F_hat = Σ_t Y_t），但实现为 `[0, cumsum(Y)[:-1]].detach() + Y`——每步恰收 1 份自己那一步的梯度 |
| 采样切片 | `slice_start=4 / slice_end=9` → [25, 36, 49, 64, 81]（5 步） |
| 数据 | construction_site: 7009 训练 + 3004 测试（448×252, 576 patches） |
| 口径 | fp32、平权 mean、bs16/卡×2、lr=1.5e-4 cosine、40 epochs / 8760 步 |
| 产物 | `output/phase1_v2_block_r2/final_model.pt`（1.36GB fp32） |

## 4. 分析与结论

1. **梯度解耦带来小幅回退**: 全量 L1 18.77 vs 未解耦 block mask 17.46（+1.3），eval_loss 0.3272 vs 0.3045。梯度按步解耦消除了 t=0 的"多份梯度"动力，但同时削弱了早期步对整条累加链的贡献——最终重建精度略降。
2. **收敛更平稳**: eval 曲线 0.4701 → 0.3272 单调、无波动，与未解耦版（0.4783 → 0.3045）同形状但整体高 ~0.02。train_loss 0.4408 也略高于未解耦版（0.4374）。
3. **渐进曲线仍全平**: 5 步 18.74–18.77，分块信息在第一步即充分——解耦不影响"信息已足够"的结论。
4. **结论**: 梯度解耦作为训练动力再平衡手段效果符合预期（每步平权），但以当前口径（fp32, lr=1.5e-4, 40 epochs）最终精度略降。若目标是最低 L1，未解耦版更优；若目标是稳定的分步学习信号，解耦版更"干净"。可尝试调大 lr 或增加 epochs 补偿解耦后的梯度总量。
