## 0. 结论速览（TL;DR）

1. **L1 数字一直在降（23.41 → 17.46 → 8.26），但 v2 的核心机制——"token 渐进解锁、每个 token 补一层信息"——从未在任何版本中生效。** "几乎全败"的准确含义是**机制目标未达成**，不是 L1 未下降。
2. **三种独立测量交叉证实同一失败模式——渐进曲线全平，信息堆在 z_cls + 前几个 token，后续 token 无增量信息**：
   - v2 KV 因果: t=1（2 键）L1=22.93 vs t=576（577 键）22.72——加 575 键只回收 0.21/12.9 ≈ 1.6% [数据]；
   - v2 分块掩码: 5 步累积 L1 全平（17.41–17.46）[数据]；
   - v5 m 扫描（最干净判据: 固定噪声/固定 ε/逐量解锁）: m=0→128 L1 变化 Δ<0.001 [数据]。
3. **根因链**（详见 §4）:
   - ① 训练目标（累加 + 逐步均值）让"信息前置"成为数学最优解——渐进曲线全平是损失结构强制的，不是有效判据；09-01 梯度解耦实验反向证实（解耦后 L1 17.46→18.77 变差）；
   - ② z_s token 无分工压力（DIAGNOSIS F1/F2 未修）: special 无 patch 内容输入、全 attend 全 patch → 冗余全局摘要；
   - ③ 解码器读不出逐 patch 内容（F3/F4 未修）: 查询 = 全局状态 + 固定模板，输出 = 共享键凸组合；**DIAGNOSIS P1-1/E2 的一行修复（逐 patch 内容查询）在 6 个版本中无一实现**（grep 证实）；
   - ④ 验证判据缺失/失效: E1 探针（trace_info_pixel）与 v5 token 使用率探针提出后从未跑过——同样的结论被全量训练后重复发现 5 次；
   - ⑤ 策略性失败: 每次失败后换架构（register→v3→v4→v5→D-AR）而非修根因；v4 的 8.26 是"微调 DINO"的联合效应（缺对照），且带 Phase 2 语义漂移风险，不是已验证的胜利。
4. **一句话**: 08-27 就已诊断出主因和最小修复（E2），之后 6 个版本全部绕开它——失败不是"没找到原因"，是"找到原因后没修"。

## 1. 背景: v2 目标与"失败"的定义

- 项目权威目标（`GOAL_compression_for_nlp.md`）: 通过 token 压缩训练编码器的联想能力（图像信息压进少量 special token z_s），训练后冻结编码器接入 Qwen 做 Phase 2 NLP 解码。像素重建是训练脚手架 + 信息保持探针，Phase 1 中间验收 = **K 压缩 × 重建质量**。
- v2 架构（`model_v2.py`）: DINOv2-large(不冻结) → specials（register 或 ReEncoder）→ OutputQueryDecoder（采样时刻输出全部 patch 预测）→ PixelHead → 像素 L1。
- v2 的灵魂设计: **渐进前缀**——采样时刻对应 z_s 前缀（平方数/分块），期望"前缀越长重建越精"（联想能力: 少 token 也能还原，更多 token 补更多细节）。
- **"失败"的定义**: 上述渐进机制（token 增量性）从未在任何版本中成立——渐进曲线全平（v2 系列）或 m 扫描无增量（v5）。L1 的绝对值下降（v4 8.26）不代表机制成功: v4 无时序结构，且其增益归因存疑（§4.5）。

## 3. 失败模式: 渐进曲线全平（三种独立测量）

| 测量 | 版本 | 数值 | 结论 |
|---|---|---|---|
| 前缀长度扫描 | v2 KV 因果（08-27） | t=1: 22.93 / t=576: 22.72，极差 0.21 | 键里没有（或读不出）逐 patch 信息 |
| 累积步数扫描 | v2 block（09-01） | 5 步 17.41–17.46 全平 | 第一步信息已充分 |
| m 解锁扫描 | v5（08-31） | m=0→128 Δ<0.001 | token 增量性未出现，信息在 z_cls+首 token |

三者指向同一事实: **无论掩码怎么改（KV 因果 / 分块 / 扩散解锁），z_s 后续 token 都不携带增量信息。** v5 的 m 扫描是最干净的判据（固定输入、只变 token 解锁量，无损失结构干扰），其失败即机制失败的最终证据。

## 4. 根因分析

### 4.1 训练目标让"信息前置"成为数学最优解（最根本）

- **累加版损失** `L = mean_n L1(cumsum_n Y, target)`（09-01 block 版）: 模型把信息全塞进第一个步的 Y₁、后续 Y_t≈0，则所有累加结果都≈Y₁——曲线天然全平且损失最低。**这是损失函数驱动的最优策略，不是模型缺陷。**
- **实证（09-01 梯度解耦）** [数据]: 去掉"t=0 收 |T| 份梯度"的三角失衡后，L1 反而 17.46→18.77 变差（`REPORT_v2_block_grad.md`）。若 z_s 有可分摊的增量信息，解耦后模型应能分散信息而不损失精度；变差恰恰证明**信息根本不在后面那些 token 里**。
- **推论**: 累加损失下"渐进曲线全平"不是有效的机制判据；有效判据 = m 扫描式探针（固定输入、逐量解锁 token 看 L1 是否单调降）。

### 4.2 z_s token 无分工压力（F1/F2 未修）

- **F1** [代码] `SpecialTokenBank`: special k 输入 = 共享向量 + 位置编码，**不含 patch k 内容**——z_s[k] 想携带 patch k 信息只能靠注意力从 576 patch 中硬学路由（4 层网络在 1153 长序列上的难题）；
- **F2** [代码] specials 行看全部 patches（全局/全双向）→ 所有 z_s 收敛为"位置标签化的全局摘要"，彼此冗余；register 模式（v4）让 24 层 DINO 直接算 z_s，但**没有任何机制强制分工**（v4 z_s within-std 0.27 = "紧凑分工"或"冗余升高"两可，token 级分析从未做）;
- **v5 解锁约束被绕过** [推断]: `unlock` 只限制 token 何时可见，不限制是否使用——交叉注意力权重可≈0 直接忽略新解锁 token（v5 报告 §4 建议的"token 使用率探针"未跑）。

### 4.3 解码器读不出逐 patch 内容（F3/F4，E2 修复从未实现）

- **F3** [代码] 查询 = `A_t`（全局采样状态）+ `query_base[k]`（**跨图不变的固定模板**，`model_v2.py:507`）——patch k 的查询身份只来自固定模板；
- **F4** [代码] 输出 = 对共享键的凸组合 + 共享 FFN——每个 patch 的输出活在"577 键张成的流形"里，无法独立表达逐 patch 高频。
- **E2 修复从未实现** [代码，grep 全量]: DIAGNOSIS P1-1 `Q = W_q(A_t) + query_base + Linear(z_s[k])`（约 +1M 参数，预期 L1 22.7→≤16、平台消失）在 08-28 HANDOFF 列为"下一步第一优先"，但之后 6 个版本全部绕开——v3 QFormer 是固定 query 模板（`q = query_base.expand(...)`），v4 沿用 v2 解码器，v5 交叉注意力是 ctx 平均聚合。

### 4.4 验证判据缺失/失效——全量训练后才发现机制没生效（重复 5 次）

- **E1 探针**（`trace_info_pixel.py`: z_s / F_hat 线性解码 L1，30 分钟定位信息丢在哪层，DIAGNOSIS §5 P0）: 提出后从未在新模型上跑过；
- **v5 token 使用率探针**（交叉注意力权重统计）: 提出但未跑；
- 结果: 同样的"渐进曲线全平"结论在 08-27、08-28、08-31、09-01×3 被全量训练（每轮 3h+）后重复发现——每次都在验证前先押上全量训练成本。

### 4.5 策略性失败: 换架构不修根因；v4 的"成功"是假象

- register 被证实"编码侧修复不动解码瓶颈"后（08-28），没有回头修解码器而是开了 v3；
- **v4 8.26 的归因问题**（`ANALYSIS_v4_deep.md` 逐条拆穿）:
  - "突破 9.8"是旧模型**样本内线性上限** vs 新模型**端到端 held-out** 的口径混比，不可直接对比；
  - 四格矩阵（编码形态 × DINO 可训性）只占两格: 8.26 是"register + 微调 DINO"的**联合效应**，现有证据支持"增益主要来自 DINO 微调"（register+冻结孪生 `--freeze_dino` 一键可跑，未跑）；
  - **DINO 微调语义漂移是 Phase 2 直接风险**: 7k 张同分布工地图微调 304M 预训练模型，GOAL §4.2 预警的"像素化扭曲被永久固化"——8.26 对项目目标（冻结编码器做 NLP）不是已验证的胜利。
- **D-AR 微调**（09-01）: 外部模型，与 v2 架构无关，验证不了本项目。

## 5. 下一步建议（按优先级）

1. **P0｜停止开新架构，实现 08-27 就写好的修复**:
   - 解码器逐 patch 内容查询（`Q = A_t + query_base + Linear(z_s[k])`，约 +1M 参数，DIAGNOSIS E2）;
   - 编码器侧 special k 注入 `Linear(patch_feat[k])`（修 F1，绕开"4 层学 576 路路由"难题）。
2. **P0｜先跑探针再训练**（~30 分钟，零训练成本）: `trace_info_pixel.py` 定位 z_s/F_hat 信息丢失层级 + 交叉注意力 token 使用率统计——用数据决定先修编码侧还是解码侧，避免第 6 次"全量训练后才发现机制没生效"。
3. **P0｜修损失结构**（否则机制判据无效）: 累加损失下渐进曲线数学上必然全平。改为"每步独立预测 + 信息流硬截止掩码"，或改用 m 扫描式探针（固定输入逐量解锁）作为机制判据。
4. **P1｜补 v4 缺失对照**: `train_v4.py --freeze_dino`（register+冻结）确认 8.26 归因；微调前后 DINO 特征相似度/线性可预测性探针量化 Phase 2 语义漂移风险。
5. **P2｜K 压缩 × 重建质量**（Phase 1 中间验收）: 在修好路由之后做，否则无效。
