- 系列背景: v2 分块掩码 register 式，K=num_specials 与 N 解耦（b653847），K = 最终采样步集的平方块终点。

- 预期动机（外部参考）: v4 的 register K=64 曾达 8.26（架构不同不可直接比），K 压缩到 ~64 区间可能更接近"信息集中"甜点。

## 4. 判读（数据事实 + 标注假设）

1. **采样窗口左移带来 v2 block 系列最大单步改进**（17.46 → 14.28）。同预算、同代码、同 seed 42、同损失结构，唯一变量 = slice [4:9]→[2:7]（K 576/99→63、读窗口 1..99→1..63、steps [25..81]→[9..49]）。
2. **[假设 H1, 待拆] "K/读窗口落 ~64 区间更优"**: 与 v4（register K=64 + 不冻结 DINO, 8.26）的 K 规模呼应；K=576/99（窗口 1..99）都显著更差。若 H1 成立，"去花瓶 + 真压缩到 ~64" 才是 register 式的正确形态，此前的 [4:9] 系实验都停在"读 1..99"上。
3. **[假设 H2, 待拆] "低索引块更优"**: slice [2:7] 的采样块为块 3..7（首步 t=9 前缀只读 0..15），而 [4:9] 为块 5..9（首步前缀 0..35）。低索引 register 更接近 z_cls、在 DINO 输出流中可能携带更"基础/全局"的信息层级。H1 与 H2 在本实验**耦合**（窗口左移同时缩小了 K），无法分离——需要 K×窗口扫描（如 K=63 固定换窗口、或窗口固定换 K）。
4. **曲线全平机制与窗口无关**: slice27 的渐进曲线极差 0.020，与历次一致——"累加损失 + 首步前缀 + 查询混叠 → 第一步一肩扛起"的解释在此窗口下依然成立；E2（逐 patch 内容查询）仍是让"每步增量"出现的主修复。
5. **未跑单49**（判据: L1 ≤ 17.46 则不跑）。用户后续如需诊断单步角色/验证 H1，可用 steps=[49]（自动 K=63）单步训练对照 REPORT_v2_single_step_retrain 的 S64 式消融。

## 5. 建议的后续实验

1. **K×窗口解耦扫描**（H1 vs H2 裁决）: 固定读窗口内容（如都覆盖块 3..7 的 1..63），在 K=63 与花瓶式 K=576 下对比（K=576 时解码器实际仍只读 1..63，即"花瓶挡在窗口外"）→ 分离"K 总量"与"窗口位置"的贡献。
2. **单步 K 解耦消融**（DESIGN §6.1 未完成支线）: steps=[49]（K=63）等单步重训练，对照旧花瓶式 S25/S64（19.15/19.58）。
3. **v4 对照**: v4 的 8.26 与本次 14.28 同为 ~64 register 规模，架构差异（v4 方案 vs OutputQueryDecoder）与 DINO 微调贡献仍待拆（ANALYSIS_v4_deep.md 未闭合）。
4. 曲线全平主线不变: 损失结构改造 + E2。
