## 3. 口径校准与反转裁决

**控制点**:k35c 与历史 K=35 锚点在**同 K、同 slice [0:5]、同代码/超参/步数**下只差"单卡 bs32 vs 2 卡 DDP bs16×2",
故其差是单卡↔DDP 口径差**唯一的同条件定量估计**(详见 `REPORT_ksweep_k35c.md` §口径校准):

| 口径 | K | 像素 L1 | `full_norm_l1` | 相对差 |
|---|---|---|---|---|
| k35c 单卡 bs32 | 35 | **14.1470** | **0.246021** | 基准 |
| 历史 BPTT 2 卡 DDP bs16×2 | 35 | 18.05 | 0.314064 | DDP 高 **+3.9030 px** |
| detach 时代 blockdiag | 35 | 19.02 | — | 高 **+4.8730 px** |

- **加性 offset = +3.9030 px**,以 DDP 为基准 **21.62%**(以单卡为基准 +27.59%);等价 单卡 = DDP × **0.7838**,
  DDP/单卡 = **1.2759**。
- **归一化口径独立复核**:`full_norm_l1` 差 0.068043,相对 DDP **21.67%** —— 与像素口径的 21.62% 高度一致
  (两个独立度量给出同一相对口径差,不是单一口径伪影)。
- **形态**:DDP K=35 的 per-step 为 18.27 → 18.05(落差 0.22 px,≈1.2%),k35c 为 14.3941 → 14.1470(落差 0.2471 px,
  1.717%);**绝对落差几乎相同**,而绝对水平差 3.90 px ⇒ 口径差基本是**近乎恒定的整体位移**,不是精炼动力学改变。

**反转裁决(单卡 K=99/K=120 是否真击败 DDP K=576 = 16.42 px):**

| 单卡点 | 像素 L1 | raw 优于 K=576 | 加性校准(+3.9030) | 乘性校准(×1.2759) |
|---|---|---|---|---|
| K=99 | 12.88 | −3.54 px(−21.6%) | 16.7830 ⇒ **DDP 反优 0.3630 px(2.16%)** | 16.4334 ⇒ DDP 反优 0.0134 px(0.08%,实质持平) |
| K=120 | 12.51 | −3.91 px(−23.8%) | 16.4130 ⇒ 单卡仍优 0.0070 px(0.04%,实质持平) | 15.9614 ⇒ 单卡优 0.4586 px(2.87%) |

**结论:该 offset 基本可以完全解释这一"反转"。** 单卡 K=99/K=120 的 raw 领先幅度(3.54 / 3.91 px)与同 K 同 slice
实测的口径差(3.9030 px / 21.62%)在数值上几乎相等;加性校准后 K=99 反被 DDP K=576 超过 2.16%、K=120 与 K=576
实质打平(0.04%);乘性校准后 K=99 打平、K=120 仅微弱领先 2.87%。**两种校准口径下,"单卡压缩档明显击败 DDP
全量 K=576"都不再成立——它落在校准误差带内,不能采信为真实的 K 缩放效应。** 同理 K=48(13.1483)/K=63(14.0587)
在校准后也都劣于 DDP K=576(分别 +0.63 / +1.54 px,按加性)。

**局限(须随结论一起引用)**:offset 只在 K=35 的 **1 个**控制点上测得,"offset 与 K 无关"是**假设而非实测**;
K=99/120/576 处的真实 offset 未知;该 offset 还把"单卡 vs DDP"与两个 K=35 run 间任何其它差异(n=1 无法分离)
混在一起。尽管如此,21.6% 远大于通常 seed 级波动,且大小/方向恰好与反转缺口一致,**最简约解释仍是口径差**。

## 4. 异常点 K=63

**量化:**

- K=63 像素 L1 = **14.0587 ± 5.2055**(norm 0.244483),比 K=48(13.1483)**差 +0.9104 px(+6.9%**,
  以 K=63 为基 +6.5%);相对 K=35(14.1470)只**好 0.0883 px(0.63%)** —— 即 K=63 实质与 K=35 同档。
- 落差占比 **1.143%** 是 K≥35 各档中最弱的一个(对比 K=35 1.717% / K=48 7.89% / K=99 6.75% / K=120 9.68%);
  其"后步几乎不精炼"被推到了当前最极端:step1(14.2213)与 K=48(14.2742)几乎相同甚至略好 0.053 px,
  但 K=48 靠迭代精炼拿回 1.13 px,K=63 只拿回 0.16 px。
- **绝对质量在 K 轴上并非严格单调**:单卡序列 `15.02 → 15.01 → 14.15 → 13.15 → [14.06] → 12.88 → 12.51`,
  除 K=63 外单调改善;K=48→K=63→K=99(13.1483 → 14.0587 → 12.8812)是唯一折返区段。
- 训练期 `eval_recon` 显示 K=63 在 **2190 步就已最差**(0.4312 vs K=48 0.3739,领先落后 +0.0573),此后收敛到
  约 +0.0155 并保持 ⇒ **差距不是后期才出现,也不是评测噪声造成的伪影**;三个独立口径(`full_norm_l1` / 像素 L1 /
  `eval_recon`)给出一致结论。

**判断与建议(不下定论):** `K = (√max_t + 1)² − 1` 把 K 与步集硬绑定,49 这一步使 K=63 的"特殊 token 容量/步数配比"
改变;可能解释包括单次运行优化方差、步集-K 耦合、早期训练轨迹差异。**现有数据不足以区分。**
**建议:对 K=63 追加不同 seed(或重跑)以排除 run variance(n=1 per point);在确认前不把 K≈64 作为工作点。**

## 6. Phase-1 中间验收判定

依据 `doc/2026-08-28/GOAL_compression_for_nlp.md` §2:**Phase-1 中间验收 = K 压缩 × 重建质量**
(K=32/64/128 下"活信息"保真;重建是信息保持的直接探针,决定 Phase-2 NLP 天花板)。对应本 sweep 的三个工作点:

| 目标工作点 | 实测点 | 像素 L1 / norm | 判定 | 理由 |
|---|---|---|---|---|
| K≈32 | K=35c | 14.1470 / 0.246021 | **可用(满足下限)** | 三个口径都远优于 detach 基线 19.02;K=24→35→48 严格单调,32 在爬坡段而非平台 |
| K≈64 | K=63 | 14.0587 / 0.244483 | **存疑,暂不满足** | 非单调离群:不如更小的 K=48(+6.9%)、仅≈K=35;**须重跑/补 seed** |
| K≈128 | K=120 | 12.5095 / 0.217494 | **满足,且为单卡最优** | 三个口径一致最佳;落差占比首次达两位数 |

**补充裁决(口径校准后):** 同口径内 K=120/K=99/K=48 优于 K=35、K=35 优于 K=24/K=15 成立;但"单卡 K=99/K=120
<b>击败</b> DDP K=576"**不成立**(§3)。因此可确定性表述的是:**在单卡口径内,把 K 压到 120 相对零压缩 K=576
在校准误差带内不损失可测质量(实质打平),即约 4.8× 压缩是可接受的**;不能表述为"压缩后更好"。

**推荐 Phase-1 工作点:**

- **主推 K=120(slice [0:10],≈目标 K=128):** 理由——(a) 全 sweep 绝对重建质量最好(12.5095 px / 0.217494,
  三个口径一致);(b) 不落在任何非单调区段,是"干净"的上端点;(c) 校准后与 DDP K=576 实质打平 ⇒
  以 **4.8× 压缩换取零可测质量损失**,直接服务"少 token 编码最多信息"的验收目标与 Phase-2 context 节省。
- **备选 K=48(slice [0:6]):** 若 Phase-2 上下文预算优先——它是效率拐点(K=24→48 已拿到主要增益),相对 K=120
  仅差 0.6388 px(以 K=120 为基 +5.1% / 以 K=48 为基 −4.9%),但解码步数减半。
- **不推荐 K=63:** 在非单调异常澄清前不得作为 ≈K=64 工作点。

## 7. 诚实的边界

1. **n=1 per point、仅 seed42**:8 个 K 点各只跑一次,无误差棒;K=63 的非单调与各档间的细微排序无法用重复性验证。
2. **口径混杂**:7 个单卡点(bs32)与 2 个 DDP 锚点(bs16×2)、1 个 detach 时代基线(并行 + 累加损失)不是同一口径;
   只有 K=35 有同条件单卡对照(k35c),**其余 K 的 offset 未被测量**,校准本身带"offset 与 K 无关"的假设。
3. **无同口径 K=576 单卡点**:K=576 只有 DDP 锚点,因此"压缩档 vs 零压缩"的最终裁决仍缺一个单卡全量点。
4. **K=63 原因未解释**:优化方差 / 步集-K 耦合 / 早期轨迹差异三者无法用现有数据区分。
5. **末步回吐、K=24 首步非单调等形态**:幅度均小于各档 `step_pixel_std_255`,严格记录但不宜过度解读。
6. `infer_test.json` 不含 per-step 归一化空间 L1,故 §2 的 per-step 只在 0–255 空间;`full_norm_l1` 只有总量。
7. 跨代不可比:K=576/detach 锚点与本次 run 的损失口径/并行架构不同,"旧 ~19–20 读出上限"不适用于本次口径。
