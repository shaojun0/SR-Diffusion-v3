## 0. 结论先行

1. **目标句里已经有这个需求了**（README §1 的"动态调整 token 数量"），但仓库目前没有任何一条"边际收益曲线"来支撑它——我们不知道第 100 个 register 相对第 10 个到底值多少。
2. **K 和 T 是两件不同的事，收益完全不同**，必须先拆开（§2）：
   - 自适应 **K（token 数）** = **信息分配**问题，收益在**压缩率/NLP 质量**，**不在算力**（因为 DINO 是双向编码，改 K 必须整条重编码，省不下来）；
   - 自适应 **T（步数）** = **计算分配**问题，收益**直接是算力**（5 步 1h32m vs 24 步 4h35m），并且**顺带解决"零增量自锁"**。
3. **用监督学习，不用 RL**（§3）。Phase-1 的重建 L1 是一个连续、便宜、可复现的信号；RL 的价值在于信号稀疏/不可验时，这里不成立。
4. **Step 1 不需要重训、不需要改代码**：拿现有 K=576/BPTT 权重，在推理时**掩掉高序号 register**，直接画出 `full_norm_l1 vs K'` 曲线（§4）。这一条实验就能决定后面所有投入。
5. **T 的边际曲线其实已经有了**（`RESULTS_v2_bptt.md` 的 24 步逐步曲线 19.10 → 16.38），只是没被当成决策依据用（§5）。

## 1. 问题：K 和 T 现在都是"配置"，不是"测出来的量"

当前状态：

| 量 | 现在怎么定 | 问题 |
|---|---|---|
| `K`（register/specials 数）| `K = min(max_t((⌊√t⌋+1)²−1), N)`，由**最终采样步集**推导（`model_v2.py:164`）| K 是步集的**函数**，不是信息量的函数。README §1 要的是后者 |
| `T`（循环步数）| 由 `--slice_start/--slice_end` 指定，训练时**固定跑满** | 已知"后步仍未分工"（跨代 −5.3%，但逐步仅 1.3%），却仍然每步都算 |

两条已知事实（`RESULTS_v2_bptt.md`）：
- BPTT 打开后 24 步逐步曲线**首次由"平"转"降"**（19.10 → 16.38），但**后段步的增量依然很小**；
- 训练耗时的**主要杠杆是步数**：24 步 4h35m vs 5 步 1h32m。

→ 所以"每张图都跑满 24 步 + 固定 576 个 register"这个配置，**在算力和信息两个维度上都没有被论证过是最优的**。

## 2. 必须先分清：自适应 K ≠ 自适应 T

这是本提案最重要的一条，混淆这两者会导致错误的目标函数。

### 2.1 自适应 K（token 数）= 信息分配

- **能省算力吗？——基本不能。** 本项目 specials 是 **prepend** 进 DINOv2 的 `[cls; specials(K); patches(N)]`，且 DINO 是**双向**编码器。改 K ⇒ 序列长度变 ⇒ **全部 patch 的隐状态都变** ⇒ 必须整条重编码。没有 causal-LLM 那种"缓存 prompt KV、只重算 latent 块"的便宜可占。
  > 注：在因果 LLM 的 latent-CoT 里，"把 latent 块放 prompt 之后"能省 60 倍以上重算；**本项目不适用**（双向 + prepend）。不要照搬。
- **真正的收益是 README §1 说的那个**：信息量大的图多给几个 z_s，信息量小的少给几个 ⇒ **同等压缩率下 NLP 质量更高**，或**同质量下压缩率更高**。这是**率失真 / 信息分配**问题。
- 度量应该是 **Phase-2 的文本质量**（最终验收），Phase-1 重建 L1 只是**代理探针**（README 已明确这一点）。

### 2.2 自适应 T（步数）= 计算分配

- **直接省算力**：平均步数从 24 降到 ~6，训练/推理时间近似线性下降（5 步已是 1h32m vs 4h35m）。
- **顺带解决一个已记录的结构性缺陷**：现在每步都被监督成"直接预测整图"，导致后步的 L1 最优解 = 输出 0 ⇒ **零增量自锁**（`doc/2026-09-07/ANALYSIS_k3_why_later_steps_zero.md`）。**"允许提前停"把这个自锁从 bug 变成信号**：后步没有增量，就让模型停下来，而不是逼它输出一个 0。
- 度量是**逐步 L1 的边际增量** `Δ_t = L1(t) − L1(t+1)`。

**建议的目标函数拆分：**

| | 自适应 K | 自适应 T |
|---|---|---|
| 优化目标 | `min 平均K` s.t. `Phase-2 质量 ≥ 阈值` | `min 平均T` s.t. `Phase-1 L1 ≤ 阈值` |
| 决策粒度 | 逐**样本**（图与图之间信息量不同）| 逐**样本**，也可以逐图自适应 |
| 预期收益 | NLP 质量 / 压缩率 | **算力 3–5×** + 破自锁 |
| 优先级 | 中（最终目标，但信号贵）| **高（信号已有，收益确定）** |

## 3. 为什么用"离线扫描 + 监督路由"，而不是 RL

一个自然的想法是：**"结果好就减少 latent，结果差就增加"**，用 RL 学。这条路不推荐，理由具体到本项目：

1. **信号是连续且廉价的**。重建 L1 每步都能算、可复现、方差低。RL 的价值在于奖励稀疏或不可验证时（数学答案对/错），这里不成立——你有一个稠密的回归目标，用监督学习即可，方差低一个量级。
2. **"结果好不好" ≠ "多给一个 token 有没有用"**。后一个才是你要的（边际价值）。一个朴素规则"好就减、差就加"会在**再算也没用的样本**上把资源烧光——这类样本在本项目里就是**严重退化/低信息量的图**，它们无论多少 register 都重建不好。必须用边际信号，不能用绝对结果。
3. **RL 的 rollout 成本是乘法**：`prompt 数 × group size × epoch × 步数`。本项目的编码器又贵又双向，group size 一乘就爆炸。
4. **latent 是确定性的**：同一张图同样 K 跑两遍结果相同 ⇒ GRPO 组内 advantage ≡ 0，除非人为注入随机性。这又要求额外改造（变分/噪声/可变 K）。
5. **成本对照**：本提案的 Step 1+2 在 3004 张 test 上大约 **1–3 GPU·h**；一个能收敛的 RL run 至少高 1–2 个数量级。

> 结论：**监督的边际价值回归** > RL，因为这里的信号是稠密、连续、可复现的。RL 留到"Phase-2 文本质量无法用代理指标预测"时再考虑。

## 4. Step 1（止损判据）：寄存器掩码消融 → K 的边际收益曲线

**目标**：回答"第 k 个 register 值多少"。**不需要重训，不需要改代码。**

**做法**：拿现有 `K=576 / 24 步 / BPTT` 权重，只改 `--num_specials`（`train_v2.py:149`，已有此参数）做成"只用前 K′ 个 register"的推理。

两条可行路径，建议都做（互相校验）：

- **路径 A（干净，需确认读窗口语义）**：`--num_specials K′` 直接重训/重推断，K′ ∈ {35, 64, 128, 192, 288, 384, 576}。
  - ⚠️ **约束**：`--num_specials` 必须 **≥ max 采样步**（`train_v2.py:294` 的提示）。所以**不能**在 24 步全轨迹下把 K 降到 35——想小 K 就必须同时缩步集（`--slice_*`），这样 K 和 T 就**耦合**了。
- **路径 B（零重训，推荐先做）**：保持 K=576 与 24 步不变，在**推理时把高序号 register 置零**（`z_s[:, K′:] = 0`，或用一个 `memory_mask` 挡住），扫 K′。
  - 这直接给出"已有权重下，后段 register 是否真的被用到"的**因果证据**；
  - 与本仓库已有的掩码实验传统一致（`query_mask_mode` / `memory_mask` / region_loss），结论可对比；
  - ⚠️ 注意区分 **置零 vs 掩码**：两者语义不同（一个提供"零内容"，一个从注意力里移除），**必须分别测**，不要混。

**读法与判据**：

```
画 full_norm_l1 (或像素 L1) vs K′，在 3004 张 test 上。
```

| 曲线形状 | 含义 | 决策 |
|---|---|---|
| **有明显拐点**（前段陡降，后段平坦）| 高序号 register 贡献 negligible ⇒ **存在可分配的头寸** | → 做 Step 2/3 |
| **单调缓降，无拐点** | 每个 register 都在贡献 ⇒ 压缩是"平权"的，没有可省的 | → 自适应 K 收益有限，**优先做自适应 T**（§5）|
| **平坦甚至反升** | 存在"花瓶 register"/噪声 register | → 立刻做剪枝 + region_loss 式再分工 |

**成本**：3004 张 test × 7 个 K′ 值 × 一次前向。DINOv2-large(300M) + 轻解码器，**远小于 1 GPU·h**。这批图还能复用 `doc/2026-09-16/data/` 的口径直接和 16.42 对比。

> **这一条就是止损点**：如果曲线是"无拐点的单调缓降"，那么 README §1 的"动态调整 token 数量"在 Phase-1 探针上就**没有头寸**，应该把精力转向自适应 T，或者转向前置的图像级难度预测。

## 5. Step 2 的一半是免费的：T 的边际曲线已经存在

`RESULTS_v2_bptt.md` 里已经有 24 步逐步曲线（19.10 → 16.38）。把它当成**决策依据**用：

1. 算 `Δ_t = L1(t) − L1(t+1)`，画出**边际增量曲线**；
2. 找一个 `ε`（例如"相对总增益的 1%"）定义**饱和点** `T*`；
3. 检查：`T*` 是多少？是图上普遍一致，还是逐图差异很大？
   - **逐图差异大** ⇒ 有自适应空间，值得做逐样本早停；
   - **普遍在很早就饱和** ⇒ 直接把步数砍到 `T*`（比如 6），无需自适应——**这也是收益**，而且立刻拿到。

> 注意：这与"后步仅 1.3%"的结论一致，但要把它量化成**逐图分布**而不是全局平均。全局平均 1.3% 可能掩盖"少数图后步贡献很大"。

## 6. Step 3：把自适应做成可学的（监督路由器）

只有在 Step 1 出现拐点、或 Step 2 显示逐图差异大时才做。

### 6.1 目标与标签

**逐样本预测"需要多少"**：

- **回归式**：预测饱和点 `T*`（步数）或 `K*`（token 数）。标签从 Step 1/2 的扫描直接得到（**这是关键——不需要 RL**）。
- **分类式（更稳）**：桶化成 `{4, 8, 16, 24}` 步，或 `K ∈ {64, 128, 288, 576}`。桶化对批处理友好，且避免回归的标定问题。
- **门控式（对本架构最自然）**：K 固定 K_max，给每个 register 一个门控 `g_i ∈ [0,1]`，训练时加稀疏正则（`E[#active]` 或 L1 on `g`）。**有效 K 自适应，而张量形状不变** ⇒ 不破坏 DDP/批处理，也不需要按 K 分桶。

### 6.2 特征放在哪

- 用**中间层**特征，不要用最后一层。在因果 LLM 上的实测结论是中间层（约 12–17 层 / 28 层）预测推理预算最强（r≈0.74），首尾都掉到 0.6 以下。
- 对本项目：可用 `z_cls` 或 register 聚合后的隐状态作为路由器输入；也可以直接用**图像侧的廉价统计量**（分辨率、纹理复杂度、DINO patch 特征的方差/熵）——后者完全不需要额外前向，最省。
- 路由器规模：2 层 MLP（~256 隐藏单元）足够；**不要**为这个去微调主干。

### 6.3 训练与标定

- 损失：`L = L_recon + α·L_router`（`L_router` = 对 `T*` 的 BCE/MSE 或桶分类 CE）。
- **推理时用阈值扫出曲线**：`τ` 或桶边界在验证集上扫，得到 **L1-vs-平均步数** 曲线。**不改权重就能调部署点**——这是监督路由器相对 RL 的实操优势。
- 若要用约束形式：`min E[T] s.t. L1 ≤ 阈值`，用对偶变量（PID 式）自动调 `α`，**不要手调固定系数**——模型变强后同样的系数会对应不同的步数。

### 6.4 一定要防的两个坑

1. **暴露偏差**：如果训练时总跑满 24 步，路由器只见过"满步状态"；推理早停后状态分布偏移，路由器会过度乐观。**训练时对步数/门控注入随机性**（随机 T、随机 dropout 掉部分 register），让模型见过各种长度的状态。
2. **路由器学成"难度分类器"而不是"边际价值预测器"**：难度高 ≠ 多给就有用（低信息量的图就是"再给也没用"）。标签必须用**边际增益** `Δ`，不能用**绝对 L1**。

## 7. 与"零增量自锁"的关系：自适应是同一个问题的解法

`doc/2026-09-07/ANALYSIS_k3_why_later_steps_zero.md` 的诊断是：每步都被监督成"预测整图"，后步的子任务 = 预测残差，而残差从后步可读的键里不可预测 ⇒ L1 最优 = 0 ⇒ 后步收不到梯度。

自适应停在逻辑上是这个诊断的**自然延伸**，而且比"再加损失项"更干净：

| 方案 | 做法 | 风险 |
|---|---|---|
| region_loss（已试）| 第 t 步只监督自己 region 的 patch 行 | 已实测"机制验证成功但现实现有结构性缺陷"（`doc/2026-09-07/`）|
| 循环 + BPTT（已试，**有效**）| 显式把上一步输出喂给下一步 | 已验证 L1 −30.8% |
| **自适应早停（本提案）** | 允许模型在某一步停下，不强迫后步产出 | 需要学一个停止策略；但**不改变现有损失口径**，可叠加 |

三者**不互斥**：BPTT 提供梯度路径，region_loss 提供分工压力，自适应早停提供"承认无增量"的出口。

## 8. 工程注意（针对本仓库的具体约束）

1. **`--num_specials` 的下界**：必须 `≥ max 采样步`（`train_v2.py:294`）。所以"降 K"只能和"缩步集"一起做 ⇒ **K 与 T 无法完全解耦**。若要用路径 A 做纯 K 消融，需要先加一个"允许 K < max step"的开关（重映射读窗口），**这是一处真实的代码改动**；路径 B（推理掩码）绕开了它，所以**先做 B**。
2. **prepend + 双向 ⇒ 无 KV 缓存红利**。见 §2.1。任何"只重算 latent 部分"的优化在本架构都不成立。
3. **`detach` 与扫描的交互**：当前是 BPTT（`model_v2.py:528` 的 `.detach()` 已去掉）。做 Step 1 的**推理**扫描不受影响；但如果要做"训练时随机步数"，BPTT 下的显存会随最大步数增长（87.2 GB @ 24 步 / batch 32）——随机步数时按最长轨迹分配显存即可。
4. **checkpoint 与 K 的一致性**：`model_info.json` 记录 `num_specials`，推理必须对齐权重形状（README §1）。掩码消融不改变形状，安全；改 `--num_specials` 重训则会产生不兼容权重，注意别混用（仓库已有"静默算错"的先例，见 README §1 的 checkpoint 兼容性更正）。
5. **两步走的口径统一**：Step 1 请固定用同一个 `infer_v2_test.py` + 同一批 3004 张图 + 同一个指标（`full_norm_l1`），以便与 `16.42` 直接对比。

## 9. 风险与反面证据

| 风险 | 说明 | 缓解 |
|---|---|---|
| **K 上没有头寸** | 若 register 贡献是平权的，自适应 K 收益极小 | Step 1 止损判据；转向 T |
| **Phase-1 代理失效** | 重建 L1 好 ≠ Phase-2 文本好（README 已警告"像素重建是脚手架"）| Step 1 的结论**只能**用来筛掉明显没戏的方向，不能用来定最终 K；最终必须 Phase-2 验证 |
| **早停导致欠训练** | 后步本来需要 BPTT 才能学会分工，早停可能让它永远学不会 | **先跑满步 + BPTT 训练**，再引入早停；不要一开始就早停 |
| **掩码消融的解释歧义** | 置零 vs 掩码语义不同，可能得出相反结论 | 两种都测；报告里明确写清用的是哪种 |
| **逐图自适应破坏批处理** | 不同图不同步数会产生 ragged batch | 固定形状 + mask（跑满但冻结已停样本），而不是真变长 |
