## 观察

1. **形态 = 前重后轻的饱和曲线(近似单调,但末端回升)。** 落差高度集中在最前几步:step2 一步吃掉总落差的
   **63.9%**(0.5957/0.9321),前 3 步吃掉 86.5%,前 5 步吃掉 **99.9%**(0.9313/0.9321);
   step6–7 再挤出 0.0195 px 的增益(此时达曲线最低点 12.8625),step8–9 又反向吐回 0.0187 px,
   因此 **step5→step9 的净贡献仅 0.0007 px**。
2. **后步增益确实随 K 增大而恢复,但仍远弱于全量。** 以"step1→last 落差占 step1 的百分比"为口径:
   K=35 ≈ 1.2%（18.27→18.05;至最低点 18.03 约 1.3%)→ **K=99 = 6.75%** →
   K=576 = 14.03%(19.10→16.42;至最低点 16.38 约 14.2%)。即压缩档位下后步并非完全不动,但
   K=99 的后步增益仍只有全量 24 步口径的一半左右,且几乎全部来自第 2–5 步,而不是后段迭代精炼。
3. **增益来源是"少量特殊 token 换取可观的全局初始化",不是逐步精炼。** 首步(块起点 1,几乎无上下文)
   13.81 → 第 5 步(块起点 25)12.88 已经把能拿的都拿到;之后 4 步无实质收益。
   ⇒ 在 K=99 这一档,**增加解码步数的边际价值≈0**,压缩-质量曲线更可能由"特殊 token 数量/容量"而非"迭代步数"决定。
4. **异常/可疑点(严格记录,不下定论):**
   - 末两步(步 8、9)同向回升 +0.0044 / +0.0143 px。幅度远小于 `step_pixel_std_255`(4.79),单看数值可视为噪声;
     但两步同向且 step7 即达最小,形态与 K=576 锚点"末步回升 0.04"类似,值得留意是否为固定现象。
   - **K=99 优于 K=576 锚点 21.6%**(见上节),与 K 单调性的先验冲突,是本次最需要复核的一点。
   - 无 NaN / 发散 / OOM;进程 `TRAIN_RC=0`、`INFER_RC=0`,`k99.done` 已落盘。
5. **缺项说明**:`infer_test.json` 未包含 per-step 归一化空间 L1(只有 `step_pixel_l1_255` / `step_pixel_std_255`),
   故本文 per-step 只报 0–255 空间;`full_norm_l1` 仅有总量。其余请求指标(`num_specials`、`decoder_steps`、`n`、`time_s`)
   均已取得,无缺失。
