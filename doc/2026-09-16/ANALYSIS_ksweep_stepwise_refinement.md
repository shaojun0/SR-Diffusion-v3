> 数据来源:7 份 `output/ksweep_<tag>/infer_test.json` 的 `step_pixel_l1_255`,由 `srdiff_overnight/runtime/step_analysis.py` 在服务器上重算。
> 口径:单卡 bs32,BPTT `bptt@d76f0c5`,全量 3004 test。逐步增量 Δᵢ = L1ᵢ₋₁ − L1ᵢ(**正 = 该步让图像变好**)。

## 结论(一句话)

**有逐步细化,但不是「每步持续干活」**:落差几乎全发生在**前 3–4 个采样步(≥88%)**,增量按 **~3–4 倍几何衰减**,之后 **2–3 步增量转负(过冲回退)**;而且**只有 K≥48 才明显**,K≤35 近乎平,**K=63 是唯一折返**。

## 三个形态事实

1. **增量确实出现且单调递减** —— detach 时代逐步增量 ≈ 0、曲线全平(后步坍缩);BPTT 下去掉 carry 的 `detach` 后,首次出现**连续正增量、且按 ~3–4 倍几何衰减**的序列。所以「后步真干活」这件事**发生了**,但强度集中在前端。
2. **有效细化窗口随 K 后移,但右端始终有过冲**:最小步位置 2→3→4→5→5→7→7;**每个 run 的最后 2–3 步增量都是负的**(k120 末 3 步 −0.0033/−0.0074/−0.0111,k99 末 2 步 −0.0044/−0.0143)。即「有效细化步数」实测约 4–6 步,再多就是回退。
3. **规模阈值**:总落差 K35 1.78% → K48 7.98% → K99 6.88% → K120 9.84% → K576 14.0%(跨口径)。**K≤35 近乎平(≤1.8%),K≥48 才出现真细化**;**K=63(7 步却只 1.27%)是唯一与趋势相反的折返点**,形态上更像低 K。

## 机制读数

- 每步产物是**直接预测** `Y_pix[:,t]`(训练是各步平权像素 L1,`F_hat = Y_pix[:,-1]`,步间无累加集成);步 t 的读窗口是它自己的平方块(blockdiag),循环 carry(`Y = query_base + Y`,不 detach)把上一步状态传给下一步。
- 因此 Δᵢ 的物理含义 =「在 carry 基础上,第 i 个平方块的新 tokens 带来的细化量」。Δᵢ **几何衰减** ⇒ 靠后 token 块对图像的信息贡献快速趋零:**K 的有效容量远小于名义 K**。
- 负增量 = 过冲:继续 refine 反而略微远离目标(各步平权监督下,末步没有被特别激励去做到最好)。

## 待办/含义

- K=63 补 seed 重跑,先排除 run 方差(每点 n=1)。
- 若目标是「每步都显著干活」,单靠 BPTT 只能把曲线从「全平」变成「前重后轻」;需要动损失或读窗口激励(per-step 差异化监督、残差目标等)。
