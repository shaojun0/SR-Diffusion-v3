## 观察

1. **形态 = 前重后轻的饱和曲线(近似单调,末端连续三步回升)。** 落差高度集中在最前几步:
   step2 一步吃掉总落差的 **72.2%**(0.9680/1.3408),前 3 步吃掉 **93.0%**,前 5 步的理论落差
   1.3525 px 已达到总落差的 **100.9%**——即 **step5→last 净贡献为负 −0.0117 px**:后 5 步不仅没有
   继续精炼,反而小幅回吐。最小值第 7 步 12.4877 由 step6、step7 各挤出 0.0084 / 0.0017 px 得到,
   随后 step8–10 三步同向回升合计 +0.0218 px。
2. **后步增益随 K 增大仍在恢复,这是 K-sweep 里最清晰的一条趋势。** 以"step1→last 落差占 step1 的
   百分比"为口径:**K=35 ≈ 1.2% → K=99 = 6.75% → K=120 = 9.68% → K=576 = 14.03%**
   (至各自曲线最低点:K=35 ≈ 1.3%、K=99 = 6.88%、K=120 = 9.84%、K=576 ≈ 14.2%)。
   K=120 已把 K=99 的落差相对扩大 **+43.9%**,并首次把"落差占比"推到两位数;但相对全量 576 档
   (14.0%)仍只到约 **69%**,且增益仍几乎全部来自第 2–3 步,而非后段迭代精炼。
3. **增益来源仍是"更多特殊 token 换更好的全局初始化",不是逐步精炼。** 首步(块起点 1,几乎无上下文)
   13.85 → 第 3 步(块起点 9)12.60 已吃掉 93% 的落差;第 4 步之后 7 个解码步合计只再贡献 0.09 px
   左右。⇒ 在 K=120 档,**超过约 25 个特殊 token 之后,增加解码步数的边际价值迅速衰减**。
   压缩-质量曲线在该区段仍由"特殊 token 数量/容量"主导。
4. **异常/可疑点(严格记录,不下定论):**
   - **末三步(步 8/9/10)连续同向回升** +0.0033 / +0.0074 / +0.0111 px,且回升幅度逐步加大;
     三步合计 +0.0218 px 远小于 `step_pixel_std_255`(4.61),单看数值可为噪声,但"第 7 步达最小、
     之后连续回升"的形态在 **K=99(回升 2 步 +0.0187)与 K=576(末步回升 0.04)中重复出现**,
     更像固定现象而非偶发,值得后续用固定 seed 的 per-step 细化实验确认其是否由 decoder 在
     高步数下过拟合/漂移导致。
   - **K=99 与 K=120 都显著优于 K=576 的 DDP 锚点(−21.6% / −23.8%)**,与"K 越大越好"的先验相反。
     由于 K=35/K=576 为 2 卡 DDP bs16×2 旧口径,该反转不能直接当作结论;需等同一单卡口径补一个
     K=576 点(或 k35c 落定以定量口径差)后再判定。
   - `args.json` 中 `grad_accum=1`、`slice_start/end=0/10`、`decoder_steps=null`(由步集自动推导),
     与计划 §1 的 k120 设定一致;`num_specials=0`(输入参数,非实际值),实际 K 由
     `infer_test.json` 的 `num_specials=120` 确认为 **120** ✅。
   - 无 NaN / 发散 / OOM;`TRAIN_RC=0`、`INFER_RC=0`,`k120.done` 已落盘。
5. **缺项说明**:`infer_test.json` 未包含 per-step 归一化空间 L1(只有 `step_pixel_l1_255` /
   `step_pixel_std_255`),故本文 per-step 只报 0–255 空间;`full_norm_l1` 仅有总量。
   其余请求指标(`num_specials`、`decoder_steps`、`n`、`time_s`)均已取得,无缺失。
