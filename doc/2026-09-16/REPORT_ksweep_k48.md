## 观察

1. **形态 = 前重后轻的饱和曲线(近似单调,仅末步回升)。** 落差高度集中在最前几步:
   step2 一步吃掉总落差的 **66.1%**(0.7442/1.1259),前 3 步吃掉 **92.4%**,前 5 步吃掉 **101.2%**
   (1.1396/1.1259)——即 **step5→last 净贡献为负 −0.0137 px**:饱和点在第 5 步,第 6 步小幅回吐。
   这与 K=99(饱和于第 7 步、回升 2 步 +0.0187)、K=120(饱和于第 7 步、回升 3 步 +0.0218)形态同类,
   只是本 run 提前一步饱和、回升幅度更小。
2. **总落差占比打破 K 单调趋势:K=48(7.89%)高于 K=99(6.75%)。** 汇总口径
   ("step1→last 落差占 step1 百分比"):**K=35 ≈ 1.2% → K=48 = 7.89% → K=99 = 6.75% →
   K=120 = 9.68% → K=576 = 14.03%**(至各自曲线最低点:K=35 ≈ 1.3%、K=48 = 7.98%、
   K=99 = 6.88%、K=120 = 9.84%、K=576 ≈ 14.2%)。K=48 这一个点**不在**"K 增大→落差占比增大"的
   单调序列上,是本次最显著的形态异常,需要如实记录而非平滑掉。
3. **但该异常是"首步更差"造成的,不是"后步更强"。** K=48 的 step1 为 14.27,明显高于 K=99 的 13.81
   与 K=120 的 13.85;其末步 13.148 也高于 K=99 的 12.881 / K=120 的 12.509。也就是说 K=48
   在**曲线两端都更差**,相对落差反而因首步基座更低而变大。因此**总落差占比不能单独作为压缩档位好坏的
   代理指标**——判断压缩-质量关系应以绝对 L1(`full_norm_l1` / 像素 L1 / `eval_recon`)为准,
   该三者在三个单卡点上一致地随 K 单调改善:13.148 / 12.881 / 12.509 与 0.2288 / 0.2241 / 0.2176。
4. **后步增益的绝对量级仍随 K 大致恢复,但增益来源依旧是"少量特殊 token 换全局初始化"。**
   K=48 的 1.126 px 落差大于 K=99 的 0.932 px 而小于 K=120 的 1.341 px;
   而落差中 92.4% 在第 3 步前已拿到,第 4–6 步合计仅再贡献约 0.086 px。⇒ 在 K=48 档,
   额外解码步的边际价值已很小,压缩-质量主要由特殊 token 容量决定,与 K=99/K=120 的结论一致。
5. **异常/可疑点(严格记录,不下定论):**
   - K=48 的落差占比(7.89%)高于 K=99(6.75%),破坏 §观察 2 的趋势序列;见 §观察 3 的归因
     (首步基座差异),但仍建议在汇总报告中用绝对质量指标复核该区段是否真为单调。
   - 末步回升仅单步 +0.0137 px,小于 K=99 的两步 +0.0187 与 K=120 的三步 +0.0218;三档均为
     "达最小后回升"的固定形态,回升绝对值远小于 `step_pixel_std_255`(4.94),单看数值可视为噪声。
   - 本 run 与 K=99/K=120 同为单卡 bs32、同代码、同步数,横向可比;但均优于 K=576 的 DDP 锚点
     (本 run −19.9%),与"K 越大越好"的先验相反,该反转在口径差被校准前**不能采信**。
   - `args.json` 中 `grad_accum=1`、`slice_start/end=0/6`、`decoder_steps=null`(由步集自动推导),
     与计划 §1 的 k48 设定一致;其中 `num_specials=0` 为输入参数(非实际值),实际 K 由
     `infer_test.json` 的 `num_specials=48` 确认为 **48** ✅。
   - 无 NaN / 发散 / OOM;`TRAIN_RC=0`、`INFER_RC=0`,`k48.done` 已落盘。
