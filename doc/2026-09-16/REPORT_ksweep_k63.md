## 观察

1. **绝对质量不随 K 单调:K=63(14.06 px)反而比 K=48(13.15)/K=99(12.88)/K=120(12.51)都差,
   是本次单卡 sweep 的最差点。** 单卡序列 13.15 → **14.06** → 12.88 → 12.51 px 明显非单调,
   与"K 越大/越接近 K=64 越好"的先验相悖。`full_norm_l1`(0.2445 vs 0.2287/0.2241/0.2175)与
   `eval_recon` 两个独立口径给出**同一结论**,不是像素空间度量造成的伪影。
2. **落差形态:K=63 是"前重后轻 + 早饱和 + 末两步回吐",且总落差为单卡各档最小。**
   step2 一步吃掉总落差的 **76.85%**(0.1250/0.1626),前 3 步吃掉 **100.03%**——即第 3 步之后
   净贡献已归零甚至为负;第 4–5 步合计仅 0.0185 px,第 6–7 步反向回吐 0.0185 px。
   饱和点在第 5 步,与 K=48 相同,但比 K=99/K=120(均第 7 步饱和)更早。
   单卡口径落差占比序列:**K=48 7.89% → K=63 1.14% → K=99 6.75% → K=120 9.68%**,
   K=63 是显著的低点(与 K=35 的约 1.2% 同量级)。
3. **K=63 的劣势来自"后步几乎不精炼",而不是"首步更差"。** 其 step1 = 14.2213 与 K=48 的
   14.2742 几乎相同(甚至略好 0.053 px),但末步 14.0587 比 K=48 的 13.1483 差 0.910 px。
   也就是说 K=48 在首步相近的基座上靠迭代精炼拿回约 1.13 px,而 K=63 只拿回 0.16 px。
   这与"压缩档位下后步贡献微弱"的既有结论方向一致,但 K=63 把该现象推到了目前最极端的位置。
4. **K=63 仍显著优于两个 DDP 锚点与 detach 基线**:比 K=35 BPTT(18.05)低 22.1%,
   比 K=576 BPTT(16.42)低 14.4%,比 detach 时代 blockdiag K=35(19.02)低 26.1%。
   但比 K=576 更好这一点在口径差被校准前**不能采信**(同为 K 相关反转,见 K=48 报告 §观察 5)。
5. **异常/可疑点(严格记录,不下定论):**
   - **K→质量非单调是本 run 最主要的异常。** K=63 与 K=48 仅相差一个 slice 步(49),
     却出现 0.91 px 的反向差,而两者均为单卡 bs32 / 同步数 / 同 seed。可能的解释包括:
     单次运行的优化方差、采样步集与 K 的耦合方式(49 这一步带来的 K=63 使特殊 token 容量
     相对步数配比改变)、以及早期训练轨迹差异(见 §训练期轨迹 2190 步处 +0.0573 的落后)。
     **现有数据不足以区分这些解释**,建议汇总报告如实标注该点为非单调离群,并在条件允许时
     对 K=48/K=63 追加不同 seed 或重跑以确认是否为噪声。
   - 末步回升 0.0185 px 远小于 `step_pixel_std_255`(5.21),单看数值可视为噪声;但"达最小后回升"
     在 K=48/99/120 上重复出现,形态一致,故按固定形态记录而非忽略。
   - 日志头部固定行"上一步输出(detach)喂回当下一步查询 ⇒ 步间无梯度回流"是代码打印的**通用说明**,
     与 K=48 日志逐字相同,描述的是"上一步输出作为查询"这一路径,不构成对 BPTT(carry 不 detach)
     口径的反证;本 run 的 slice/K/步集与计划 §1 完全一致。
   - 无 NaN / 发散 / OOM;`TRAIN_RC=0`、`INFER_RC=0`,`k63.done` 已落盘。`train_loss` 终值 0.3422
     (K=48 为 0.3264),与 `eval_recon`/像素 L1 的落后方向一致。
