## 观察

1. **K=15 是压缩-质量曲线在低 K 端的预期劣化点,绝对质量在单卡五点中最差。** 三个独立口径
   (`full_norm_l1`=0.2612、像素 L1=15.02、`eval_recon`=0.2612)一致给出同一结论,方向与
   `PLAN` §0/§2 的预期相符:压缩到仅 3 个解码步、15 个特殊 token 时,重建质量相对 K=48
   (13.15 px)劣化 **+1.88 px(+14.3%)**、相对 K=120(12.51 px)劣化 **+2.52 px(+20.1%)**。
   单卡序列(由小到大):**K=15 0.2612 → K=48 0.2287 → K=63 0.2445 → K=99 0.2241 → K=120 0.2175**,
   K=15 落在最差端,K=63 仍是那个非单调离群点(劣于更小的 K=48)。
2. **per-step 落差比例是全部测点中最弱的(−0.249%),与"步数极少 ⇒ 精炼空间小"一致。**
   3 步内 step1→last 仅 0.0375 px;单卡口径落差占比序列:
   **K=15 0.249% → K=48 7.89% → K=63 1.14% → K=99 6.75% → K=120 9.68%**。
   K=15 为最低点,量级与 K=63(1.14%)、K=35(约 1.2%)同在"后步几乎无增益"区,
   但比它们还低约 4–5 倍。⇒ 在 3 步档,**额外解码步的边际价值已被压到接近零**。
3. **本档唯一形态异常:最小值出现在第 2 步而非末步,末步反而回升。** K=15 的 3 步曲线为
   15.0622 → **15.0195(最小)** → 15.0247,末步回吐 +0.0052 px;而 K=48/K=63 最小在第 5 步、
   K=99/K=120 最小在第 7 步,均为"达最小后末步/末几步回升"。也就是说 K=15 不仅在**幅度**上
   落差最小,在**形态**上也提前到第 2 步饱和。该回升 +0.0052 px 远小于 `step_pixel_std_255`(5.47),
   单看数值可视为噪声;但"饱和后回升"的形态在其他四档重复出现,故按固定形态记录而非忽略。
4. **绝对质量并未在低 K 端崩溃(仍显著优于 detach 基线),但跨口径锚点须谨慎。**
   K=15 比 detach 时代 blockdiag K=35(19.02)低 **21.0%**,比 K=35 BPTT DDP 锚点(18.05)低 **16.8%**,
   甚至比 K=576 BPTT DDP 锚点(16.42)低 **8.5%**。后两者是 2 卡 DDP bs16×2 旧口径,
   与"K 越大绝对质量越好"的先验相反,**在校准单卡↔DDP 口径差(待 `k35c`)之前不能采信**;
   可以确定的只是:K=15 在**同单卡同代码口径内**是五点中最差。
5. **异常/可疑点(严格记录,不下定论):**
   - 首步基座明显最高:K=15 的 step1 = 15.0622,比 K=48(14.2742)/K=63(14.2213)高约 0.8 px,
     比 K=99/K=120(13.81/13.85)高约 1.2 px。即极限压缩下**连"零精炼"的首步预测也更差**,
     这与"特殊 token 容量决定主要质量"的既有结论一致(见 K=48 报告 §观察 4)。
   - 单卡五点内 K 与绝对质量并非严格单调(K=63 离群,已在前序报告记录);K=15 的加入**没有**
     改变该结构,K=15 只是把最差端向下延伸。
   - `train_loss` 终值 0.3567 为单卡各档最高(K=48 0.3264 / K=63 0.3422),
     `train_runtime` 9330 s 为各档最短(步数少、循环解码步最少),两者均与预期一致。
   - 日志头部固定行"上一步输出（detach）喂回当下一步查询 ⇒ 步间无梯度回流"是代码打印的**通用说明**,
     与 K=48/K=63 日志逐字相同,描述的是"上一步输出作为查询"这一路径,不构成对 BPTT(carry 不 detach)
     口径的反证;本 run 的 slice/K/步集与计划 §1 完全一致。
   - 无 NaN / 发散 / OOM;`TRAIN_RC=0`、`INFER_RC=0`,`k15.done` 已落盘。
6. **缺项说明**:`infer_test.json` 未包含 per-step 归一化空间 L1(只有 `step_pixel_l1_255` /
   `step_pixel_std_255`),故本文 per-step 只报 0–255 空间;`full_norm_l1` 仅有总量。
