## 0. 要回答的问题

臂②（每步**独立** `[cls]` 查询槽）把 stack2x→baseline 的聚合差距填掉了 50.1%，
但它同时改变了两件事：**(i) 给 decoder 多了一个可学习槽位**、**(ii) 该槽位携带步身份**。
臂②的收益究竟来自哪一个，无法从臂②自己分辨。臂③ = 臂① 的 `step_embed` **+** 一个**在 5 步间广播共享**的 `[cls]` 槽：

| 配置 | `step_embed`（additive 身份） | `[cls]` 槽 | 身份进前向的载体 | 新增参数 |
|---|---|---|---|---|
| `stack2x`（对照） | ✗ | 无 | 无 | — |
| **臂①** `stepid` | ✓ | 无 | 每步 additive 向量 | 5×2048 = 10,240 |
| **臂②** `stepidcls` | ✗ | **每步独立** | 每步私有槽（隐式） | 5×1024 = 5,120 |
| **臂③** `stepidshcls` | ✓ | **单槽广播（共享）** | 每步 additive 向量（槽**不含**身份） | 5×2048 + 1024 = 11,264 |

**预先写死的三种可能读法**（避免事后解释）：

- **P1「槽位主因」**：臂③ 也应显著优于 stack2x、量级接近臂② ⇒ 臂② 的收益主体是**额外槽位**，与步身份无关。
- **P2「身份主因」**：臂③ ≈ 臂①（≈0.403）⇒ 共享槽位几乎无独立增益，臂② 的收益来自**步身份**。
- **P3「可叠加」**：臂③ 显著优于臂① 与臂② ⇒ 两者各自独立有效。

**判据（沿用 runbook §4 口径）**：

1. **主判据**：后段边际增益 `Δ16`、`Δ25` 是否在 probe 与全量 test 上同向、是否翻正。
2. **副判据**：后段 `scale` 占比、tail 逐块 cos、`z_s` within-std 是否结构性变化；**只改 cos 不改 Δ ⇒ 判无效**。
3. **聚合判据**：全量 test `full_norm_l1` vs `stack2x 0.41729` / 臂① `0.40316` / 臂② `0.37442` / baseline `0.33179`。
4. **读出判据**：全量 `head_mean`（step1 单发质量）。
5. **训练健康判据**（仓库 `ANALYSIS_lr_batch_vs_steplaw.md` §7 事先写死）：`grad_norm < 1e-2` 连续 ≥3 条日志（≥60 步），
   或 loss 升破 step-200 值且 60 步内不回落 ⇒ **硬失败，立即判负，不必跑完**；健康段 `grad_norm` 应在 0.1–3。
6. **诚实边界**：单 seed（42）、无误差棒；1e-3 量级差异不可判显著，只有聚合量级（1e-2）可判。

**作用域是本次实验的关键变量**（见 §4）：`step_embed` 必须加到**该步的全部查询行**（臂① 的原始作用域），
若收窄成「只加 patch 行」、让 `[cls]` 行在 5 步间字面不变，训练会塌缩。共享的是 `[cls]` 的**参数**
（只有 1 个向量），不是它的输入内容；`[cls]` 行**输出**因块掩码（每步只读自己的 `z_s` 块）不同而不必相同。

### 4.3 结论与决策

1. **根因是 v1 的收窄**：`[cls]` 行在 5 步间字面不变 ⇒ 该行成为唯一的**步不变**查询行，正好驱动仓库已知的
   「步不变退化吸引子」（5 步输出完全相同）。**步身份必须进 `[cls]` 行**（臂① 的原始作用域）才能训练。
2. **共享槽位本身也不健康**：D1（纯控制臂，无任何 identity 注入）逃出常量地板后 `grad_norm` 单调升到 20+，
   属发散；loss 0.94 远差于臂② 0.60 ⇒ **「额外槽位」不是中性的容量增加，逐 step 独立性是承重的**。
   这在本轮就以训练侧证据回答了报告 §4.3 的一半：P1「槽位主因」不成立。
3. **决策**：正式臂③ 采用 **D2 作用域**（= 目标原文「臂① additive step_embed + 5 步共享一个 [cls]」的字面实现），
   于 2026-09-13 14:40 启动 8760 步（2 卡）。
4. **诚实边界**：700 步筛查只判「是否落入早期塌缩/发散」，不能替代 8760 步的聚合结论（D1 的后段行为未跑到）。

### 5.1 修正后的结论（重要）

§4.3 曾把 v1 塌缩归因于「`step_embed` 收窄到 patch 行」。**该归因已被推翻**：同一份 D2 代码两次运行结果相反
（筛查 D2 健康 0.7205 @706；正式 D2 锁死 1.15）⇒ 决定性变量不是作用域，而是**运行间非确定性**。
共享 `[cls]` 使训练坐在退化吸引子边界上（双稳态）：

| 运行 | 变体 | 结果 |
|---|---|---|
| 1 | v1（仅 patch 行） | 塌缩（loss 1.15 / grad 0.003 锁死 1800+ 步） |
| 2 | D1（纯控制臂，无 identity） | 逃出地板后**梯度发散**（`grad_norm` 6→20），loss 0.94 |
| 3 | D2（臂① 作用域） | **健康**（0.7205 @706） |
| 4 | D2（同代码复跑） | **塌缩**（loss 1.15 / grad 0.007） |
| 5 | D2 复跑 #1（500 步截断，中止前） | 未塌缩但 `grad_norm` 已升到 5.1（同 D1 的发散形态） |

**对报告 §4.3 的答案（比 P1/P2/P3 更强）**：臂② 的收益**不能**归因于「白送一个额外槽位」——
共享槽位不是中性的容量增加，**逐 step 独立是承重的**。共享槽位这条线按用户裁定放弃，改跑臂④
（= 臂② 每步独立 `[cls]` **+** 臂① `step_embed`），见 `EXPERIMENT_step_identity_arm4_stepidcls_stepid.md`。
