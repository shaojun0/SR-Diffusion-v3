# SR-Diffusion v3 — 臂④「臂② 每步独立 [cls] + 臂① step_embed」最终报告（2026-09-13）

> 问题（用户）：「跑臂①和臂②的结合吧！」——四臂报告 `REPORT_step_identity_AB.md` 已证明两条身份注入各自
> **单独**有效（臂① 填补 stack2x→baseline 差距 16.5%、臂② 50.1%），但**从未测过二者叠加**。
> 本报告正面检验可叠加性；共享 `[cls]` 的臂③ 因**双稳态不可训**已按用户裁定放弃
> （见 `EXPERIMENT_step_identity_arm3_sharedcls.md`）。
> 证据目录：`data_stepidcls_stepid/`（含 `scope_ab/` 作用域对照与两次塌缩日志）。

---

## 0. 结论速览

1. **不可叠加，且相互干扰。** 全量 test `full_norm_l1`：baseline 0.33179 / stack2x 0.41729 /
   **臂① 0.40316 / 臂② 0.37442 / 臂④ 0.39763**。臂④ 相对 stack2x 只填补 **23.0%**，
   而臂② 单臂即填补 **50.1%** ⇒ **把 `step_embed` 加到臂② 上，私有槽的收益被砍掉一半以上**
   （相对 stack2x 的改善从 0.0437 缩到 0.0197）。
2. **臂④ 全程夹在臂① 与臂② 之间**：每个 checkpoint（2000/4000/6000/8000/final）都优于臂①、
   劣于臂②；终版 0.3976 vs 臂① 0.4032（只好 1.4%）、vs 臂② 0.3745（差 6.2%）。
   ⇒ 叠加的结果**退化成"臂① 一档"**，而不是"①+②"。
3. **后段重新净负**（主判据失败）：全量 test Δ16 **−0.0013**、Δ25 **−0.0018**（臂② 为 +0.0018/+0.0015），
   总落差塌到 **+0.0002**（臂② +0.0302）。臂② 曾达成的"Δ16/Δ25 双翻正"被 `step_embed` 抹掉。
4. **连 step1 读出也被拖差**：全量 `head_mean` 22.660（臂② 21.335，臂① 23.097）。
   臂② 的收益主体本是"单发读出变好"，叠加后这一项也退掉了 1.3 px。
5. **机制上 decoder 退化为单发**：后 4 步 `scale/scale₁` 仅 **4.7–5.8%**（身份臂中最低；臂① 达 12%），
   probe 总落差 **−0.0002**（等于零），`z_s_within_std` **0.0056**（全臂最塌，臂② 0.1223）。
6. **隐含设计变量（重要副产品）**：`step_embed` 的作用域是**生死级**变量。把它加到全部 Q 行（含 `[cls]` 行）
   的版本 **2/2 塌缩**（`[cls]` 行上 `step_cls[t]+step_embed[t]` 冗余）；只加到 **N 个 patch 行**
   （= 臂① 原始行集）才健康。结合臂③ 的结果可得一条规律：
   **`[cls]` 行必须恰好携带一个步身份向量——零份（共享槽）或两份（冗余）都会塌。**

**一句话**：显式步身份与私有 `[cls]` 槽**不是加法关系**——两者叠加把后段收益重新打回净负、把单发读出拖差，
最终只保住臂① 一档的水平。这再次把后段分工的杠杆指向**训练信号（每步私有目标）**，而非架构/身份。

## 1. 实验设计

与四臂逐项相同的 depth-4 配置（`stack_dim 2048 / heads 16 / dropout 0.05 / lr 1.0e-4 / wd 0.01 /
warmup 0.03 / clip 1.0 / seed 42 / bs16×2卡(全局 32) / 8760 步 / slice 0:5 (K=35, steps=[1,4,9,16,25]) /
blockdiag / 448×252`）。臂④ = 臂② 的每步私有 `[cls]` 槽 **+** 臂① 的零初始化 `step_embed`
（新增参数 5×2048 + 5×1024 = 15,360）。

**作用域 A/B（本实验的隐含单变量）**：

| 变体 | `step_embed` 作用域 | `[cls]` 行上的身份 | 结果 |
|---|---|---|---|
| ④a | 全部 Q 行 | `step_cls[t] + step_embed[t]`（**冗余**） | ❌ **2/2 塌缩**（loss 锁死 1.15、`grad_norm` 0.004–0.07） |
| ④b（采用） | 仅 N 个 patch 行 = 臂① 原始行集 | 仅 `step_cls[t]` | ✅ 健康，逐记录贴合臂② |

`step_embed` 零初始化 ⇒ 训练起点与纯臂②**逐位一致**，故"臂④ − 臂②"干净地度量 `step_embed` 的增量。

## 3. 按事先判据的裁决

| 判据 | 臂④ |
|---|---|
| **① 可叠加性（主判据）** | **不成立**：未优于臂②，且把臂② 的填补率从 50.1% 压到 23.0% |
| **② 后段分工（Δ16/Δ25 翻正）** | **失败**：Δ16 −0.0013、Δ25 −0.0018 重新净负 |
| **③ 读出归属（`head_mean`）** | **退化**：22.660 vs 臂② 21.335 |
| **④ 机制侧（scale/cos/within-std）** | 结构性变化有（scale 占比最低、within_std 最塌），但**方向是负的** |
| **⑤ 训练健康** | ✅ `grad_norm` 1.1–2.8，无塌缩（④a 的 2/2 塌缩是作用域选错，不是本臂） |

**综合裁决**：**臂① 与臂② 相互干扰，不能叠加。** 本实验否证了"两条身份注入可叠加"的假设，
并把四臂报告的结论推进了一步：**身份注入这一层的两个变体已互相饱和甚至相消**，
后段分工的杠杆只能去**训练信号（每步私有目标）**找。

## 4. 局限

1. **单 seed（42）、无误差棒**；该配置家族已多次出现塌缩/双稳态（臂③ 与本文 §1 的作用域 A/B）。
   聚合量级结论（差 2.3e-2）稳健；1e-3 级 Δ 细节不可判显著。
2. **作用域（④a vs ④b）是本实验的隐含变量**，其差别是生死级（塌缩 vs 健康）⇒ 身份注入类实验必须先做作用域体检。
3. 臂④ 是全部臂中 `z_s_within_std` 最低者，同时后段最无用。这与四臂报告"cos/within-std 不预测后段有用性"
   并不矛盾（本臂只是该相关性上的一个点），但提示**极端塌缩**（低一个数量级）可能与后段归零同时出现。
4. 未做 train-split 同口径 eval（与四臂报告同）。

## 5. 下一步（按信息量排序）

1. **P1 分区域私有目标 × 臂②**：仓库里唯一能把后段幅度拉到 45% 的手段（`REPORT_v2_region_loss_AB.md`）
   与已证实能改善 step1 的私有 `[cls]` 槽相叠——这才是"能否叠加"的真问题所在（身份层已证明饱和）。
2. **不再沿"身份注入"投入**：本实验已证两条身份机制相消，架构侧无更多低垂果实。
3. **train-split 同口径探针**（零训练），补齐 §4.4。
