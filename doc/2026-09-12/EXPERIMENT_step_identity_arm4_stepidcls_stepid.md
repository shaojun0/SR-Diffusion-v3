## 0. 设计（单变量）

| 配置 | `step_embed`（臂①） | `[cls]` 槽（臂②） | 新增参数 |
|---|---|---|---|
| `stack2x`（对照） | ✗ | 无 | — |
| **臂①** `stepid` | ✓ | 无 | 5×2048 = 10,240 |
| **臂②** `stepidcls` | ✗ | 每步独立 | 5×1024 = 5,120 |
| **臂④** `stepidcls_stepid` | ✓ | **每步独立** | 5×2048 + 5×1024 = 15,360 |

与臂③ 的关键差别：`[cls]` 是**每步私有**的（`(5,1024)`），因此**不存在步不变查询行**——
这正是臂③ 塌缩的机制来源。`step_embed` 仍为零初始化，**训练起点逐位等于纯臂②**，
故"臂④ − 臂②"这一差值干净地度量 `step_embed` 的增量。

## 2. 作用域 A/B 与最终补丁

臂① 的 `step_embed` 在臂① 时代作用在**该步的 N 个 patch 查询行**上（那时还没有 `[cls]` 行）。
把它与臂② 的 `[cls]` 槽结合时，作用域有两种写法，实测差别是**生死级**：

| 变体 | `step_embed` 作用域 | `[cls]` 行上的有效步身份 | 结果 |
|---|---|---|---|
| **④a** `allrows` | 全部 Q 行（N patch + `[cls]`） | `step_cls[t] + step_embed[t]`（**两参数在同一行相加 ⇒ 冗余**） | ❌ **2/2 塌缩**（`stepidcls_stepid_attempt{1,2}_collapsed.log`） |
| **④b** `patchrows`（**采用**） | 仅 N 个 patch 行 = **臂① 原始行集** | 仅 `step_cls[t]`（单一身份，无冗余） | ✅ 健康，逐记录贴合臂②（record 22：0.6584 vs 0.6582） |

两次 ④a 运行都在 step ≈ 450 前后落入同一退化吸引子（loss 锁死 ~1.15、`grad_norm` 0.004–0.07，
命中 §0 第 5 条硬失败判据），已分别停跑归档；④b 在同一窗口正常下降到 0.66、`grad_norm` 1.1–2.2。

**机制结论（与臂③ 合并成一条完整的"身份剂量"规律）**：`[cls]` 行必须**恰好携带一个**步身份向量——
**零份**（臂③ 共享槽：该行步不变）或**两份**（④a：两个参数在同一行相加，存在零梯度冗余方向）都会塌缩；
**一份**（臂② 或 ④b）才健康。这解释了 7 次运行中全部 4 次失败。

最终补丁（④b，对臂② `model_v2.py` 的 diff）：

```diff
@@ OutputQueryDecoder.__init__
         self.step_cls = nn.Parameter(torch.randn(len(self.steps), dim) * 0.02)
+        # 臂④: 零初始化步身份向量（起点逐位等于纯臂②）
+        self.step_embed = nn.Parameter(torch.zeros(len(self.steps), self.stack_dim))

@@ OutputQueryDecoder.forward
-        Y = self.stack(self.stack_in(Y), self.stack_in(A),
+        Y = self.stack_in(Y)                                     # (B,|T|·Q,stack_dim)
+        # 臂④: 步身份只加到该步的 N 个 patch 行(行序 (t,k), k∈[0,Q), 末行 k=N 为 [cls])
+        se = self.step_embed.view(len(self.steps), 1, self.stack_dim).expand(-1, N, -1)
+        se = torch.cat([se, torch.zeros(len(self.steps), 1, self.stack_dim,
+                                        device=Y.device, dtype=Y.dtype)], dim=1)
+        Y = Y + se.reshape(len(self.steps) * Q, self.stack_dim).unsqueeze(0)
+        Y = self.stack(Y, self.stack_in(A),
                        memory_mask=mask, tgt_mask=tgt_mask)
```

## 3. 训练前验证（全部通过）

- 对外契约不变：`out=(2,5,36,256)`、`last_step_cls=(2,5,256)`、`attn_mask=(185,36)`、`tgt_mask=(185,185)`
- 臂② 性质保留：`step_cls=(5,1024)` **每步独立**（无步不变行）；blockdiag 隔离成立
- 臂① 性质加入：`step_embed=(5,2048)` **零初始化**，两参数梯度均 >0（0.289 / 0.222）
- **零初始化等价性**：`step_embed=0` 时送进 `self.stack` 的张量与**纯臂②构造逐位一致**
- **作用域（④b）**：非零 `step_embed` 使该步的 **N 个 patch 行**精确平移自己的向量，而
  **`[cls]` 行完全不受 `step_embed` 影响**（其步身份全部来自 `step_cls[t]`）

## 4. 判据（事先写死）

1. **可叠加性（主判据）**：全量 test `full_norm_l1` 是否优于臂② `0.37442` 与臂① `0.40316`。
   - 若 **臂④ ≈ 臂②**（差值 ≤ 噪声）⇒ `step_embed` 在已有私有槽时**无增量**（二者不独立，共享同一增益来源）。
   - 若 **臂④ 显著优于两者** ⇒ 可叠加。
   - 若 **臂④ 差于两者** ⇒ 相互干扰。
2. **后段分工**：`Δ16`/`Δ25` 是否在 probe 与全量 test 上同向翻正（沿用 runbook §4）。
3. **读出归属**：全量 `head_mean`（step1 单发质量）——臂② 的收益主体被判定为"step1 读出变好"，
   臂④ 是否在此基础上再改善，决定 `step_embed` 的贡献位置。
4. **机制侧**：后 4 步 `scale` 占比、tail cos、`z_s_within_std`（只改 cos 不改 Δ ⇒ 判无效）。
5. **训练健康**：`grad_norm` 应在 0.1–3；`<1e-2` 连续 ≥3 条日志 ⇒ 硬失败立即判负（仓库事先写死口径）。
6. **诚实边界**：单 seed（42）、无误差棒；1e-3 量级差异不可判显著。

## 7. 按事先判据的裁决

| 判据 | 结果 |
|---|---|
| **① 可叠加性（主）** | **不成立**：臂④ 0.39763 既未优于臂②（0.37442，差 6.2%），也未带来臂② 之外的增量；相对 stack2x 只填补 **23.0%**，而臂② 单臂即填补 **50.1%** ⇒ **加 `step_embed` 把私有槽的收益砍掉一半以上**（0.0437 → 0.0197）。 |
| **② 后段分工** | **失败**：Δ16 **−0.0013**、Δ25 **−0.0018** 双双**重新转负**（臂② 为 +0.0018/+0.0015）；总落差塌到 **+0.0002**（臂② +0.0302）。 |
| **③ 读出归属** | **退化**：`head_mean` 22.660（臂② 21.335）⇒ 连 step1 单发读出也被 `step_embed` 拖差 1.3 px。 |
| **④ 机制侧** | 后 4 步 `scale` 占比 **4.7–5.8%**（身份臂中最低，臂① 达 12%）＋ `z_s_within_std` **0.0056**（全臂最塌，臂② 0.1223）⇒ decoder 实质上只剩 step1 单发。 |
| **训练健康** | ✅ 全程 `grad_norm` 1.1–2.8，无塌缩（这与 ④a 形成对照，见 §2）。 |

**裁决**：**臂① 与臂② 不能叠加，且相互干扰**——把 `step_embed` 加到臂② 上，得到的是"臂① 一档"的结果
（0.3976 ≈ 臂① 0.4032，仅好 1.4%），臂② 的收益被抵消掉一半以上；后段 Δ 重新净负、step1 读出也被拖差。
这一结论与四臂报告的收尾判断一致：**后段分工的真正杠杆不在"身份注入"这一层，而在训练信号（每步私有目标）。**

**注意**：本臂是 `z_s_within_std` 最低（最塌）的配置，同时也是后段最无用的配置。这与 `REPORT_step_identity_AB.md` §2.3
「cos/within-std 不预测后段有用性」（臂② 最塌却最无害、baseline 最健康却净负）并不冲突——本臂只是该相关性上的
**一个**数据点，不足以复活"register 塌缩 → 后段归零"的因果论断。

## 8. 局限

1. **单 seed（42）、无误差棒**；本配置家族已多次出现塌缩/双稳态（见 `EXPERIMENT_step_identity_arm3_sharedcls.md`
   与本文 §2），故"臂④ 劣于臂②"的**量级**结论稳健（差 2.3e-2 ≫ 噪声），但 1e-3 级细节不可判。
2. **作用域 A/B 是本实验的隐含变量**：④a（全 Q 行）2/2 塌缩、④b（patch 行）健康，说明"身份剂量"是生死级设计变量，
   这也意味着**任何身份注入臂都必须先做作用域体检**。
3. 未做 train-split 同口径 eval（与四臂报告同）。
