# 分辨率扫描「只有 56×56 达标」的根因复核（2026-09-23）

> 复核对象：[`doc/2026-09-22/REPORT_resolution_sweep.md`](../2026-09-22/REPORT_resolution_sweep.md)
> 及其产物 [`doc/2026-09-22/res_sweep/`](../2026-09-22/res_sweep/)。
> 复核方式：**只读**代码/产物 + 一台 CPU 微型复现台（本轮新增，见 §8）。
> 结论不是「多步递归训不起来」，而是：**这个扫描的自变量不是「像素数」，且高分辨率的臂是被
> 一个没跑完的 warm start 喂进平凡解（预测均值）的；真正需要修的变量在配方/预算，不在架构上限。**

> ## ★ 2026-09-23 判决实验已跑完：本复核 §3/§7 的推断**实测成立**
> 224²、只把 A 相 1000→**3000** 步（B 相 5000 步不变），16 步循环从平线变成单调下降：
> 最好 L1 **34.02 → 19.38**（−43.0%）、PSNR **14.26 → 18.69 dB**（+4.43 dB），
> 并**重新超过** per-patch 均值基线（17.35 dB）+1.34 dB。A 相逃逸实测发生在 **1500→2000 步之间**。
> ⇒ **原报告 §3.1「多步递归训不起来」被推翻**，根因确认是 A 相预算 + A→B 两相切换。

## 0. 一句话结论

1. **像素数不是自变量。** 扫描把 `像素数 ↔ N ↔ |T|=⌊√N⌋ ↔ 读窗口几何 ↔ 未读 special 数 ↔ 序列长度 ↔ 每步损失权重`
   全绑在一起了。**决定性反例：扫描的 336² 与主线的 448×252 像素数完全相同（都是 112,896）、
   N 相同（都是 576）、|T| 相同（都是 24），结果却一个崩（L1 38.7 平线）一个达标（L1 19.1→16.4）。**
2. **高分辨率臂的「崩」= 停在平凡解（预测均值/近乎常量），不是「分辨率变差」。**
   224²/336² 的最好步 L1 ≈ 34–39、PSNR 13.4–14.3 dB，而**同图同分辨率的 per-patch 均值基线是
   17.35 / 17.83 dB** —— 模型连「每块预测自己的 DC」都没到，是**优化没起来**，不是任务变难
   （per-patch 均值基线本身几乎不随分辨率变）。
3. **最直接的近因：扫描的两相配方（A 相「单步全读」warm start 1000 步 → B 相「多步分块读」1500 步）
   在 A→B 切换时会把模型打坏，且代价随 N 急剧变大；同时 A 相在 224² 上 1000 步**还没逃出平凡解**。**
   证据见 §2、§3。
4. **原报告的招牌对比（§3.1「224px 单步全读 21.59 dB vs 16 步循环 14.26 dB ⇒ 编码器/解码器有能力、
   是多步循环训不起来」）是预算/warm start 混淆的**：单步臂拿的是 3000 步**专用的单步训练**（~2000 步才
   逃出平凡解），多步臂的前 1000 步却在**未逃出**的状态里烧掉了。见 §6。
5. 建议的修法见 §7：**先冻结 |T|（跨分辨率用固定步切片）** + **去掉 A/B 两相、从零训递归**（或把 A 预算
   提到逃出为止）**+ carry 归一化**，再谈分辨率。

## 1. 决定性反例：336² 与 448×252 是同一个几何，结果相反

| | 扫描 **336²**（patch 读出 / DINOv2-small） | 主线 **448×252**（register 读出 / DINOv2-large） |
|---|---|---|
| 像素数 | **112,896** | **112,896** |
| patches N | **576**（24×24） | **576**（32×18） |
| 采样步 \|T\| | **24**（[1,4,…,576]） | **24**（[1,4,…,576]） |
| K = num_specials | 576 = N | 576 = N |
| 读窗口几何 | 完全相同（4,5,7,…,47,1） | 完全相同 |
| 每步 L1 曲线 | 39.61 → 38.71（最好 @t=256）→ 38.75 | 19.10 → 16.38（最好 @t=324）→ 16.42 |
| 轨迹改善 | **−2.2%** | **−14.2%**（单调前缀 24/24） |
| 最好 PSNR | 13.61 dB | 19.02 dB |
| 训练预算 | warm 1000 + nested 1500 步，bs 16 | **8760 步，全局 bs 32，fp32，无 warm start** |
| z_s 来源 | **patch token（光栅序，局部）** | **576 个 register（全局摘要）** |
| 编码器 | DINOv2-**small**（384, 12L） | DINOv2-**large**（1024, 24L） |
| 数据 | DIV2K-800，直接 resize 成正方 | construction_site-7009，letterbox 448×252 |

**同一像素数、同一 N、同一步集、同一读窗口、同一损失，结果差 5.4 dB。** 所以「像素越来越多→效果雪崩」
这个读法本身不成立；扫描测到的是**配方 + 读出语义**，不是分辨率。

特别注意 **step 1**（窗口永远只有 4 个位置：`z_cls` + 3 个 z_s）：
- register 版（主线）：3 个 register 是**全局摘要**（DINOv2-large 全双向 24 层算出）⇒ step1 L1 **19.10**，
  离最好步只差 2.7；
- patch 版（扫描）：3 个 patch token 就是**图左上角 3 个 patch**（光栅序）⇒ step1 L1 **39.61**，≈ 平凡解。

因为损失是 `mean_t` **各步平权**，patch 版前十几步都「信息饥饿」，最优解被拉向「输出均值」；
register 版没有信息饥饿的步，所以不会被拉走。这是「高分辨率崩、56² 不崩」的最简机制解释
（56²：step1 就已是 4/17 个 token，窗口占比 24%；576²：4/577 = 0.7%）。

读窗口信息占比（K=N，末步恒退化为 1 个 token）：

| N | \|T\| | step1 窗口 | 单步最大窗口 | 末步窗口 |
|---:|---:|---:|---:|---:|
| 4（28²） | 2 | 4（100%） | 4（100%） | **1** |
| 16（56²） | 4 | 4（25%） | 7（43.8%） | **1** |
| 64（112²） | 8 | 4（6.2%） | 15（23.4%） | **1** |
| 256（224²） | 16 | 4（1.6%） | 31（12.1%） | **1** |
| 576（336² / 448×252） | 24 | 4（0.7%） | 47（8.2%） | **1** |

## 2. 新证据：A→B 切换本身就会把轨迹打坏，且代价随 N 变大

### 2.1 真实 run（现有产物里的直接证据）

`res_sweep/runs/224_diag-patch/result.json`：A 相跑了 **3000 步**（单步全读），B 相只跑了 2 步。
A 相结束时单步全读 L1 = **14.07 / 21.20 dB**（已经很好）。紧接着用**同一份权重**走 16 步分块读：

```
L1: 58.99 → 68.53 → 78.98 → 86.77 → 91.79 → … → 101.41 → 101.40 → 100.62
PSNR: 10.90 → 9.35 → 8.10 → … → 6.36 dB          （逐步单调变坏/发散）
```

**即：一个 21.2 dB 的单步模型，套进 16 步循环立刻掉到 10.9 dB 并继续发散。** A 相与 B 相的读窗口
分布（A：1 个 257-token 窗口；B：16 个 ≤31-token 窗口）差得太远，切换是「换任务」而不是「换课程」。
扫描的标准臂（`run_sweep.sh`）正是这个配方：A=1000 → B=1500，A 相结束后没有 B 相的回退保护。

### 2.2 CPU 微型复现台（本轮新增，单变量：只换 z_s 读出段）

`doc/2026-09-23/toy_zmode_ab.py`（照抄 `model_v2.py` 的块读窗口 / 裸加 carry / `mean_t` L1；
N=K=64、|T|=8、A=600、B=900、seed 42，其余与 `doc/2026-09-16/cpu_probe_bptt_toy.py` 一致）：

| 臂 | A 相（单步全读）后 test L1 | B 相 it0 的 step1 | B 相 900 步后 step1 / 最好 / 末步 | 轨迹改善 |
|---|---:|---:|---:|---:|
| z_s = **register** | 0.6291 | **0.7868** | 0.4495 / **0.2386** / 0.2467 | 46.9% |
| z_s = **patch** | **0.0633**（几乎无损） | **0.8730** | 0.6213 / **0.1964** / 0.2079 | 68.4% |
| 平凡解（预测均值） | 0.8101 | — | — | — |

两件事：
1. **A→B 切换的瞬时破坏是真实的、且 patch 版大得多**（patch：0.063 → 0.873，**13.8×**；
   register：0.629 → 0.787，1.25×）。patch 版在 A 相几乎完美（0.063），一切到块读就整块丢掉。
2. **在 N=64 / |T|=8 上，patch 读出并没有「训不起来」**（900 步后 0.1964，甚至略好于 register）。
   ⇒ 所以「z_s 用 patch」**不是**唯一根因，但它是让 A→B 破坏放大 10 倍的因素；
   在真实数据 + 更大 N + 更小预算下，这个破坏就没能恢复（§3）。

## 3. A 相在 224² 上 1000 步还没逃出平凡解（现有唯一直接测量）

同 `224_diag-patch` 的 A 相 `hist`（单步全读，val 100 张）：

| A 相步数 | 500 | **1000** | 1500 | 2000 | 2500 |
|---|---:|---:|---:|---:|---:|
| L1 | 40.64 | **36.08** | 29.48 | 18.08 | 14.07 |
| PSNR | 13.37 | **14.19** | 15.34 | 19.34 | 21.20 |

- 224² 的 **per-patch 均值基线 = 17.35 dB**（原报告 §2/§3.1）⇒ **A 相第 1000 步（14.19 dB）还在平凡解下面**，
  约 **1500→2000 步之间**才逃出。
- 而 `run_sweep.sh` 对所有分辨率都用 **A=1000**（`run_sweep2.sh` 的 A 也只从 600 涨到 1000），
  且标准臂的 A 相 cosine 只跨 1000 步（LR 在 it=1000 已衰减到 ~0，比 diag 的 3000 步 cosine 更死）。
  ⇒ 标准 224/336 臂是**从一个没逃出平凡解的模型**开始跑 B 相的，最终 34–39 的 L1 正是这个水平。
- ⚠️ 边界：11 个标准臂都没存 `hist`（`--eval_every` 默认 0），它们 A 相结束时的 L1 **没有落盘**，
  所以「标准臂 A 相也没逃出」是**由上面的数字推断**，不是直接测量。**这正是应该补的第一个实验**。

对照：28² / 56² 的 B 相曲线在 1500 步内就降到 12.2 / 16.1 ⇒ 小 N 上 A 相（或 B 相自己）在预算内逃出了。
**逃逸所需步数随 N 增长**，而 A 预算没随 N 增长。

## 4. 与 |T| 绑定的两个结构性问题（因为 |T|=⌊√N⌋，它们被误读成分辨率效应）

**(a) 末步窗口恒退化为 1 个 token（结构 artifact）。** 所有扫描尺寸的 N 都是完全平方数，
`square_block_starts(N)` 含 `t=N`，其块 `[N, N+2√N]` 被 `min(·,K)` 截成 `[N,N]` ⇒ 1 个 token。
`F_hat` 恰好取这个退化的末步。28² 的「第 2 步改善恰好 0.0%」就是这个 artifact，**不是数据点**；
「|T| 步」系统性高估有效轨迹。（仓库 `doc/2026-09-16/ANALYSIS_v2_bptt_cpu_verify.md` §2.4 已记录。）

**(b) 裸加 carry 无归一化，其幅度随 |T| 线性增长。** `model_v2.py:596` 是 `Y := query_base + Y_stack_out`
（无 norm / 无残差缩放）。本机实测（D=128、depth 2、随机初始化，取每 token 的 ‖Y‖ 均值）：

| N | \|T\| | 第 1 步 ‖Y‖ | 末步 ‖Y‖ | 增长倍数 |
|---:|---:|---:|---:|---:|
| 16 | 4 | 5.63 | 27.42 | 5× |
| 64 | 8 | 6.28 | 77.21 | 12× |
| 256 | 16 | 5.03 | 149.09 | 30× |
| 576 | 24 | 5.83 | 248.89 | **43×** |

即：**递推越长，查询/激活尺度越大**（再叠加 grad clip=1.0 对 BPTT 梯度的重标定）。
主线同样有这个问题，但主线是 **fp32 + 8760 步 + 从零训**，扫描是 **A/B 两相 + 2500–7000 步**。
不管根因归属如何，**「分辨率扫描」里 |T| 从 4 变到 24，这个混淆必须隔离掉再谈分辨率。**

## 5. 为什么 448×252 能达标（同一 N / 同一 |T|）

按重要性：
1. **没有 A/B 两相**：从零直接训 24 步递归（`train_v2.py` 单条 cosine，40 epoch = **8760 步**，
   全局 bs 32 = 约 28 万样本），不存在「A 相没跑完 + A→B 破坏」这两件事。
2. **register 读出是全局的**：step1 的 3 个 z_s 已经是全局摘要 ⇒ step1 L1 19.10（vs 扫描 39.61），
   `mean_t` 平权损失没有「不可能的早步」把它拉向均值。
3. 编码器是 DINOv2-large（1024/24L）；扫描是 small（384/12L）。
4. 数据是 7009 张 construction_site（letterbox 448×252），扫描是 800 张 DIV2K（直接 resize）。
5. 精度 fp32（历史 448 臂）。附带说明：同配方换 fp16+8bit 后跨度从 −2.67 px 塌到 −0.07 px
   （见 `REPORT_res896_448_fp16_8bit.md`）⇒ 精度/优化器也不是免费的。

反过来说，主线在 224×126 / N=144 / |T|=12 上同样成立（`rd_224_d4_bptt.json`：12.67→12.00 单调降）
⇒ **「多步递归本身训不起来」不成立**，成立的是「扫描这套两相配方 + 小模型 + 小预算在 |T| 大时训不起来」。

## 6. 原报告里需要更正的两处

**(1) §3.1 的招牌对比是预算/warm start 混淆的。**
「224px 单步全读 21.59 dB vs 同分辨率 16 步循环 14.26 dB ⇒ 编码器/解码器/像素头有能力，是 16 步循环训不起来」
——单步臂（`224_diag-patch`，A=3000）是**专门用 3000 步单步训练**、在 ~2000 步才逃出平凡解的模型；
16 步臂（`224_long-patch`，A=1000 + B=5000）的前 1000 步停在**未逃出**的 A 相里，且 A→B 又被打坏一次。
两边不是同一个起点，不能据此判「循环不行」。**正确说法**：*在「A 相逃逸预算不足 + A/B 两相切换」这套配方下，
B 相在 |T| 大时恢复不过来。*

**(2) bpp 用了「名义 token 数」`t+1`，而解码器在第 k 步实际累计读过 `(k+1)²` 个 token。**
`evaluate()`（`sweep_res_train.py:141-142`）里 `tokens=[t+1]`；主表 / RD 图 / 对 JPEG 的 Δ 都用它。
按实际累计读入，最好步 bpp 被低估最多 37%（56²：1.224 名义 vs **1.959 实际**；112²：1.531 vs 1.959）。
⇒ 112/224/336 的「vs JPEG」应分别再差约 −1.5 / −0.8 / −0.5 dB（方向不利于我们，但不改变「崩」的结论）。
（原报告的**逐 step 明细表**里已经印了 1.959 这个实际值，只是主表/图没用它。）

另外：主表把 28² 的技巧性 0.0% 与 +3.61 dB 并列，容易读成「低分辨率更好」；它其实是 |T|=2 且第 2 步退化的结构 artifact。

## 7. 建议的下一步（按性价比，全部是「隔离变量」）

| | 做法 | 目的 / 判据 |
|---|---|---|
| ✅ 1 | **224² 补一臂：A=3000（确认 A 相结束时 L1 ≈14）再 B=5000**；同时补一臂 **无 A 相、从零训 24/16 步递归** | 直接判定「B 相能否恢复」。若曲线开始下降 ⇒ 原报告 §3.1 结论被推翻，根因是 phasing/A 预算 |
| ✅ 2 | **跨分辨率冻结 |T|**：所有尺寸都用同一个步切片（例如都取 `steps[0:8]`）或固定 `decoder_steps`，并相应改 K | 把「分辨率」与「递归长度」解耦，才能谈分辨率 |
| ✅ 3 | **carry 归一化 / 残差缩放**（`Y := query_base + λ·Y`，或对 Y 做 LayerNorm），并记录 `gn` | 去掉 §4(b) 的 |T| 依赖不稳定 |
| ✅ 4 | 报告里同时给 **实际累计 bpp**、**窗口宽度**、**per-patch 均值基线**、**常量图基线** | 让「是否崩到平凡解」一眼可见 |
| ⚠️ 5 | 若要在真实主线上做，回到 **register + DINOv2-large + 长预算 + 无 A/B 两相** | 扫描的 patch 简化只适合机制探针（原报告 §5 也这么说） |

## 8. 本轮独立复现实验（CPU，可重跑）

```bash
cd doc/2026-09-23

# ~25 分钟（8 线程 CPU）；日志 data/toy_zmode_ab_log.txt
```

- 脚本：`doc/2026-09-23/toy_zmode_ab.py`（改自 `doc/2026-09-16/cpu_probe_bptt_toy.py`，新增 `z_mode∈{register,patch}`）

  - register：A=0.6291 → B step1 0.4495 / 最好 **0.2386**（改善 46.9%）
  - patch：A=0.0633 → B step1 0.6213 / 最好 **0.1964**（改善 68.4%）
  - A→B 瞬时破坏：register 0.629→0.787；**patch 0.063→0.873（13.8×）**

> 边界：CPU toy 只到 N=64 / |T|=8、合成低维数据、D=32、2 层编解码器；它证明的是
