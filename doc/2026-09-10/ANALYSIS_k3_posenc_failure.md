## 0. 结论速览（TL;DR）

1. **[数据]** `3151bab` 是一次**参数 tying**（(1,36,D) → (1,6,D)），不是"删除冗余权重"：它在解码器 memory 读出路径上引入了一个**精确的块内置换不变子群 S_{|block|−1}**。本机实测：块内非种子 register 内容置换后，after 版输出变化 `7.15e-7`（fp 噪声），before 版 `2.18e-2`（`/tmp` 实测，D=64/K=35，3 seed 一致）。
2. **[数据]** 该改动删掉的是一条**可用的块内位置寻址通道**：块内位置项对 cross-attention logits 的贡献 std 从 `4.9e-3–3.2e-2`（before, D=64）降到**恰为 0**；位置通道可区分键数 36 → 6。这解释了为什么前向"几乎无损"（匹配初始化下 ‖ΔY‖/‖Y‖ ≈ 2.3%）。
3. **[数据]** 在**块内完全塌缩态**下，after 版非种子成员的梯度差**恰为 `0.00e+00`**，且 200 步 Adam(lr=1e-3) 后仍**恰为 `0.00e+00`**（精确不变子空间）；before 版从同一状态逃逸到 `1.53e-1`。**注意限定**：该精确不变性是把 `z_s` 当自由变量的**解码器读出子系统**的实测结果；端到端并不存在精确不变集——编码器侧 `SpecialTokenBank.pos` 逐位置（`model_v2.py:113`）使各 register 的编码器雅可比不同（见 §2.5(2)）。**但**该不变量集**不是吸引的**：偏离 `ε=1e-3` 时 after 版仍会缓慢分离（400 步 ×3.1），只是比 before 版慢约一个量级。
4. **[推断]** 因此**不能**说"块级共享把 register 推向塌缩"：本机从随机初始化训 600 步，两版块内 register 间距都**不下降**（9.538 → 9.804 / 9.789，两版几乎重合）。块级共享的作用是**取消了塌缩发生后唯一的免学自愈通道**，而不是**制造**塌缩压力。触发塌缩的驱动来自解码器之外（编码器侧 `SpecialTokenBank.pos` 仍逐位置，`model_v2.py:113`）或一次外部事件。
5. **[数据] A/B 归因裁决**：代码层面唯一变量成立（`git diff --stat 3151bab^..42fa6d0` 代码仅 `model_v2.py` 40+/4−）；运行层面**不成立**（`max_steps` 8760 vs 1600 ⇒ warmup 262 vs 48、lr≥0.9 峰值暴露步数 1741 vs 318 ≈ 5.5×）。但**关键分歧点**（两臂都在 step 320 / epoch 1.46 出现梯度尖峰，此后只有 A 无法恢复）落在一个 lr 仅差 8%（1.4998e-4 vs 1.3900e-4）的窗口内，**预算差异不足以解释分歧**。故：块级共享位置编码是"塌缩发生且不可恢复"的**必要条件级候选**，**不是**已确立的充分机制。

## 2. 机制分析（cross-attention q·k 的数学分解）

### 2.1 分解

记 `A_p = c_p + u_p`（`c_p` = 内容 = `[z_cls; z_s]` 第 p 列；`u_p` = 位置向量；after 版 `u_p = pos_embed[0, isqrt(p)]`）。第 ℓ 层 cross-attention、head h、查询行 j（step `t_j`，块号 `k_j = isqrt(t_j)`）：

```
q_{j,h} = W^Q_h · LN(x_j^{ℓ−1}) + b^Q_h
k_{p,h} = W^K_h · A_p + b^K_h = (W^K_h c_p + b^K_h) + W^K_h u_p
s_{j,p,h} = q_{j,h}·k_{p,h} / √d_h
          = [ q_{j,h}·(W^K_h c_p + b^K_h) ] / √d_h   +   [ q_{j,h}·(W^K_h u_p) ] / √d_h
             └────────── 内容项 ──────────┘             └────────── 位置项 ──────────┘
α_{j,p,h} = softmax_p( s_{j,p,h} + mask_{j,p} )
o_j = Σ_h Σ_p α_{j,p,h} · W^V_h A_p     （A 同时充当 cross-attn 的 K 和 V）
```

四条关键性质：

* **(P1) 位置项逐层相同**：`k_{p,h}` 只依赖 `A_p`，而 `nn.TransformerDecoder` 在所有层复用同一 `memory = A`（且 `norm_first=True` 下 memory **不**过 LayerNorm，`_mha_block(self.norm2(x), memory, memory, …)`）⇒ 位置项在每层都是 `q_{j,h}·(W^K_h u_p)/√d_h`。
* **(P2) after 版位置项是块号函数**：`u_p = v_{k(p)}` ⇒ 位置项在块内**恒为常数**。对 `i≥1`，该步只允许自己块内的键，块内全体 logits 加同一常数**不改变 softmax 分布** ⇒ **块内注意力权重完全由内容决定**。
* **(P3) value 侧同样被削弱**：`Σ_{p∈块k} α_p u_p = v_k · (块 k 的注意力质量)`——只依赖**块级**注意力质量，与块内权重如何分配**无关**。因此块内注意力重分配在输出里**不可见**（logits 侧与 value 侧同时失效）。
* **(P4) 位置项并未整体消失**：`i=0` 时 z_cls（块 0）与块 1 同场，位置项改变二者的**相对**权重；`i≥1` 时"读到第几块(=第几步)"这一**块级**信号完整保留（查询 `A_t = c_t + v_{k(t)}` 自带块向量）。丢失的只是**块内偏移** `j = p − k²`。

### 2.2 由此得到的精确代数结论（本报告新增）

**命题**：after 版解码器输出对"块内非种子成员的内容置换"**精确不变**。

**证明**：设块 k 内位置集 `P_k = {k², …, min((k+1)²−1, K)}`，种子 `σ_k = k²`。固定种子内容，对非种子成员作任意置换 `π ∈ S_{|P_k|−1}`。after 版下 `A_p = c_p + v_k`（`p ∈ P_k`），故置换后键集合 `{A_p}` 作为**多重集**不变，仅标签改变；softmax 对键集合是**等变**的（`α` 与 `A` 同步置换）⇒ `o_j = Σ_p α_{j,p} A_p` 逐位不变。查询侧不受影响（`A_{σ_k}` 未变）。
before 版下 `A_p = c_p + u_p` 且 `u_p` 逐位置不同，置换内容**不**构成键集合的置换（`{c_{π(p)} + u_p} ≠ {c_p + u_p}`）⇒ 输出改变。 ∎

**数值验证（本机，D=64, K=35, N=16, 3 seed）**：
```
非种子成员置换 max|ΔY|:  after = 7.153e-7 / 9.537e-7 / 7.153e-7   ← fp 噪声
                        before = 2.179e-2 / 1.900e-2 / 1.885e-2
含种子成员置换 max|ΔY|:  after ≈ before ≈ 6.5e+0                ← 查询取自块内 t=k²，换掉种子即改变 query
```

**块内位置项贡献（本机，D=64）**：
```
[after ] 块内 max|Δk_pos|: 0.00e+00 ×5 块；块内位置项 logit std: 0.00e+00（块3/5 为 2.5e-10 / 2.0e-09 浮点残差）
[before] 块内 max|Δk_pos|: 4.95e-2 – 6.57e-2；块内位置项 logit std: 4.9e-3 – 3.2e-2
去重位置行数:  after 6/36   before 36/36
```
这与另一路报告在 D=1024 上测得的 `7.5e-3–1.05e-2`（位置项 logit std，占块内完整 logit 差异的 1.5–2.4%）量级一致 [数据]。

### 2.3 塌缩态下的梯度（本机新增，本节最关键的实测）

构造**精确块内塌缩**初始态（块内非种子内容全部等于该块种子），对 `z_s` 求 `∂L/∂z_s`（D=128, K=15, N=64, steps=[1,4,9]）：

```
[after ] 各块非种子成员梯度差: blk1 = 0.00e+00, blk2 = 0.00e+00, blk3 = 0.00e+00     ← 精确为 0
[before] 各块非种子成员梯度差: blk1 = 4.75e-05, blk2 = 2.13e-05, blk3 = 1.98e-05   ← 非零恢复力
```

### 2.4 但不变集**不吸引**（本报告新增，修正了另一路报告的过强表述）

从塌缩态加微扰 `ε` 再跑 400 步 Adam：
```
[after ] ε=1e-3: dev 3.995e-3 → 1.242e-2  (×3.11)     [before] ε=0 : dev 1.331e-3 → 1.715e-1 (×129)
[after ] ε=1e-2: dev 3.995e-2 → 1.257e-1  (×3.15)     [before] ε=1e-3: dev 4.563e-3 → 1.701e-1 (×37.3)
```

⇒ after 版的"对称破缺速率"被压低约 **12–40×**，但在 `ε>0` 时**并非冻结**。只有**恰好**落在塌缩流形上才是精确不动点（而这是零测集）。

更进一步：**从随机初始化出发，两版都不把块内 register 拉近**——
```
初始化块内间距 9.5379 → 600 步 Adam 后:  after 9.8042 / before 9.7886（loss 1.2895→0.8633 / 1.2887→0.8629）
```
⇒ **解码器对 `z_s` 的优化本身不产生"register 趋同"压力**。因此"块级共享 → 键表示趋同 → 分工压力消失 → 塌缩"这条链的**第 2 步在本机测不到**。

### 2.5 机制裁决

**三路报告的说法与裁决**：

- 既有报告（`REPORT_v2_block_slice05_posenc.md:4`）说：块内共享位置向量 → **键表示趋同** → 注意力无法按位置区分 → 分工压力消失 → 退化吸引子。
- 代码审计路说：这是删除了"免学通道 + 精确对称破缺"，机理是 tying 导致块内**相对更新恒为 0**。
- 方法论路说："块内键表示趋同"是措辞错误（`z_s` 内容仍逐位置不同），且模型整体**不具备**块内置换对称性（编码器侧仍是逐位置）。

**本报告判定**：

1. **"键表示趋同"必须从因果链中删除**。三条独立理由：(a) `pos_embed` 是**加性**偏移，块内键 `z_s[j] + v_k` 因内容不同而彼此不同 [数据: §2.2]；(b) **健康模型也有高度块内相似**——09-02 实测旧 K=576 健康模型（像素 L1 **17.46**）块内两两 cos = **0.915**、跨块 0.905 [数据: `doc/2026-09-02/REPORT_v2_single_step_retrain.md:56`]；(c) slice05 的**健康逐位置基线**本身 `z_s` within-std 已只有 **0.053**（slice27_v2 为 0.143，P 为 0.171–0.178）[数据: `doc/2026-09-07/REPORT_v2_E1_probe.md:43,47`]。⇒ 高块内相似度在健康模型里普遍存在，**既不必要也不充分**。
2. **"模型整体不具备块内置换对称性"正确**：编码器侧 `SpecialTokenBank.pos` 逐位置且未被本次改动触碰（`model_v2.py:113`）⇒ 置换 register 的**输入嵌入**会改变其内容。被删除的是**解码器读出路径**上的块内可辨识性，不是全局对称性。
3. **"解码器 memory 读出对块内位置精确不可辨"正确且已独立复现**（§2.2、§2.3）。
4. **机制仍未直接观测**。「块级共享位置编码通过取消块内自愈通道，使塌缩一旦发生即不可逆」是**与全部本机数据相容的最简假设**，其微观中间步骤（编码器侧 register 是否真的在 A 臂塌缩、注意力熵是否塌缩、`‖Δθ‖` 是否真的仍在移动）**本机无任何 A 臂权重/激活可测**，故只能写作假设。

### 3.4 尖峰共现与 clip 语义（本报告新增，削弱两路报告的"破坏性步长"解释）

- 两臂**都在同一个 step 320 / epoch 1.46 出现梯度尖峰**（A 12.4560，B 2.1825）；B 还在 step 240 有一次 5.6847 并恢复 [数据]。同一 seed、同一步/epoch 数（219 步/epoch 两臂日志一致）⇒ 这是**与该数据/协议绑定的内生事件**，与位置编码无关。
- `grad_clip = 1.0`（两臂 args 相同），且 transformers `Trainer` 记录的 `grad_norm` 是 **clip 前**的总范数（`_grad_norm = nn.utils.clip_grad_norm_(...)` 的返回值被写入 `logs["grad_norm"]`；本机 transformers 4.57.6 源码核对，与既有报告记录的服务端版本一致）[数据]。⇒ 两臂的 12.46 与 2.18 **都被 clip 到范数 1.0**，**实际步长范数相同（≈ lr×1.0）**。差异只在**方向**，不在幅度。
- **(P-审计)「已纠正-4」**：既有报告"grad_norm 崩到 0.001–0.006 且不再恢复 ⇒ 梯度湮灭自锁"表述过强。正确表述：(a) 平台梯度**中位数 4e-3**，但仍偶发 0.07–0.498 的尖峰（84 点中 5 点 >0.05，最大 0.4981 @ epoch 9.41）且**尖峰后 loss 无趋势改善**；(b) AdamW 下 `grad_norm≈4e-3` **不蕴含参数停止移动**（逐坐标步长 ≈ lr·m̂/√v̂，lr = 1.35e-4 ≫ ε = 1e-8）。另一路报告写的"参数照旧以 ~1.35e-4/步 移动"是**上界**（仅在梯度符号逐坐标一致时取到），不是实测。**本机没有 A 臂的 ‖Δθ‖ 测量**，故"参数是否仍在移动"属未测。可支撑的准确说法是：**可用的、有信息量的梯度信号消失了**。

**（b）A 的终点落在哪个区间**

**（c）train/eval 零间隙（有信息，但需限定）**

A 末段（epoch≥9.0, n=10）train loss 均值 ≈1.1459，eval 1.1394 ⇒ train − eval ≈ **+0.006**，且 341.9M 全参可训练、训练 2160 步后 **eval 低于 train**。若输出含任何依赖输入的分量，训练集上应出现可见拟合优势 [推断，较强]。

**（d）`loss ≡ recon`（本报告修正其解释力）**

A 的 `eval_loss 1.1394238471984863` 与 `eval_recon 1.1394248008728027` 差 **9.5e-7** [数据]。loss 是 5 步 L1 的平权均值，recon 只是最后一步 ⇒ 五步 loss 在 fp32 精度内相同。
**「已纠正-7」**：既有报告把这一条当作"输出在采样轴上是常数 ⇒ 退化不动点"的直接证据。但 09-02 文档已实测：**健康** block 模型（17.46 px）本身的渐进曲线也是"全平"的——每步像素增量 `|W·Y_t| = [1.054, 0.015, 0.015, 0.015, 0.015]`，逐累加 L1 `[0.299, 0.301, 0.306, 0.311, 0.317]`（微升 +0.018），机制是"后几步把输出学进 PixelHead 近零空间"（`R^1024→R^588` 的核方向）[数据: `doc/2026-09-02/REPORT_v2_single_step_retrain.md:52-58`]。
⇒ **"渐进曲线全平"是本架构的通用行为，不是塌缩标志**。仍然成立的是 A 的**紧密程度异常**：健康模型的 loss 与 recon 差约 6%（0.3054 vs 0.317），A 差 9.5e-7（约 4 个数量级更紧）。故正确表述是：**A 的逐像素增量在 fp32 精度内完全为零**（异常），而"曲线平"本身（正常行为）不构成证据。

**（e）可执行的零训练判据（本报告新增，附现成阈值）**

09-02 文档已给出"输出是否退化为常数色"的现成判别量：**`F_hat` 像素输出 std** = 多步 **0.84** / 单25 0.49 / 单64 **0.083** / 单81 **0.073**（后者即 `≈常数色`）[数据: `doc/2026-09-02/REPORT_v2_single_step_retrain.md:56`]。

### 4.2 裁决：「唯一变量」之争

- 代码审计路说：代码层唯一变量成立，运行层不成立（自相矛盾于既有报告 `:13` 与 `:36`）。
- 方法论路说：A/B **不是**单变量对照，因此"直接原因"未确立。
- 训练动力学路说：`max_steps`/`eval_every`/`smoke`/`output_dir` 四项差异**均不能**独立造成塌缩，因为 A 在 1600 步时（epoch 7.31）loss ≈1.15、远超 B 同 step 的 0.5177 ⇒ 塌缩发生在 1600 步**之前**。

**本报告判定：训练动力学路的论证更强，但需要补一条它没写的关键量化。**
理由：(i) 分歧点在 step 320–340，该处 lr 仅差 8%（1.4998e-4 vs 1.3900e-4），warmup 差异（262 vs 48）在该点已**双双结束**，故 warmup 相位不构成分歧点的混淆 [数据]。(ii) 但它**确实**使 B 的后期健康部分来自退火，因此"A 的 1.1394 与 B 的 0.4985 可直接比较"是**不成立**的；可比较的只有 step ≤400 的区间。(iii) n=1/臂 ⇒ 只能得到"该 seed 上共现"，得不到"塌缩率"。

⇒ **结论**：块级共享位置编码是"该次运行中塌缩发生且不可恢复"的**唯一剩余代码变量**，归因强度为**中—强（必要条件级）**；不足以称为"已定位的直接原因"（无重复、无同调度对照、无 A 臂权重证据）。

### 4.3 为什么"塌缩发生在事件之后"这一点最关键

两臂**都**在 step 320 出现尖峰（A 12.456 / B 2.1825，均被 clip 到范数 1.0），差别只在尖峰**之后**：
- B：step 340 → 0.9005、step 400 → 0.6834，继续下行 7 个 epoch 到 0.4985；
- A：step 340 → 1.2054、step 400 → 1.1521，梯度在尖峰后约 180 步衰减到 0.0057（step 380 → 0.1408、step 400 → 0.0632、step 500 → 0.0057）后再不恢复。

这把 A/B 差异的精确定位从"是否发生事件"缩小到"**事件后能否复原**"——而这恰好是 §2.3 所测的"块内自愈通道有无"唯一的定性差别。**这是目前支持"块级共享为致因"的最强单条证据** [数据+推断]。

## 6. 为什么提交时的论证是错的（推理表达 vs 训练动力学的缺口）

`3151bab` 的 docstring 论证链（`git show 3151bab -- model_v2.py` 中的新增注释）：

> 「解码器对每个采样步**整块**读取自己的 z_s 块（memory_mask 列级不区分块内位置，查询 A_t 也只取块内一个位置），块内逐位置编码对解码器**没有可利用的语义**（同一个 step 下的位置编码失去意义），只需保留"哪个块/采样步"的位置信号——参数从 (1,K+1,D) 降到 (1,⌊√K⌋+1,D)。」

三处缺口，逐条给证据：

**缺口 1：把"掩码不区分"当成"模型不区分"（前提不成立）**
`memory_mask` 管的是**允许哪些列**，而 `pos` 是**加在 `A` 上**的（`3151bab:model_v2.py:382-383`），`A` 同时是 cross-attention 的 **K 和 V**。列级掩码不区分，不代表 logits 里没有位置信号——中间隔着一个 `+pos`。本机实测 before 版块内位置项 logit std `4.9e-3–3.2e-2`（占块内完整 logit 差异的约 1.5–2.4%）[数据]。

**缺口 2：把"删掉块内偏移"说成"删掉同一步的位置编码"（推理跳跃）**
`p ↦ (isqrt(p), p − isqrt(p)²)` 是双射 ⇒ 逐位置参数的能力 = 「块号 k」+「块内偏移 j」两部分。after 版**保留了 k、删除了 j**。而 k 恰恰就是"哪个采样步"的信号，且它在 after 版**本就由查询 `A_t` 自带**（`A_t` 含 `v_{k(t)}`，§1.2 实测每步查询块号与步一一对应）⇒ 位置参数里属于"步信号"的那部分是**冗余的**，但"块内偏移"部分不是。提交删掉的是后者，却按前者的理由论证。

**缺口 3：用"推理表达能力"的论证授权一个"训练动力学"改动（论证类型错）**
前向层面改动确实是小扰动：匹配初始化下 ‖ΔY‖/‖Y‖ = **2.3%**（3 seed）；编码器侧 `SpecialTokenBank.pos` 未动，内容方向损失灵敏度 ΔL ≈ **+0.116**（两版几乎相同）⇒ **"模型原则上不可能实现该功能"是错的**，用内容模拟位置标签仍然可行。
但梯度/动力学层面**不是**小扰动：本机实测**块内塌缩态下非种子成员梯度差恰为 `0.00e+00`**，200 步 Adam 后仍恰为 0；而 before 版从同一状态逃逸到 `1.53e-1`（§2.3）。前向论证无法覆盖"哪些方向在优化中被浪费"。

**准确的责任定性**：「已纠正-8」把该改动称为"裁掉冗余"**不准确**，另一路报告称其为"承重结构拆除"**方向正确但略强**。最准确的表述是：

> 它没有删除任何"模型原则上学不会"的功能，但它删掉了一条**免学（structurally free）的块内寻址通道**，并同时使解码器读出路径在块内塌缩态下**恰好失去全部恢复梯度**。恢复该能力被降级为"必须由编码器把位置标签写进 `D` 维内容空间、并与内容路由竞争"，而不是免费的。

**附带的方法学错误**：既有报告 `REPORT_v2_block_slice05_posenc.md:13` 写"同预算、唯一变量"，而同文 `:36,:47` 的配置表自己列出 A 预算 8760（截停）/ B 预算 1600，两处自相矛盾 [数据]。这是本次归因最实质的缺陷。

## 7. 修复方案候选

先做的一步（**零训练**，约 1 小时，无需 GPU 训练）：

### P-1 服务器端零训练诊断（**所有后续结论的前提**）
- **对象**：A 臂 `checkpoint-2000`（`/root/work/output/phase1_v2_block_slice05_posenc/`）与 B 臂 `final_model.pt`。
- **测什么**：① `F_hat` 像素输出 std（现成阈值：常数色 ≈**0.073–0.083**，健康多步 **0.84**，见 `doc/2026-09-02/REPORT_v2_single_step_retrain.md:56`）；② 5 步渐进曲线极差；③ `z_s` within-std 与**按块分组**的块内两两 cos（复用 `doc/2026-09-07/probe_e1.py`）；④ 各步 cross-attention 权重熵与读出秩；⑤ `∂L/∂z_s` 在 A 权重上的**块内非种子成员梯度差**（预期 ≈0，即 §2.3 的现场证据）。
- **为什么必须最先做**：A 的"近常数输出"在项目内**从未被实测**（唯一 eval 数字是标量 loss）；"1.1394 与 1.1382 相等"只说明**终点相同**，不说明输出形态相同。
- **判据**：`F_hat` std ≲0.1 且块内梯度差 ≈0 ⇒ §2.3 机制获现场支持；若 `F_hat` std ≈0.8 ⇒ 既有机制叙述需整体重写。

### P0（前置，非修复）：对齐调度后复跑 A/B
| 项 | 内容 |
|---|---|
| 机制理由 | 现 A/B 混淆了"位置编码"与"峰值 lr 暴露时长"（5.5×） |
| 参数量 | 不变 |
| 最小协议 | `--max_steps 600 --eval_every 200 --warmup_ratio 0.03`，seed ∈ {42,43,44}，其余与 A/B 完全一致；2 卡 bs16；A 实测 3.29–3.32 s/步 ⇒ 约 33 min/臂，6 臂 ≈ 3.3 h |
| 判据 | **塌缩** = 连续 ≥3 个日志点 `grad_norm<0.05` 且 loss ∈ [1.10,1.20]；**健康** = step 400–600 grad 中位数 >0.1 且 eval@600 <0.75（B 锚 0.6834@400、0.539@800；A 锚 1.1521@400、1.1394@2000）。**报"塌缩率 k/3"而非"塌/未塌"** |
| 风险 | 若同调度下 A 码不再塌，则既有结论作废（这正是要知道的） |

### P1 块级共享 + **块内偏移**差分（`u_p = B[k] + D[j]`, `j = p − k²`）
| 项 | 内容 |
|---|---|
| 机制理由 | 块内单射 ⇒ 精确恢复 §2.2 的置换不变性破除；是"可辨识性↑、容量↑"的控制格 |
| **参数量（本报告已裁决的冲突点）** | **17 行 = 17,408 参数**（B: 6 行；D: 0..10 共 11 行），仍比原 36 行省 **52.8%** [数据: 计算]。**注**：另一路报告称"块级共享 + 块内差分必然回到 K+1 参数、不存在保参数收益"——该结论只对 `pe[block] + δ[pos]`（**逐位置** δ，6+36=42 行 > 36）这一种参数化成立；对**块内偏移跨块共享**的 `D[j]` 参数化（17 行）**不成立**，已纠正。两路报告的算术各自正确，混淆在"差分索引是位置 p 还是块内偏移 j" |
| 风险 | 17 行 < 36 行 ⇒ 函数类是严格子集，**仍需实测**是否足以维持训练稳定；不能预设"必然健康" |
| 协议 | P0 协议，与 A 码/B 码三方同跑；判据同 P0 |

### P2 块级共享 + 块内**固定（不可学习）**位置码
| 项 | 内容 |
|---|---|
| 机制理由 | 可辨识性只要求位置码**非恒等**，不要求可学习：`pos = pe[block] + U[:, rank]`（`U` 固定正交基）或正弦码 |
| 参数量 | 可学习 6,144（**−83.3%**），额外可学习 **0** [数据: 计算] |
| 收益 | 若成立即**同时满足提交的工程动机与训练动力学需求** |
| 风险 | 固定码与 `z_s`（不过 LN 直接进 cross-attn memory，`‖z_s‖≈32`）的尺度不匹配；正弦码的秩结构可能与块边界不对齐 |
| 协议 | P0 协议，固定码强度 α ∈ {0.02·std(z_s), 0.1·std(z_s)} 两臂单变量，520 步；附加判据：训练 100 步内 `pos` 项对 attention logits 的贡献量级须与 A 同量级（否则不是单变量） |

### P3 逐位置但低秩分解（`pos_p = pe[block] + U·c_p`, `U∈R^{D×r}`）
| r | 参数量 | 省幅 |
|---|---|---|
| 4 | 6,144 + 4,096 + 144 = **10,384** | −71.8% |
| 8 | 6,144 + 8,192 + 288 = **14,624** | −60.3% |
| 16 | 6,144 + 16,384 + 576 = **22,928** | −37.8% |

**预先登记的判据**：若 r=4 健康 ⇒ 位置码只需极少自由度，"参数量冗余论"被支持；若 r=4 塌而 r=16 健康 ⇒ 存在容量阈值，压缩方向可行但压过头了。
**风险**：r=4 < 块内 11 个位置，部分位置对可能退化为近同码；`U` 与 `c` 的双线性有尺度简并（需 qk-norm 或固定 `U` 尺度）。

### P4 把块内身份从 key 侧移到 **attention logits 的标量偏置**（ALiBi 式）
| 项 | 内容 |
|---|---|
| 机制理由 | 只需打破置换对称，不需方向信息：`s_{j,p} += b(block(p), rank(p))` |
| 参数量 | 6,144 + 36 标量 ≈ **6,180（−83.2%）** [数据: 计算] |
| 价值 | 这是判定"位置向量作为**方向信息**是否必需"的**手术刀**：救回来 ⇒ 既有报告的"逐位置编码不可裁剪"被显著削弱；救不回来 ⇒ 需要方向性位置码 |
| 风险 | 标量偏置与 `-inf` 掩码相加时须避免污染；只按 rank 会让不同块的同 rank 键混淆（需 `b(block, rank)` 二维） |
| 协议 | **必须拆两臂**：(i) 只加 key 侧偏置（query 不动）；(ii) 只把 `pe` 从 key 移到 query。各 600 步 |

### P5 对 register 加显式反塌缩正则
| 项 | 内容 |
|---|---|
| 机制理由 | 若"块级 pos 塌缩"确由 register 同质化介导，直接压制被证的退化量更贴近（块内两两 cos / 协方差非对角 / 每 register 方差下限 / 谱熵下限）。仓库既有文档已提同方向建议（`doc/2026-09-07/REPORT_v2_E1_probe.md:69`、`doc/2026-09-04/LITREVIEW_v2_supplement_decoder_collapse.md:83,178`） |
| 参数量 | **0**（只加 λ） |
| 关键设计 | **加在 A 码上**（不是 B 码）——这才是单变量因果中介检验：若 A 码 + 正则转健康 ⇒ register 同质化是中介；若仍塌 ⇒ 中介假设被否 |
| 风险 | 与重建目标冲突；可能把同质化推到别的自由度（例如编码器学出更小幅度的 z_s）；λ 敏感 |
| 协议 | λ ∈ {0, 0.01, 0.1}，600 步；每 100 步落一次 `z_s` within-std（要求 >0.10；健康参照 slice27_v2 = 0.143） |

### P5' 初始化打破对称（低成本变体，来自仓库既有文献综述）
把 `SpecialTokenBank.token/pos`（`model_v2.py:112-113`）初始化为 DINO patch 特征或 k-means 中心（`LITREVIEW_v2_supplement_decoder_collapse.md:188`）。参数量 0，风险为破坏与预训练 DINO 的尺度匹配，可与 P2–P5 正交叠加；因属随机性假设，**必须多 seed**。

**统一验收判据（全部可在 CPU 秒级测出，见 §2.2/§2.3）**：
`① 块内位置项 logits std > 0`；`② 非种子置换 ΔL ≠ 0`；`③ 塌缩态非种子梯度差 > 0`。

## 8. 仍然未知的问题（按重要性排序）

1. **塌缩是确定性结构后果，还是低概率事件的单次实现？** 现状 n=1/臂，无法给出塌缩率。这决定了"该提交训练级失效"是**必然**还是**若干 % 概率的风险**——工程决策完全不同（回退 vs 加保护性超参）。
2. **A 臂的终端输出形态究竟是什么？** 从未实测。`F_hat` std 探针（P-1）即可解决。
3. **触发因子是位置编码本身，还是峰值 lr 暴露时长？** lr≥0.9peak 步数 1741 vs 318（5.5×）[数据]；若 P0 同调度下 A 码不再塌，(a) 作废。
4. **slice05 是否本就是脆弱配置？** 健康基线 within-std 已 0.053（= slice27 的 1/3）[数据]。需 K=99 复现 + "中性扰动"对照臂。
5. **块级共享是否真的通过 register 同质化起作用？** 本机从随机初始化**测不到**塌缩压力（§2.4）；且健康 K=576 模型块内 cos 已 0.915 [数据]。这条因果链目前**没有正向证据**，只有"取消自愈通道"的负向证据。
6. **`grad_norm→0` 是否等价于"训练停滞"？** AdamW 下不等价 [推断]。本机无 A 臂 `‖Δθ‖` 测量；需记录 `‖Δθ‖`、Adam `v` 范数、梯度方向一致性、cross-attention 熵/秩。
7. **位置身份应由谁承载：解码器 `pos_embed` 还是编码器 `SpecialTokenBank.pos`？** 后者始终逐位置（`model_v2.py:113`）⇒ 模型整体无块内置换对称性。对照臂（把 bank pos 也改块级共享）能分离这两条通道，直接决定"对称破缺"假说的成立与否。
8. **效应是否只在 DCU/fp32/bs32/2 卡下成立？** 两臂恒定的环境差异不构成 A/B 混淆，但限制外部有效性。
9. **K 与块内键数是否存在阈值效应？** K=35（6 块、块内 [3,5,7,9,11]）与 K=99（10 块、块内 [3..19]）未做对比。
10. **`eval_every=2000` 是否掩盖了塌缩的可逆性？** 若在 step 400–600 截停，是否还能靠退火恢复？这直接关系到"是否必须回退该 commit"。
