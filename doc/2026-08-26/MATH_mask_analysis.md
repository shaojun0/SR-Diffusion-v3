## 0. 结论摘要（先行）

**掩码有用，但属"必要不充分"：保留掩码，并用前缀加权训练（w(k) 递减）作为配套补丁。**

1. 掩码定义的是一个**层内注意力支持集**（二元关系/块三角矩阵），它保证"前缀可计算、信息流结构受控"
   ——这是预算/渐进场景的**数学必要条件**，且零参数、已在代码中实现并自检。
2. 掩码**不保证**前缀的信息含量与 decoder 的小前缀能力：k=1..32 的平台期（≈0.0033，全量 2.9×）是
   **训练目标问题**（decoder 训练时恒见全量 k=N，从未见小前缀；编码器无信息前置压力，信息摊匀），
   **不是掩码失效**——可证：k 越小掩码越"宽松"（屏蔽对越少），性能却越差，二者反相关。
3. 一个必须诚实指出的**结构局限**：specials 因果掩码只约束**直接路径**；由于 patches 是全局双向枢纽，
   深度 ≥ 2 时信息会经 patch 枢纽"回渗"，**传递闭包意义上的严格前缀自洽不成立**（详见 §3.2）。
4. `DESIGN_prefix_weighting.md` §3 的 telescoping 恒等式**数学上不成立**（数值反例见 §6.2）；
   但其实践结论（w(k) 递减 ⇒ 前置偏置）在"梯度压力"框架下**成立**（§6.4），机制本身是正确的配套补丁，
   只是理由需要改写。

## 1. 符号与设定

- 序列长度 L；注意力掩码 **M ∈ {0,1}^{L×L}**，约定 **M[i,j]=1 ⇔ i 被禁止看 j（屏蔽）**（torch 2.x bool 约定，True=屏蔽）。
  允许集 **A[i,j] = 1 − M[i,j]**。
- 三个模块的输入布局（位置索引从 0 起）：
  - **ReEncoder**：`[cls(0); specials(1..N); patches(N+1..2N)]`，L = 2N+1；
  - **FeatureDecoder**：`[z_cls(0); z_s(1..k); <patch_token>(k+1..N+k)]`，L = N+k+1（k 为前缀长度，1≤k≤N）；
  - **TextDecoder**：`[z_cls(0); z_s(1..N); 文字(N+1..N+T)]`，L = N+1+T。
- 编码器 E_φ: x ↦ (z_cls(x), z_s(x))，z_s ∈ R^{N×D}；解码器 f_θ: (z_cls, z_s[:k]) ↦ F_hat ∈ R^{N×D}。
- 训练目标（现状）：min_{θ,φ} E_x ‖f_θ(z_cls(x), z_s(x)) − P(x)‖₁，其中 P(x) 为 DINOv2 的 N 个 patch 特征——**恒为 k=N**。
- 测试度量：L1_k = E_x ‖f_θ(z_cls(x), z_s[:k](x)) − P(x)‖₁。

## 2. Q1 掩码的数学本质

### 2.1 掩码作为二元关系 / 矩阵

掩码 M 等价于一个**二元关系** R_M = {(i,j) : M[i,j]=0} ⊆ [L]×[L]（"i 允许看 j"），其邻接矩阵为 A = 1−M。
块状掩码 = 该关系在行/列子块上取"全开放 / 上三角 / 下三角 / 全屏蔽"四种形态之一。

### 2.2 信息流图与偏序

定义**流图** G_M = (V, E)，V = [L]，**E = {(j→i) : A[i,j]=1}**：有向边 j→i 表示"token j 的表示可能流入 token i 的下一层表示"。
对角线恒允许（A[i,i]=1，残差自环）。

- **依赖集**：token i 在层 ℓ 的输出可能依赖的输入 token 集合为
  D_ℓ(i) = { j : G_M 中存在长度 ≤ ℓ 的路径 j→…→i }（传递闭包的 ℓ 截断）。
- **可见偏序**：i ⪯ j ⇔ i ∈ D_∞(j)（"i 的信息能到达 j"）。
- **specials 子图的偏序**：在 specials 块内 A[i,j]=1 ⇔ j ≤ i，故边 j→i 存在 ⇔ j ≤ i；
  specials 上的可达关系是**全序（链）**：D_1(special i) ⊇ {cls} ∪ {1..i}——这正是"special i 只见 specials≤i"。
- **patches 是通用枢纽**：patch 行全开放 ⇒ 每个 patch ∈ D(patch') 且 {specials}∪{cls} ⊆ D(patch)；
  special 行看全部 patches ⇒ patches ⊆ D(special i)。故 patches 与一切 token 双向相连（2-环），
  **流图整体不是 DAG**（有环），因果性只存在于 specials 块内部的上三角屏蔽中。

### 2.3 三处掩码的矩阵结构与信息流语义

**① ReEncoder**（L=2N+1；`build_prefix_mask(L, 1, N+1)`）：

```
        cls   specials(1..N)   patches
cls       0       0             0
specials  0     [严格上三角=1]   0        ← special i 屏蔽 specials j>i；见全部 patches
patches   0       0             0        ← 全开放（全局双向）
```

- 语义：cls 全局；specials 前缀链（special i 的**直接**注意力支持 = {cls, specials≤i, patches}）；
  patches 全局（图像无时序，全双向）。
- 屏蔽对总数：|M|=N(N−1)/2，与 N² 同阶，全部集中在 specials×specials 上三角块。

**② FeatureDecoder**（L=N+k+1；`build_prefix_mask(L, 0, k+1)`，k 可变）：

```
        z_cls+z_s(0..k)   patch(1..N)
z(0..k)  [严格上三角=1]     0        ← z 行: 因果链 + 可见全部 patch 行
patch   0                  0        ← patch 行: 全局（见所有人、被所有人见）
```

- 语义：z 区域因果链（z 行 i 只见 z≤i + 全部 patch 行）；patch 区域全局。
  k 前缀 = 主子矩阵（principal submatrix）：z_end=k+1 时，缺失的 z 行/列直接不存在，掩码是
  全量掩码在保留索引 {0..k}∪{k+1..N+k} 上的子矩阵——**k<N 与 k=N 语义自洽（向后兼容）**。
- 屏蔽对总数：k(k+1)/2，随 k **单调递增**（k=1 → 1 对；k=576 → 166176 对）。

**③ TextDecoder**（L=N+1+T；`tail_causal=True, z_see_tail=False`）：

```
        z(0..N)           文字(N+1..N+T)
z      [严格上三角=1]     1（全屏蔽）   ← z 行: 因果链 + 不看文字（防未来文字经 z 泄漏给前面的文字）
文字    0                 [严格上三角=1]  ← 文字行: 见全部 z + 文字≤i（标准下三角）
```

- 语义：z 因果且不看文字；文字行标准自回归下三角。k<N 时经 kept 索引（{0..k}∪{N+1..N+T}）子采样，
  文字绝对位置恒为 N+1..N+T，**不随 k 漂移**。

## 3. Q2 前缀自洽性

### 3.1 直接路径定理（精确成立）

**定理（直接支持集前缀因果性）**：对 ReEncoder（causal_specials=True），在每一层 ℓ，
special i 的注意力输出只依赖层 ℓ−1 的 {cls, specials ≤ i, patches}（其直接允许集），与 specials j>i 的输入无关。

*证明*：由 §2.3 的掩码结构，special 行 i 的允许列 = {0}∪{1..i}∪{N+1..2N}；注意力输出是这些列的
value 的凸组合，故单层输出 f({value_j : j 允许})。归纳即得逐层结论。∎

**推论（单层前缀不变性）**：单层情形下，z_s[:k] 的计算不依赖 specials k+1..N 的输入——掩码保证了
"前 k 个 special 是一个闭子系统"（直接路径上）。

**FeatureDecoder 侧（精确成立）**：k<N 前缀输入时，掩码是全量掩码的主子矩阵（§2.3 ②），
前向对任意 k 良定义，输出恒为全量 N 个 patch；k=N 与全量语义逐位一致（向后兼容）。
z 前缀链的作用：patch 输出是 {z_cls, z_s[:k], patch_token} 的可微函数 g_k(·)，随 k 增大可用信息单调增多；
实测 L1_k 近似单调下降（0.00339→…→0.00114）与此一致。

### 3.2 多层传递闭包的诚实局限（重要）

**命题（回渗）**：深度 ≥ 2 时，流图的传递闭包是**完全图**：对任意 special i<j，
存在路径 j → patch → i（patch 行见 special j，special 行 i 见 patch），长度 2。

*推论*：z_s[i]（层 ≥2 的输出）**可以**依赖 special j>i 的层 1 输出——而后者携带图像信息
（每个 special 都直接看全部 patches）。因此：

- **严格前缀自洽（"z_s[:k] 与后段 specials 完全无关"）在传递闭包意义下不成立**；
- 掩码保证的只是**每层的直接支持集**（§3.1），它是"一阶因果"，不是"传递因果"；
- 模型代码注释亦写明"前缀稳定性：直接路径上"——设计者已知此边界。

**对实验与场景的影响**：
- k-sweep（只截断 decoder 输入）**不受影响**：编码器恒算全量，z_s[:k] 就是训练时的值；
- "只算前 k 个 special 的预算推理"（截断编码器）则**不保证** z_s[:k](截断) = z_s[:k](全量)，
  二者差图像相关量。若要严格传递前缀稳定，需要：depth=1，或同时屏蔽 patch→special 关注
  （使 patches 成为纯图像编码器、specials 只做读出——但这会削弱"编码器重组信息到 specials"的能力）。

### 3.3 前缀自洽性的数学必要性

"预算/渐进"场景要求：∀k，前缀 z_s[:k] 是**自足条件**（well-defined 的 decoder 输入）。
若无 specials 因果块（specials 全双向），z_s[i] 会在每一层直接看 z_s[j>i]——前缀 z_s[:k] 就
不是闭子系统，即便只算前 k 个 special 也会引用不存在的依赖（或依赖后段处理）。因此
**specials 因果掩码是前缀自洽性的必要条件**（直接路径上）；充分性还需训练目标配合（§5）。

## 4. Q3 表达力分析

### 4.1 假设类包含关系

记 H_full = 全双向注意力的 transformer 函数类，H_mask = 固定掩码 M 的同类。**H_mask ⊆ H_full**
（掩码可被全双向网络近似模拟：把被屏蔽对的 logit 学成充分负即可，或加一个按位置的 gating head）。
反之 **H_full ⊄ H_mask**（固定深度）：全双向下 special i 可直接读 special j>i 的**槽位特定处理结果**，
掩码下只能经 patch 枢纽间接读。

### 4.2 掩码不改变计算图连通性的情形（本结构成立）

**命题**：在 patches 全局双向 + specials 见全部 patches 的结构下，掩码版与全双向版的**可达图相同
（都是完全图，深度 ≥2）**。即掩码只改变**逐层允许的注意力二分结构**，不改变**跨层信息可达性**。

*证明*：任一 token 到任一 token：i → patch → j（第 1 类边 i→patch：special 行见 patch / patch 行见 patch；
第 2 类边 patch→j：patch 行全局 / special 行见 patch）——与掩码是否屏蔽 specials 上三角无关。∎

含义：掩码的约束是"软的"——它不切断任何信息通道，只把"special j>i 的直接读"改成"经 patch 枢纽的
间接读（多一跳、且与其它 special 的处理结果在 hub 上混合）"。代价是**深度常数**（间接读需 ≥2 层）
与**通道混合**（hub 共享），而非信息可达性。

### 4.3 通用逼近性

已知结论：带（因果）掩码的 transformer 仍是序列函数的通用逼近器（Yun et al., *ICML 2020*，
"causal transformer" 可逼近 sequence-to-sequence 映射；掩码不破坏逐 token 的上下文映射能力）。
本结构中：每个 special 都能直接看全部 patches（图像的全部信息），故 z_s[i] 的逐层函数类不受
"信息可达"限制；decoder 的 patch 输出行全局，可任意聚合 z。整条管线（DINO → ReEncoder →
FeatureDecoder）是通用逼近器的复合，在深度/宽度充分时能表示目标映射 x ↦ P(x)（含恒等型重建）。
**"前缀 k 的输出序列覆盖全双向"的论证**：k=N 时 decoder patch 行全局 ⇒ 输出位置与全双向等势；
编码器 z_s 全体覆盖全部图像信息；故**输出类**（patch 重建函数）在极限下与全双向等价——差别只在
specials 的中间表示（内部对象，不进入输出）。

### 4.4 诚实的局限

1. 固定深度下，需要"special i 直接读取 special j>i 槽位"的目标函数，掩码版需经 hub 多一跳，
   且 hub 是共享通道（576 个 patch token，容量大但不免费）；
2. 掩码强加了一个**结构偏置**（specials 链式读出）——若最优解需要 specials 全双向协同，
   掩码会限制其表达；实测未出现该迹象（全量重建 0.00114 良好），但这是偏置的固有风险；
3. 通用逼近需要充分深度/宽度；4 层 ReEncoder + 4 层 Decoder 的具体容量余量未量化（超本报告范围）。

## 5. Q4 "有用"的严格界定

### 5.1 必要不充分的形式化

- 掩码约束的是**支持集**（允许对集合 S_k = {(i,j): M_k[i,j]=0}），是**结构量**：参数无关、逐模块固定。
- 训练目标约束的是**内容**（z_s 的分布、f_θ 在 S_k 上的取值）：当前目标只在 k=N 处采样，
  故
  ∇_θ L = E_x [ ∂L1_N/∂f_θ · ∂f_θ/∂θ ]，
  梯度从未经过 k<N 的输入子流形 —— **f_θ 在 {z_s[:k]} (k<N) 上的取值完全不受约束**，
  可以（也确实）退化。掩码只保证这些取值"存在且良定义"，不保证"好"。

**结论：掩码是必要的（保证前缀可计算/信息流结构），但不是充分的（不保证前缀信息含量与用法）。**

### 5.2 实验论证：平台期是训练目标问题，而非掩码失效

| 证据 | 数值 | 解读 |
|---|---|---|
| k=1 已优于 k=0 | 0.00339 < 0.00407 | 机制本身在工作：一个 z_s 就能提供信息，decoder 能消费它 |
| k=1..32 平台 | ≈0.0033 恒定 | decoder 对小前缀的输出几乎与 k 无关（退化为"k 不敏感函数"）|
| k=576 悬崖 | 0.0025 → 0.00114（2.2× 跳变）| 全量是训练时唯一见过的点，质量独一档 |
| 窗口探针（500 图，32-token 窗口）| z_s[0:32]≈0.00329, z_s[64:96]≈0.00328, …, z_s[384:416]≈0.00326；末段 z_s[448:480]≈0.0035、z_s[512:544]≈0.0034 | 编码器把信息**均匀摊在 576 个位置**，前段无更多信息量 |
| 掩码宽松度 vs 性能 | 屏蔽对 k(k+1)/2 随 k 递增，性能随 k 变好 | 平台区性能与掩码限制**反相关**——掩码不是瓶颈 |

论证要点：
1. **掩码宽松度反证**：k=1 时掩码只屏蔽 1 对（z 区域无"后面"可屏蔽），几乎全开放，decoder 有
   完全自由度使用 z_cls+z_s[0]+576 个 patch token——若掩码是瓶颈，k=1 不该最差。平台期只能来自
   "这个输入分布没被训练过"。
2. **信息摊匀的证据**：任意 32-token 窗口（含前段）还原能力相同 ⇒ 编码器无信息前置。根因是
   训练目标对 576 个位置完全对称：∂L/∂z_s[i] 只来自全量 L1_N，各位置压力相同 ⇒ 无动机把信息
   集中到前段。掩码只管 specials 间因果（支持集），管不了"信息放哪个位置"（内容）。
3. **decoder 从未见小前缀**：train_v2.py 训练循环恒 `model(x)["loss"]`（全量 k=N），
   FeatureDecoder 对 k<N 的 f_θ|_k 从未被梯度触碰（§5.1）。

### 5.3 一句话数学式

> 掩码约束的是 **attention 支持集** S_k（结构），而非**表示的内容分布** p(z_s|x) 与 decoder 函数 f_θ|_k
> （内容）。前者是必要条件（前缀良定义），后者由目标函数决定（当前只在 k=N 处约束，故 k<N 退化）。

## 6. Q5 加权机制的数学（含对草稿 §3 的修正）

记 L1_j = L1(前缀 j 重建)（j=0..N，L1_0 = 仅 z_cls），Δ_i = L1_{i−1} − L1_i ≥ 0（第 i 个 token 的边际改善），
w_j 为前缀 j 的损失权重（递减：w_0 ≥ w_1 ≥ … ≥ w_N ≥ 0）。

### 6.1 正确的 telescoping 恒等式（数值验证 ✓）

由 L1_j = L1_N + Σ_{i=j+1}^{N} Δ_i 得

**(I)**　Σ_{j=0}^{N} w_j L1_j = (Σ_j w_j)·L1_N + Σ_{i=1}^{N} (Σ_{j<i} w_j)·Δ_i

即"前缀损失加权和"≡"全量项 + 各 token 边际贡献 Δ_i 以**累计权重 Σ_{j<i} w_j** 加权"。

### 6.2 草稿恒等式的反例（数值验证：不成立）

`DESIGN_prefix_weighting.md` §3 声称 Σ_j w_j L1_j ≡ Σ_j (w_j−w_{j+1})·Σ_{i≤j}Δ_i (+边界项)。
其 RHS 逐项 telescoping（于 j）得 **Σ_i (w_i − w_N)·Δ_i**，与 (I) 相差 Σ_i (Σ_{j<i} w_j − w_i + w_N)·Δ_i ≠ 0。
数值实验（N=576，w_j=1/(j+1)，真实 L1 曲线）：LHS=2.2648e-2，草稿 RHS=3.7357e-4，差 2.227e-2 ≫ 0。
**草稿恒等式不成立。**

由此还推翻草稿的一个解读："w 递减 ⇒ 边际系数 (w_j−w_{j+1})≥0 ⇒ 越早的 token 边际贡献权重越大"——
在**正确**的 (I) 中，Δ_i 的系数 Σ_{j<i} w_j 随 i **递增**（i=1→1.00, i=288→6.25, i=576→6.93），
即加权前缀损失给**后段** token 的边际改善权重更大。真正的"前置"机制是梯度压力（§6.4）。

### 6.3 分部求和恒等式（数值验证 ✓）

**(II)**　Σ_{i=1}^{N} w_i Δ_i = w_1 L1_0 − w_N L1_N + Σ_{j=1}^{N−1} (w_{j+1} − w_j) L1_j

即"按边际贡献加权"（系数 w_i 递减 ⇒ 早段权重更大，正是草稿想要的语义）等价于一个**带负系数的**
前缀损失组合——它不是普通加权损失，而是"奖励小前缀做得好"的差分形式。若真要按边际权重优化，
应直接构造目标 Σ_i w_i Δ_i（或其代理），而非 Σ_j w_j L1_j。

### 6.4 梯度压力：真正的前置机制（数值验证 ✓）

token i 的表示 z_s[i] 出现在所有前缀 j ≥ i 的重建中，其梯度为

∂/∂z_s[i] Σ_j w_j L1_j = Σ_{j ≥ i} w_j · ∂L1_j/∂z_s[i]，

压力幅度 ∝ **Σ_{j≥i} w_j**。对递减 w，Σ_{j≥i} w_j 随 i **递减**（w=1/(j+1)：i=1→5.94, i=288→0.69, i=576→0.0017）
⇒ **越早的 token 收到越大的总梯度压力 ⇒ 信息前置** ✓（与草稿的实践结论一致，但理由不同）。
均匀采样 k∈[1..N] 时 w_j ≡ 1，压力 ∝ Σ_{j≥i} 1 = **N−i+1**（i=1→576, i=N→1，精确线性递减）——
草稿 §3 的"天然加成"论断**精确成立**（这是机制的基石）。

**小结**：机制正确（decoder 端：小 k 高权重 ⇒ 学会用前缀；编码器端：梯度压力 ∝ Σ_{j≥i} w_j 递减 ⇒
前置）。需修正的只是 §3 的恒等式与"边际系数"表述——应改为 (I)(II) + 梯度压力论证。

### 6.5 数值验证输出（`verify_weighting_math.py`，N=576）

```
恒等式 (I)  Σ_j w_j L1_j == (Σw)L1_N + Σ_i(Σ_{j<i}w_j)Δ_i      差 6.9e-18  ✓
恒等式 (II) Σ_i w_i Δ_i == w_1 L1_0 − w_N L1_N + Σ(w_{j+1}−w_j)L1_j  差 1.1e-19  ✓
草稿 §3     Σ_j w_j L1_j ≡ Σ_j(w_j−w_{j+1})Σ_{i≤j}Δ_i        差 2.2e-2   ✗ 不恒等
           （草稿 RHS 精确等于 Σ_i(w_i−w_N)Δ_i，已交叉验证）
方向        (I) 中 Δ_i 系数递增 1.00→6.93；(II) 中 w_i 系数递减 0.50→0.0017
梯度压力    均匀采样 ∝ N−i+1：576→288→1；加权 w=1/(j+1)：5.94→0.69→0.0017
```

## 7. Q6 结论

**(a) 结论**：**掩码有用，且应保留——但它是"必要不充分"**。它解决的是"前缀可计算 / 信息流结构受控 /
三模块语义自洽 / 文字防泄漏"这一组结构性问题；它不解决（也无法解决）"前缀有信息含量 / decoder 会用前缀"，
后者是训练目标的事。实验平台期正是训练目标缺失的证据，而非掩码失效。

**(b) 性质归属**：
- **掩码带来的**：任意 k<N 的前向良定义与主子矩阵自洽（FeatureDecoder/TextDecoder 均已支持 k<N 前缀）；
  直接路径前缀因果（§3.1）；TextDecoder 防未来文字经 z 泄漏（z_see_tail=False）；文字绝对位置不随 k 漂移；
  逐层注意力结构受控（§2.3）。
- **需要训练目标配合的**：信息前置（编码器端，靠梯度压力 Σ_{j≥i} w_j 或均匀采样 N−i+1）；
  decoder 小前缀胜任度（decoder 端，靠训练时见各种 k）；有序"粗→细"分布（二者共同）。
- **掩码的结构代价**：specials 无法直接读后段槽位（需经 hub 间接读，深度+1、通道混合）；
  传递闭包意义下严格前缀自洽不成立（§3.2）——若未来要做"只算前 k 的预算推理"，这是已知风险点。

**(c) 建议**：**保留掩码设计**。它零参数、成本可忽略、是前缀语义的必要条件，且 k<N 支持已实现并自检
（`model_v2.py` __main__ 第 3b/7 项）。若最终不需要预算/渐进能力，掩码也不构成负担（全量 k=N 时
掩码是自然的主子矩阵，语义不变）。

**(d) 加权机制是否为配套补丁**：**是，且是正确方向的补丁**——它与掩码正交（掩码修支持集，加权修内容/
训练分布），正好激活 §5.2 指出的两个缺失通道（decoder 小 k 暴露 + 编码器前置压力）。
但**必须修正草稿 §3 的数学表述**：(i) 恒等式用 (I)/(II)；(ii) "前置"的论证改为梯度压力 Σ_{j≥i} w_j
（均匀采样即 N−i+1，草稿此点正确）；(iii) 若要"边际贡献加权"语义，目标应取 Σ_i w_i Δ_i 而非 Σ_j w_j L1_j；
(iv) 保留草稿 §4 的工程护栏（p_full 全量保底、w 地板、k_min 下限）防全量精度退化。
