## 1. `DBCMLAB__Constructionsafety_QApairs`

1. **任务类型**: **纯文本单轮指令问答（instruction/QA，text-generation）**，非视觉任务。
   依据: parquet schema 仅 `id/instruction/input/output`，**没有任何 image 字段**；README `task_categories: [text-generation]`、`language: [ko]`，说明为 "virtual QA pair dataset generated by GPT-3.5-turbo"，基于 KOSHA（韩国职业安全健康署）施工安全指南。
2. **数据格式**: parquet（`data/train-00000-of-00001.parquet`，6 个 row group，约 1.4 MB）。
3. **样本数**: **5114**（单分片，精确值）。
4. **单图/多图**: **无图**（无 image 列；README 中 `input` 字段全为空字符串，纯文本）。
5. **单轮/多轮**: **单轮 (1)**。
   - 字段为 `instruction` + `output`（`input` 全空），一个指令对应一个回答。
   - 轮数分布: `{1: 5114}` = **100%**（top-1 = 1 轮，占比 100%）。
   - 无语义多轮证据：`output` 中含 "질문" 的仅 2 行、含 "답변" 的仅 1 行（占 0.06%，属噪声）。5025 个不同 instruction。
6. **关键字段**: `id` (int64)、`instruction` (string)、`input` (string，全部为空)、`output` (string)。
   真实样例（截断）:
   > `id=1` | `instruction=정착장이란 무엇을 의미하나요?` | `input=""` | `output=정착장은 지반의 붕괴예상선 안쪽에 형성되어 주입재와 마찰저항을 발생시키는 부위입니다.`
7. **数据质量备注**: 第 2365 行（索引 2364，`id=2365`）`instruction` 与 `output` 均为 `NULL`。

## 2. `chandrabhuma__multi_building_defect_vqa`

1. **任务类型**: **VQA（视觉问答）**，但形式上是**分类式 VQA**——针对建筑缺陷图片提问，答案是固定类别的缺陷名称（6 类）。
   依据: 字段 `image` + `question` + `answer`；实测 `question` 只有 1 种（`"What type of building defect is visible in the image?"`），`answer` 只有 6 种取值 ⇒ 等价于 6 类图像分类。
2. **数据格式**: parquet，**图片字节内嵌**（`struct<bytes: binary, path: string>`，实测 `path` 为 `None`，需用 `bytes` 解码）。
3. **样本数**: **2411** = train 1928（643 + 643 + 642）+ test 483。
4. **单图/多图**: **单图（每样本 1 张）**。图片列为 `struct<bytes,path>`，每行一个 struct（非 list），`path=None`，`bytes` 为内嵌图片；抽样 magic `89504e47` = PNG。抽样字节大小 23,816 ~ 1,563,396 bytes。
5. **单轮/多轮**: **单轮 (1)**。
   - 字段为 `question`/`answer` 一对。轮数分布 `{1: 2411}` = **100%**（top-1 = 1 轮）。
6. **关键字段**: `image` (struct<bytes,path>)、`question` (string)、`answer` (string)。
   `answer` 分布: `cracks` 789 / `no defect` 452 / `spalling` 427 / `efflorescence` 311 / `general defects` 264 / `scaling` 168。
   真实样例（截断）:
   > `image: {path: None, bytes: <58041 B, PNG>}` | `question="What type of building defect is visible in the image?"` | `answer="cracks"`

## 3. `juungwon__LLava-ConstructionSafety_v6`

1. **任务类型**: **多轮视觉指令对话（image-conditioned multi-turn dialogue / 施工安全隐患描述）**。
   依据: LLaVA 风格字段 `messages: list<struct<content: list<struct<index,text,type>>, role>>` + `images: list<image>`；问答内容为韩语，围绕施工现场图片的作业类型、隐患与安全措施。README 未给 `task_categories`。
2. **数据格式**: parquet（`data/train-00000-of-00001.parquet`，1 个 row group，约 48 MB），**图片字节内嵌**。
3. **样本数**: **30**（单分片 train）。
4. **单图/多图**: **每样本 1 张图**（`images` list 长度实测全部为 1，hist `{1: 30}`）。
   - **重要**: 30 行只对应 **9 张不同图片**（8 张各重复 3 次 + 1 张重复 6 次）⇒ 同一图片被拆成多行。
   - 图片为 `list<struct<bytes,path>>`；`struct<bytes,path>`，`path` 为原始 jpg 文件名（非 URL）。magic `ffd8ffe0` = JPEG，例如 `H-220715_B19_N-11_018_0003.jpg`，2,012,777 bytes。
   - user 消息的 `content` 数组实测含 1 个 `type='text'` + 1 个 `type='image'`（image 项 `text=None`）。
5. **单轮/多轮**: **结构上每行单轮 (1)，但语义上是"扁平化的多轮链"**。
   - 每行 `messages` 长度恒为 2（1 user + 1 assistant），hist `{2: 30}`；user 轮数 hist `{1: 30}` = 100% ⇒ **按样本判定 = 单轮 (1)**。
   - 但同一图片的连续多行构成一条对话：**29 个相邻行对中有 20 行（69%）的 user 文本内嵌了上一行 assistant 的回答**（即上一轮回答被拼接进下一轮 user 输入）。以图片分组后，每张图对应 **3 轮**（1 张图为 6 轮）对话。
   - 结论: 官方按"行"发布是单轮样本；若按图片重组，则为 **3~6 轮多轮对话**。
6. **关键字段**: `messages`（list<struct<content, role>>；`content` = list<struct<index,text,type>>，`role` ∈ {user, assistant}）、`images`（list<image>）。
   真实样例（row 0，截断）:
   > user: `이 이미지는 어떤 작업과 관련된 이미지인가요? 또한, 이미지의 상황에 대한 설명과 어떤 위험이 있는지 말씀해주세요.` + `[image]`
   > assistant: `이 이미지는 '비계 공사'와 관련된 이미지 입니다. '시스템비계 위 낙하 위험물 배치' 이며 '낙하'위험이 있는 '비정상'적인 상황입니다.`
   样例（row 1，链式证据，截断）:
   > user: `이 이미지는 어떤 작업과 관련된 이미지인가요? ...말씀해주세요.\n\n이 이미지는 '비계 공사'와 관련된 이미지 입니다. '시스템비계 위 낙하 위...`

## 4. `ZhiyaYang__sewer-defect-crack-dataset`

1. **任务类型**: **图像分类（3 类）**，非对话/非 VQA。
   依据: schema 仅 `image` + `label`；README `label` 为 `class_label`，`names: {0: blockage, 1: corrosion, 2: crack}`。README 无 task_categories/无问答字段。
2. **数据格式**: parquet，**图片字节内嵌**（`struct<bytes, path>`）。
3. **样本数**: **585** = train 409 + validation 88 + test 88。
4. **单图/多图**: **单图（每样本 1 张）**。`image` 为单个 struct（非 list），`path` 为文件名（如 `00684402.png`），`bytes` 内嵌图片，magic `89504e47` = PNG，抽样 187,651~224,312 bytes。
5. **单轮/多轮**: **N/A**（无 `conversations`/`question`/`answer`/`messages` 等对话字段，纯分类标签）。
6. **关键字段**: `image` (struct<bytes,path>)、`label` (int64，class_label)。
   `label` 分布（全量 585）: `0=blockage` 178 / `1=corrosion` 237 / `2=crack` 170。
   真实样例（截断）:
   > `image: {path: '00684402.png', bytes: <187651 B, PNG>}` | `label=1` (corrosion)

## 关键观察（供下游使用）

- 四个数据集**全部为 parquet**；3 个含图的数据集图片均为 **parquet 内嵌 `struct<bytes,path>` 字节**（不是 URL、不是独立图片文件夹、不是 tar）。读取时需 `image['bytes']` 解码；`path` 在 chandrabhuma 中为 `None`，在另两个中为原始文件名。
- 只有 `juungwon__LLava-ConstructionSafety_v6` 是对话格式（`messages` + `images`），且仅 30 行，需注意它是**按轮拆行、按图片分组**的链式对话（每图 3 轮，1 张图 6 轮）。
- `chandrabhuma` 名为 "vqa" 但问题固定、答案为 6 个类别 ⇒ 实际可直接当 **图像分类** 使用。
- `DBCMLAB` 是**唯一无图**数据集，`input` 列 100% 为空，是 `instruction → output` 的单轮文本 QA。
- 数据质量问题: DBCMLAB 第 2365 行（`id=2365`）`instruction`/`output` 为 NULL。
